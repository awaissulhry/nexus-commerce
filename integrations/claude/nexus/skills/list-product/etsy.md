# Etsy: listing reference

Read with the list-product skill. The business's Etsy shop and market come from `business-overview` (`markets[]` with channel `ETSY`; `accounts.ETSY[].id`). Quoted sentences are what Nexus answers; `<…>` stands for a value Nexus fills in.

## 1. Etsy basics

- **One listing per family.** The family's main row holds the Etsy Listing ID; each variation is one SKU inside that listing's variations (Etsy calls them its inventory). A single product is a listing with one SKU.
- **Market:** always `GLOBAL`. publish-review, create-draft-listings and set-listing-fields call it `market`; publish-listing calls it `marketplace`. Matrix key: `ETSY:GLOBAL`. `publish-review` and `publish-listing` name the shop by its shop name (`accountLabel`); other tools may show the account's own label.
- **Prices are never converted.** The Etsy market's currency in Nexus must be the shop's: "This Etsy shop sells in <X> and Nexus holds Etsy prices in <Y>. A price is never converted: set the Etsy market's currency to <X>."
- **Languages.** Nexus's first language for Etsy is the listing's own text; every other language of the Etsy market goes as an Etsy translation, and only when the shop offers it ("<xx>: this Etsy shop does not offer that language, so its translation is not sent."). A translation needs a title and a description ("<xx> translation: Etsy needs a title and a description, so it is not sent.").
- **New listings are Etsy drafts.** A first publish creates the listing on Etsy as a draft: "Publish creates this listing on Etsy as a draft: buyers cannot see it. Etsy charges its listing fee when a listing goes live, not for a draft." In the sheet a draft reads Inactive: "A draft on Etsy: buyers cannot see it. Nexus cannot set an Etsy draft live yet; going live comes in a later Nexus update." Going live needs photos, which Nexus does not send yet (section 3).
- **The switch.** Nothing reaches Etsy while Etsy publishing is off on the Nexus server: section 6.

## 2. Before a publish

`publish-review` names what is missing; fix it first (each fix is a change a person approves).

- **Category, who made it, when made.** "Category is empty. Choose an Etsy category on the main row." · "Etsy takes Who made it, When made and Craft supply together: fill in <fields>." Set them with `set-listing-fields` (`attr_<key>`; an unknown key is refused with the list of the listing's attributes). Nexus publishes physical listings only ("Listing type "<x>": Nexus publishes physical Etsy listings only.").
- **Shipping and processing profiles.** "Shipping profile is not set. Etsy needs one before the listing can go live." · "Processing profile is not set. Etsy needs one for every variation: choose it on the main row (or on each row)."
- **Text and attributes.** `product-content` with `coordinate: { channel: "ETSY", market: "GLOBAL" }`; `set-listing-content` for this listing's own title, description, tags (`pin.keywords`) and attributes such as `material` (section 4).
- **Status of a new listing: Inactive (a draft).** Active is refused: "Etsy needs at least 1 photo to go live; photos come in a later Nexus update." A person sets the main row's Status in the product sheet; no Claude tool sets it.
- **Stock of a new variation on a listing that sells.** A variation new on a live Etsy listing is sent with its stock, which needs Etsy order import on for the account: "Etsy order import is off (…), so Etsy's own sales do not reach Nexus stock. A stock number sent now could put back units Etsy has already sold, so nothing was sent to Etsy. Turn on Etsy order import first." A draft cannot sell, so a create (or a variation added to a draft) does not need it. A person turns order import on; no Claude tool can.

## 3. What Publish sends

**A new listing** (fields `"all"`; any other `fields` is refused: "A first publish sends the complete listing: name fields "all".") is ONE create, sent once: the draft with its fields, then its variations with the price and stock Nexus holds, then its attributes and translations, then a read-back. The `publish-listing` preview's `summary` says "creates 1 Etsy draft listing with N variations (not for sale; going live comes with photos later)", and `createsVariations` lists each variation (`sku`, `price` with its `currency`, `quantity`, `startsAs`: "added to the draft (not for sale; it sells once the listing goes live)", or hidden); show them before you ask. Its one `send` line is the whole create request, and the approval is bound to all of it (a price or stock changed afterwards sends nothing and asks again). Before the create, Nexus records on the main row that a create is under way, so a second create of the same listing is never started (section 5). Photos are not sent.

**A listing Etsy already holds** (a draft included):

- **Listing fields** that changed: title, description, tags, materials, category, who made it / when made / craft supply (one change), listing type, shop section, shipping profile, return policy, weight, dimensions, taxable, automatic renewal. A field empty in Nexus is left as Etsy has it: "Empty in Nexus; Etsy keeps its value." Styles and production partners go only when a listing is created ("Etsy takes styles only when a listing is created; Nexus cannot change them on a listing that exists.").
- **Attributes** (one change per Etsy attribute) and **translations** (one change per language, holding its title, description and tags).
- **Variations** as ONE replace of Etsy's whole inventory: "Sending the variations replaces Etsy's whole inventory. On a shop that uses Etsy's domestic pricing, Etsy then clears the domestic price (an Etsy fault Nexus cannot see); check it on Etsy after the publish." Say this to the person before you ask.
- **Price and stock of a variation Etsy does not hold.** When the variations go (fields `"all"`), each variation Etsy does not hold yet — new on Etsy, or dropped by Etsy ("Etsy no longer holds <SKU>; Publish adds it back as a new variation.") — goes with the price and stock Nexus holds for it: for sale or hidden as its Status says — but on a listing that is an Etsy draft it is "added to the draft (not for sale; it sells once the listing goes live)". The preview lists them in `addsVariations` (`sku`, `price` with its `currency`, `quantity`, `startsAs`); show them before you ask. If one of those numbers changes after the approval, the run sends nothing and asks for a new approval.
- **A category change** warns: "Changing the Etsy category can make Etsy drop attributes and variation properties the new category does not have. Check the listing on Etsy after the publish."
- **Not sent:** photos ("Photos are not sent to Etsy yet; they come in a later Nexus update."); the price and stock of variations Etsy already holds (`set-listing-price`, `set-listing-stock`); a SKU change ("Nexus cannot send Etsy SKU changes yet: Etsy keeps <old> for this listing (Nexus holds <new>)."); going live (a draft stays a draft until Nexus sends photos).

## 4. The tools on Etsy

| Tool | On Etsy |
|---|---|
| `publish-review` (`ETSY`, `GLOBAL`) | The studio's review: each change `SEND`, `DIFFERS`, `CANNOT_COMPARE` or `SAME`, and what blocks it. It reads the live listing only while Etsy publishing is on; off, every change says "The review reads the live Etsy listing only when sending to Etsy is on." and nothing can be sent. A listing not on Etsy yet is one create line (`__create__`), an Etsy draft. |
| `publish-listing` (`marketplace: GLOBAL`) | A new listing: the create as an Etsy draft, with fields `"all"` (section 3). A listing Etsy holds: sends the changed fields of the groups named to a listing Etsy holds: `title`, `description`, `keywords` (tags), `attributes` (every other listing field and the Etsy attributes). A translation goes when `title`, `description` or `keywords` is named. The variations go only with `fields: "all"`; named groups leave them out with "Etsy takes its variations as one whole inventory: name fields "all" to send them." `fields: "photos"` is refused ("Photos are not sent to Etsy yet; …"), and so is `["bullets"]` ("Etsy listings have no bullet points."). With `"all"`, a variation Etsy does not hold goes with its price and stock (`addsVariations`, section 3). The usual flow: dry run → `approvalId` → a person approves → it runs as them, and if the review changed since, nothing is sent. |
| `publication-status` | An update: `VERIFIED` ("Etsy took the change to listing <id>, and the read-back matches.") or `UNVERIFIED` ("Etsy took part of this change, or Nexus could not confirm it. Check listing <id> on Etsy, mark this publication checked, then Publish again: Nexus sends only what still differs."). A create: `VERIFIED` ("Etsy created draft listing <id>, and the read-back matches. It is a draft: buyers cannot see it."), or `UNVERIFIED` when Etsy gave no clear answer ("Etsy gave no clear answer to the create, so Nexus does not know whether Etsy made the draft. Nexus will not create a second one: in Publish history, open this publish and choose Mark as checked — Nexus first looks for the draft in this shop's Etsy drafts and links it."). Final at once: Nexus does not check an Etsy result again by itself; for UNVERIFIED the tool's `next` says a person does, and until then a new publish of the listing is refused. |
| `product-content` (`coordinate` `ETSY`, `GLOBAL`) | The Etsy sheet's text and attributes, per row, in one language. |
| `set-listing-content` (`ETSY`, `GLOBAL`) | This listing's own title, description and tags (`pin.keywords`), and its own attributes (`attributes`, e.g. `material`). The shipping profile, policies and other listing settings are refused ("…: a listing setting (offer, photos, shipping, policies), not text or an attribute"): use `set-listing-fields`. Saved in Nexus; Etsy changes on the next publish. |
| `listing-live-content` (`ETSY`, `GLOBAL`) | What Etsy holds now, read live, read-only. "This listing is not on Etsy yet." for a listing with no Etsy Listing ID. |
| `set-listing-fields` | Listing fields (`attr_<key>`); title, description and tags are refused here as text (the content tools change them). |
| `create-draft-listings`, `remove-draft-listings` | Nexus-only rows before the first publish ("Inert drafts in Nexus: paused and unpublished. Nothing is sent to the channel until a publish."), not Etsy drafts. Removal refuses a row that holds values ("…: it has values of its own; removing it would lose them.") or that already carries an Etsy Listing ID ("…: not a draft (it was published or carries the channel's id)."). |
| `set-listing-price` | Saved in Nexus, then pushed to Etsy (one write per listing). Etsy has no sale price on a listing ("No sale price on this coordinate"). Refused pushes: "This product has no Etsy listing id, so there is nothing on Etsy to change. Nothing was sent.", and a currency that is not the listing's ("…A price is never converted, so nothing was sent."). |
| `set-listing-stock` | As price, and held until Etsy order import is on for the account (section 2). A draft Nexus created has its rows' sync paused, so price and stock pushes are held ("Listing sync is paused. Resume sync before sending changes."). |
| `close-listing`, `reopen-listing` | The whole listing: close sets it inactive ("Etsy: the listing is set inactive (never quantity 0)."), reopen sets it active ("Etsy: the listing is set active again — Etsy may set its quantity to 1 and charge a renewal; Nexus then sends the current stock."). Given one variation's listing id, close-listing still closes the whole listing. An Etsy draft: nothing to do ("A draft on Etsy is not visible to buyers, so there is nothing to pause." · "Nexus cannot set an Etsy draft live yet; going live comes in a later Nexus update."). A Nexus-only row: "…: a draft was never live — remove it (remove-draft-listings) instead." |
| Hide or show ONE variation | Only a person, in the product sheet: the variation row's Status Inactive or Active, then Publish ("Hidden on Etsy: buyers cannot buy this variation; the rest of the listing sells."). No Claude tool does it; held while Etsy publishing is off. |
| `end-listing`, `relist-listing`, `delete-listing` | Refused: "Etsy has no End here. close-listing sets the listing inactive." · "Etsy has no End or Relist here. reopen-listing sets an inactive listing active again." · "Deleting Etsy listings from Nexus is not available yet. close-listing sets it inactive, or delete it in Etsy." |
| `link-channel-id`, `unlink-channel-id` | Link checks the Listing ID on Etsy first (a number from the listing's web address; it must belong to this account's shop, and Etsy must not report it as a draft). The undo of an unlink asks to link the same Listing ID again, which is refused while Etsy reports that listing as a draft ("…: Etsy reports listing <id> as a draft: it does not sell yet, so Nexus cannot record it as listed. Publish it on Etsy, then link it. Nothing changed."). |
| `out-of-sync-listings` | Etsy listing content is read every 4 hours on the main row ("Etsy listing content (read every 4 hours)") and a listing whose content differs is reported; the sheet shows "Differs on Etsy" on the main row's Listing ID. Price and quantity are not read back ("not checked: Etsy quantity is not read back into Nexus", the same for price): compare with `listing-live-content`. |

## 5. Refusals and their fix

| Nexus says | Fix |
|---|---|
| "Etsy needs at least 1 photo to go live; photos come in a later Nexus update." | The main row's Status is Active: a person sets it Inactive (a draft) in the product sheet, then publish again. |
| "A create of this Etsy listing started on <time> and Nexus did not see Etsy's answer, so Etsy may already hold it as a draft. Nexus will not create a second one: …" (or "…Etsy answered with listing <id>, but Nexus did not finish recording it. …", or "A create of this Etsy listing is being sent now. Wait for its result before you publish again.") | Never ask for the create again. A person opens that publish in Publish history and chooses Mark as checked: Nexus looks on Etsy and links the draft it finds (it clears the record only when Etsy holds none, and never within 15 minutes of the create). Then review again. |
| "Sending is off: publishing to Etsy is turned off on this server. …" or "Sending is off: publishing to Etsy is in dry-run mode on this server. …" | Section 6: a person decides; tell them. |
| "Etsy takes its variations as one whole inventory: name fields "all" to send them." | Publish again with `fields: "all"`, after telling the person about the whole-inventory replace (section 3). |
| "Etsy changed this listing after the review (its fields, attributes, variations, translations or state). Review again." | `publish-review` again, show the new changes, ask again. |
| "This Etsy listing belongs to another shop, not this account's, so Nexus reads nothing more of it and uses none of it." | The Listing ID is wrong for this account: a person checks the link. |
| "Etsy changes a whole listing. Choose Full update on the main row." | A person's screen choice: Full update only on the main row. `publish-listing` sends partial updates only. |
| "A first Etsy publish makes an Etsy draft, which cannot be closed, and Nexus cannot delete an Etsy listing. To take it back: delete the draft on etsy.com, then clear its Listing ID in Nexus (Clear in the product sheet's Listing ID cell, or unlink-channel-id). If the create's result is UNVERIFIED and Nexus holds no Listing ID yet, first open that publish in Publish history and choose Mark as checked: Nexus looks for the draft on Etsy and links it." | The undo of a first Etsy publish: a person deletes the draft on etsy.com, then the Listing ID is cleared (the sheet's Clear, or `unlink-channel-id`, which a person approves); for an UNVERIFIED create with no Listing ID yet, Mark as checked first. |
| "A previous publication still needs a result (<id>). …" | A person checks the listing on Etsy, then "Mark as checked…" in Publish history. |

## 6. The Etsy publishing switch

Etsy publishing is a setting of the Nexus server, not of the business: a person with access to the server turns it on. Claude never can, and no tool changes it. While it is off:

- `publish-review` compares nothing with Etsy and has one blocking problem ("Sending is off: publishing to Etsy is turned off on this server. Nexus ran every check it can without reading Etsy (it reads the live listing only when sending is live); nothing will be sent until live publishing is turned on." — or, in dry-run mode, "Sending is off: publishing to Etsy is in dry-run mode on this server. …"), so `publish-listing` is refused.
- `close-listing` and `reopen-listing` are refused ("Etsy publishing is turned off. Nothing was changed." or "Etsy publishing is in dry-run mode. Nothing was changed.").
- Price and stock pushes are skipped, and Status changes in the product sheet are held ("Sending to Etsy is not live on this server, so Publish cannot change this. Change it in Etsy.").

The first Etsy publish of a business: create one draft or send one small field group on one listing, read `publication-status`, and only then send more. `fields: ["keywords"]` sends the tags AND every translation that differs (a translation holds its own title, description and tags; one Etsy call each): check that the `publish-listing` preview's `send` lists only what the person agreed to.
