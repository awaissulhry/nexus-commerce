## 2. Changes

1. **New** `lib/outbound-webhook.ts` — the one sender for operator webhooks:
   - URL rule (`webhookUrlProblem`): HTTPS only; no user name or password; no IP literal outside the public internet; no `localhost`, `*.localhost`, `*.local`, `*.internal` (the Railway private network), `*.home.arpa`, `*.lan`, or single-label names (`redis`, `postgres`).
   - Connect-time check (`guardedLookup`): the DNS answer is checked inside the socket's own `lookup`, so the address checked is the address connected to (no DNS rebinding). Every answer must be public.
   - `deliverWebhook`: `node:http(s)` request (never follows a redirect; a 3xx is a failure), `agent: false`, 8 s for the whole exchange, at most 1 KB of the reply read, at most 500 characters kept. Never throws.
   - Non-public ranges (`net.BlockList`): IPv4 `0/8, 10/8, 100.64/10, 127/8, 169.254/16, 172.16/12, 192.0.0/24, 192.0.2/24, 192.88.99/24, 192.168/16, 198.18/15, 198.51.100/24, 203.0.113/24, 224/4, 240/4`; IPv6 `::/96, 64:ff9b::/96, 64:ff9b:1::/48, 100::/64, 2001::/32, 2001:db8::/32, 2002::/16, fc00::/7, fe80::/10, fec0::/10, ff00::/8`. IPv4-mapped IPv6 is checked against the IPv4 rules by `BlockList` itself.
   - Secret at rest: `sealWebhookSecret` (the `lib/crypto.ts` v1 envelope, the same key as the carrier and Sendcloud secrets), `openWebhookSecret` (sealed / legacy plain text / legacy bcrypt), `resealIfLegacy`.
2. `routes/settings-webhooks.routes.ts` — create seals the secret; **no key = 503, nothing saved** (plain text is never written); create and edit use the same URL rule; the test fire opens the secret, sends through `deliverWebhook`, stores a capped error, and re-seals a legacy plain-text row on the same bookkeeping write. An unreadable sealed secret answers 409 and sends nothing.
3. `services/webhook-dispatch.service.ts` — the same sender, the same capped error, the same re-seal; an unreadable sealed secret records "cannot be read" and sends nothing. Bcrypt rows are still skipped.

No schema change (the column keeps its name and now holds a `v1:` envelope). No screen change (the API answers keep their shape).

Behaviour change: `http://localhost` and every private address are refused, also for testing. A row saved before P0.3 with such a URL now fails at send time with the reason.

Differences from the exact-change list: the tests are in two files, not one (the sender's own tests need no mocks; the route tests mock the database).

> **CORRECTION (2026-09-19, found during P0.4).** The first version of this section said the third failed file was a teardown error in `services/pim/studio-publication-transports.vitest.test.ts`. **That was wrong.** The third file was `services/pim/theme-change.vitest.test.ts`, which failed to LOAD (0 tests, listed under "Failed Suites", which the saved tail of the output did not show). **P0.3 caused it:** that test replaces `node:http` with a `vi.mock` factory that reads a top-level variable, so it breaks if anything loads `node:http` before the test body runs — and `lib/outbound-webhook.ts` imported `node:http` at module load, inside the import graph of every alert (`alert.service.ts` → `webhook-dispatch.service.ts`). Proven both ways: the committed P0.3 file (`8c2f10564`) → "Cannot access 'boom' before initialization"; the fixed file → 19/19 pass. **Fix (made in the P0.4 package):** `deliverWebhook` imports `node:http` / `node:https` when it sends, not at module load. Full suite after the fix: 9479 passed, 6 failed (the two Amazon files only), 2 failed files. The teardown error in `studio-publication-transports` was real but separate (it passes alone, 21/21).
