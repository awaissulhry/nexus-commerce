## 1. What was measured first

### 1.1 The API could not express the lifecycle

`GET /api/sync-logs/webhooks` (RT.4) selects `isProcessed`, `processedAt` and `error`,
and filters on `processed=true|false`. None of `status`, `attempts`, `deliveries`,
`nextAttemptAt`, `lastError`, `signatureOk` or `verifiedBy` was exposed — every one of
them added by CX.4a or P2.1 and **never read by an API**.

So a screen built on it could say that something went wrong, but not what, how many
times it had been tried, when it would be tried again, or whether the signature had been
checked at all.

### 1.2 The existing grid rendered three states from a boolean

`ChannelEventsGrid.tsx` showed `yes` / `pending` / `failed`, derived from `isProcessed`
and an error string. A **dead letter** — an event out of attempts, waiting for a
person — came out as `failed`, identical to one that will be retried in four minutes.

Those are the two rows an operator most needs to tell apart, because **one of them needs
them and the other does not.**

### 1.3 There was a replay, but no retry

`POST …/:id/replay` runs the handler inline. Nothing queued an event for the worker.

### 2.1 Design-system rules, followed

- **Composed, not hand-rolled**: `MetricStrip`, `Card`, `Banner`, `Field`, `Listbox`,
  `EmptyState`, `Button`, `FilterChip`, `Skeleton`, and the **shared `InboundGrid`** the
  Diagnostics tab already uses — so the two screens cannot disagree about what a status
  means.
- **No new design-system component was needed**, so nothing was added to the catalog or
  the changelog and there is no entry for `.claude/DS-GAPS.md`. No design-system file
  changed, so there is nothing to mirror into `apps/factory`.
- **Every token verified against source** before committing. `DESIGN.md` warns that a
  wrong name is an invalid declaration and is *silently dropped* — a border becomes 0px
  with no error. All nine (`--nds-space-1..4`, `--nds-border-subtle`,
  `--nds-surface-raised`, `--nds-radius-md`, `--nds-text-muted`, `--nds-font-size-sm`)
  are defined in `tokens.css`.
- **Two component APIs were guessed wrong and corrected by reading the source** —
  `Card` takes `header`, not `title`, and `Listbox` has no `label` (it takes `ariaLabel`,
  or a `Field` wraps it). `tsc` caught both.

### 2.2 The decisions worth keeping

- **`retry` and `replay` are different actions, deliberately.** Retry queues for the
  worker and returns; replay runs the handler inline and answers with what happened. An
  operator clearing a hundred dead letters after fixing a channel wants the first — a
  hundred inline replays would hold a request open for as long as the slowest one and
  time out somewhere in the middle, leaving nobody able to say which had run. An
  operator investigating ONE event wants the second, because the answer is the point.
- **Only a stuck row offers an action.** A `done` event has nothing to retry, and a
  `pending` one is either being handled now or already queued — a button there invites
  an operator to race the worker.
- **A dead letter gets its own tone**, not a darker shade of failed. It is a different
  state, because nothing will try it again.
- **The totals are counted over the whole window and are NOT filtered by the caller's
  status filter.** A tally that moves when you click a filter is describing the page
  rather than the system, which is the opposite of what the number is for.
- **The lifecycle wins over the old boolean** when they disagree, because the lifecycle
  is what the worker acts on. Rows that predate CX.4a still render.

## 4. Still open

1. **The tab has never rendered against real data**, because there is almost none: no
   Shopify webhook has ever been recorded, eBay's subscriptions do not exist yet, and
   Etsy's endpoint is not configured. The ledger holds 5,158 AMAZON rows from before the
   lifecycle existed, which render through the fallback in `inboundStatusOf`.
2. **No React render test.** `apps/web` vitest is node-only here, so the tab's logic is
   covered through `inboundStatusOf` and the rest is covered by `tsc` and the ratchets.
   Stated rather than implied.
3. **Retry is one row at a time.** A "retry every dead letter on this channel" action is
   the obvious next want and is not built; the worker already handles the fan-out, so it
   is a small addition when someone has enough dead letters to need it.
4. **Archived events are not shown.** `archivedAt` is selected but nothing writes it
   yet (the archiver does not exist — P2.1 section 4), so there is nothing to filter.
