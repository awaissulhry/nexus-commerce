# P4.1e — eBay's Inventory / Trading split: keep it, and never GUESS it

**Date** 2026-09-20 · **Package** P4.1 (Publish / content), fifth slice — the last unmeasured row · **Size** S

---

## 1. The measurement — mostly a COUNTERWEIGHT

> *eBay: keep the split (Inventory API for unique SKUs, Trading for shared SKUs)*

The split exists and is **deterministic**, which is better than the row asks.
Incident #23 replaced an `it_item_id` heuristic — which, in the file's own words,
*"misrouted Trading primaries into the Inventory lane"* — with a marker that
cannot be inferred wrongly:

> A family whose ChannelListing carries `__offerIds` was created by OUR
> Inventory-API group publish, so offers exist → **Inventory lane**.
> No `__offerIds` → the listing is Trading-managed → **shared/Trading lane**.

Only a **shared-flagged** family consults the marker; the Inventory lane is the
default. So "keep the split" is already done, and done well.

## 2. The one defect: the marker's FAILURE path guessed

The prefetch that reads the marker was wrapped in a `try` whose `catch` said:

```ts
request.log.warn({ err }, 'ebay/flat-file/push: lane-marker prefetch failed — shared flag decides alone');
```

With `inventoryManagedProducts` left empty, `inventoryManagedFamily` is `false`,
so a shared-flagged family takes the **Trading** lane — **exactly the misrouting
Incident #23 was introduced to stop**, re-entering by the back door whenever the
database hiccups.

The shared lane's *adopt-don't-duplicate* belt catches many such misroutes, but
it reads `{mp}_item_id` / `ebay_item_id` **off the row**, and a family published
through the Inventory lane need not carry one. So the downside is not bounded to
"eBay returns an error": it can reach `AddFixedPriceItem`.

🔴 **This is the same shape as P4.1d, in a different file, found the same day: a
rule learned from an incident, correct on the happy path, quietly abandoned on
the failure path.** Both are now "refuse rather than guess".

---

## 3. What was built

- `laneMarkersUnavailable` records that the marker could not be read.
- A shared-flagged family whose lane therefore cannot be established is
  **refused**, one `ERROR` row per SKU, and the loop moves to the next family.
- The refusal sits **before** either lane, so neither is entered.
- It is **per family**, not per push: every family whose lane does not depend on
  the marker is unaffected.
- The sentence says it is temporary — *"the database was unavailable … Retry in
  a minute."* A hiccup must not read to the operator as a broken listing.

## 4. The proof

**12 tests green** (`routes/ebay-lane-split.p41.vitest.test.ts`).

**4 mutations, 4 named tests failed, every file restored byte for byte.**

```
✅ the catch stops recording the failure (back to guessing)
✅ the refusal is deleted (a shared family takes Trading blind)
✅ the refusal moves AFTER the Trading lane
✅ the refusal drops "Retry in a minute" (reads as a broken listing)
4 guarded, 0 not guarded
```

### 🔴 4.1 Two of those mutations failed FIRST, and the tests were wrong

The first mutation run reported **2 guarded, 2 NOT guarded**:

```
❌ the refusal is deleted (a shared family takes Trading blind)
   ran=true failed=false — THE RULE IS NOT GUARDED
❌ the refusal moves AFTER the Trading lane
   ran=true failed=false — THE RULE IS NOT GUARDED
```

The assertions were `toContain('sharedParent?… && laneMarkersUnavailable')`.
Mutating the guard to `if (false && sharedParent?… )` or appending
`&& Date.now() < 0` **leaves that substring intact**, so the rule was switched
off and the test stayed green.

**A `toContain` on part of a condition is not a test of that condition.** The
assertions now match the **whole trimmed line**, with its `if (` and its `) {`,
and a companion test asserts there is **exactly one** line testing the flag. Both
mutations convict now.

These remain **shape** gates rather than behavioural ones, and that is stated in
the test file: the refusal sits deep inside a large route handler, and driving it
for real would need auth, a connection and fixture rows for a branch that fires
only when the database is down.

### 4.2 A guard silenced by its own comment

The test *"no longer lets the shared flag decide alone"* failed at first, because
the **new** code quotes the old sentence in a comment explaining what it
replaced. The banked lesson is *"a guard that counts comments can be silenced by
one"* — here it was the reverse, and the fix is the same: comments are stripped
before matching, with a positive control that the stripper did not empty the file.

## 5. What is still open

1. **Not proven by real traffic.** The refusal fires only when the lane prefetch
   throws. The done-when is one push reporting this sentence instead of routing
   blind.
2. **The belt's dependence on a row-carried ItemID is unmeasured.** How many
   Inventory-published families carry `{mp}_item_id` on their flat-file rows is a
   question for production data. It decides whether a historic misroute would
   have duplicated a listing or merely failed — and nothing in the ledger would
   distinguish them now.
