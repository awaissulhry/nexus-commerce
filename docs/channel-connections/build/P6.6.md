**10 self-authorizations** is far above the two business profiles in use.

review-and-listing grounds alone.

## 3. Changes

1. **New** `useAmazonEnvToken(caller)` in `lib/amazon-sp-client.ts` — the one door to
   `process.env.AMAZON_REFRESH_TOKEN`. Both paths use it: the SDK client and
   `getAmazonAccessToken`, which is the one that actually exchanges it at LWA.
   - It **announces itself once per process** at WARN, naming the caller and the
     retirement switch. Once per process, not per call: it sits on the money path and a
     per-call line buries itself. The question it answers is yes/no, not how many.
   - `NEXUS_AMAZON_ENV_TOKEN=off` turns it into a **refusal** with a sentence telling
     the operator to import the grant instead.
2. `index.ts` — `seedEnvManagedConnections` will not synthesise an env-managed row once
   the token is retired. An env row created at boot is a credential nothing can revoke,
   rotate or date, which is the opposite of where D1 = A puts it. The existing guard
   (any `oauth` row, of any status, blocks synthesis) is untouched — production relies
   on it so a restart cannot undo a disconnect.

## 4. 🔴 What this deliberately does NOT do

**It does not delete the fallback.** That is one line with the largest blast radius
available: if the stored grant is ever unusable, every Amazon SP-API call stops.

The production database cannot be read from this session, so *"the stored grant works"*
is an **inference** from the application functioning, not a measurement. Retiring a
credential path on an inference is exactly the trade this programme has learned not to
make.

So the env token now **says so in the logs**, which turns *"is anything still on the env
path?"* into a question production answers by itself — and `NEXUS_AMAZON_ENV_TOKEN=off`
is the retirement, one variable, once those logs are quiet.

## 6. Production proof — the log answers it

After the deploy, watch for **one** line:

```
[amazon-sp] STILL USING the environment refresh token (P6.6 retires this)
```

- **If it never appears**, production is entirely on the stored grant, and
  `NEXUS_AMAZON_ENV_TOKEN=off` can be set — that is the retirement, and the row closes.
- **If it appears**, `caller` names which path still needs the env token, and the grant
  must be imported before retiring it.

Either way the answer comes from production rather than from an inference, which is the
whole point of shipping it this way round.
