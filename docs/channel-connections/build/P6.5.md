# P6.5 — The heartbeat no longer trips over accounts shared with a profile

State: **BUILT (2026-09-19), committed locally (not pushed, not deployed).** Run under the Owner's "Start to implement the whole plan" (FINAL-PLAN 14.3); taken early (small, independent).

Plan row (FINAL-PLAN.md section 6, P6): fix the heartbeat for shared (guest) accounts. Section 4.1: "the heartbeat updates rows a guest profile can read but not write, so its run for that profile may stop with an error".

## 1. Evidence (2026-09-19)

- With business profiles ON, the sweep runs once per profile (`jobs/cx-heartbeat.job.ts` → `runProfileTimer`) and read every active connection it could SEE.
- A guest profile SEES the accounts shared with it: the read-only policy `nexus_workspace_grant_read ON "ChannelConnection" FOR SELECT` (`packages/database/prisma/migrations/20260916a_bps1a_channel_account_grant/migration.sql:94-95`). Writes stay owner-only (`nexus_workspace_isolation … FOR ALL … USING ("workspaceId" = current)`, migration `20260908b…:7171-7172`).
- The sweep wrote `lastHeartbeatAt` etc. to every row it saw, with no per-row error handling, so in a guest profile the first shared row failed its write and the rest of that profile's accounts were not heartbeated that tick.

## 2. Change

`jobs/cx-heartbeat.job.ts` — with profiles ON the sweep reads only the accounts the current profile owns (`workspaceId = workspaceIdForQuery()`); the owner's sweep heartbeats a shared account. Each account runs in its own try/catch, so one failure no longer stops the others (counted as failed, logged).

## 3. Proof

- `jobs/cx-heartbeat.vitest.test.ts` (+2; 34 pass): in a guest profile the query carries the owner filter, the own account is heartbeated and the shared one is not; an account whose connector throws is counted failed and the next account is still heartbeated.
- Mutation check: filter removed → 1 fails.
- Full API suite: **9580 passed, 6 failed** (the two known Amazon local-account files). `tsc` 0 errors.

## 4. Production proof — OPEN

After a push, with an account shared into another profile: that profile's `cx-heartbeat` CronRun rows succeed, and the shared account's `lastHeartbeatAt` keeps moving (from its owner's sweep).
