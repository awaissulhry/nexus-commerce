## 1. Why it exists

Our fixture tests replay answers we recorded ourselves. A field a channel renames, or an error vocabulary it changes, stays green in those tests and turns red on the seller's account. This run asks the real channel, on its sandbox, and reads the **shape** of the answer.

## 2. Change

- `services/contract/channel-contracts.ts` — what is checked, one entry per operation: eBay inventory read, eBay `VerifyAddFixedPriceItem` (the channel's own dry run), Amazon marketplace participations, Amazon Ads profiles. Each entry owns its assertion sentence, so a failure says what changed, not "it broke".
- `services/contract/contract-run.service.ts` — the runner, with two rules it enforces itself:
  1. **every call goes out as `kind: 'read'`** (a read or the channel's own dry run), so a contract run can never change a listing anywhere;
  2. **the URL must resolve to a sandbox host** (`sandboxUrlOf`); a channel with no sandbox host is reported as *not configured* with its reason, never as green.
- A gateway refusal (account needs sign-in, rate bucket, publish gate) is a **failed** check: the run says "this could not be proven tonight" rather than passing quietly. ~~Green needs at least one check to have actually run.~~ **Superseded 2026-09-23 (section 6): green needs EVERY required operation of every in-scope channel proven; one passing check was a false green.**
- `jobs/channel-contract.job.ts` — nightly at 03:20 (`NEXUS_CHANNEL_CONTRACT_SCHEDULE`), recorded through `recordCronRun`, so a red run is red in the cron record too. Also runnable from the sync-logs hub as `channel-contract-run`.

**Off until the Owner turns it on:** `NEXUS_ENABLE_CHANNEL_CONTRACT_RUN=true` and one sandbox account per channel — `NEXUS_CONTRACT_ACCOUNT_EBAY`, `…_AMAZON_SP`, `…_AMAZON_ADS`, `…_SHOPIFY`, `…_ETSY` (plus `NEXUS_CONTRACT_AMAZON_SELLER_ID`). With the switch off nothing is scheduled and nothing is sent.

**Cron record.** Red → `FAILED`; partial → `PARTIAL`; not-configured → `NOT_CONFIGURED`; green → `SUCCESS` (`recordCronRun` honours a `cronStatus` on the handler's result; the hub's manual-trigger route passes it through). The manual trigger honours `NEXUS_ENABLE_CHANNEL_CONTRACT_RUN` (off → "Not run", `NOT_CONFIGURED`) and writes ONE row; a run that throws early reports itself, never the previous night.

**What a pass requires.** eBay inventory: the `inventoryItems` list itself, non-empty, `total`, each item's `sku` + `product`. Offers: a named sandbox SKU with an offer (`NEXUS_CONTRACT_EBAY_SANDBOX_SKU`). GetItem: a named item (`NEXUS_CONTRACT_EBAY_SANDBOX_ITEM_ID`), `ListingStatus`, and every declared `<Variation>` readable. Verify: only documented listing-validation codes (`RequestError`); auth, header, system and unknown codes fail. Participations: non-empty, `marketplace.id/countryCode`, `participation.isParticipating/hasSuspendedListings`. Ads: non-empty, `profileId`, `countryCode`, `currencyCode`, `timezone`, `accountInfo.id/type/marketplaceStringId`. listTransactions: Amazon's example read with our own `readTransactionsPage`.

**Safety.** Every check is gateway `kind: 'read'` on a sandbox host or not sent. eBay checks are refused (failed, nothing sent, no token read) unless the named account's connection is `environment: 'sandbox'`. Trading calls send the real client's headers EXCEPT DEV/APP/CERT-NAME (eBay: ignored outside token calls; the production CERT is a secret), plus `answerOk: tradingAnswerOk` so the ledger records an `<Ack>Failure</Ack>` as failed. The Ads call carries `Amazon-Advertising-API-ClientId` from `getChannelApp('AMAZON_ADS', <account environment>)`.

**Re-review nits (2026-09-24).** The overdue-cron alert counts SUCCESS, PARTIAL and NOT_CONFIGURED rows as proof a job ran (FAILED / RUNNING still do not). The sync-logs hub's cron tile warns while any latest row is PARTIAL / NOT_CONFIGURED ("N partial or not configured"), and each row shows its status as a design-system `Pill` in words, with the full summary on hover. `getChannelApp('EBAY', 'sandbox')` no longer falls back to the env keys unless `EBAY_ENVIRONMENT=SANDBOX` says they are the sandbox keyset — before, a sandbox token request could send the PRODUCTION client id and secret to eBay's sandbox.
