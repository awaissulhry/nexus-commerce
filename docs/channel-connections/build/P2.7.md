## 1. What was measured first

### 1.1 The hourly write INCREMENTS, and nothing deduped

`ingestMarketingStream` upserts `AmazonAdsHourlyPerformance` with an `update` that
**adds**. Its own comment says why:

> *"AMS sends corrections as DELTAS, which is why `update` increments rather than
> replaces."*

That is correct for corrections and lethal for redeliveries. SQS is **at-least-once**;
`pollAmsRaw` sets `VisibilityTimeout: 30` and the job drains up to 50 messages a tick,
routing **every record individually** to its own business profile when profiles are on.
A batch that takes longer than thirty seconds is redelivered while the first pass is
still applying, and the second pass adds the same spend, clicks and impressions again.

**Nothing errors. The numbers are simply bigger.** The same file already records what
this class of bug costs: 905 rows holding negative impressions across 46 days, totalling
−5,478, from deltas applied without a baseline.

And the only thing that could tell a redelivery from a new message was being **thrown
away at the transport boundary**:

```ts
// services/ams-sqs.service.ts — before
export interface AmsRawMessage { receiptHandle: string; body: string }
.map((m) => ({ receiptHandle: m.ReceiptHandle as string, body: m.Body as string }))
```

SQS's `MessageId` was never carried out of the poller.

### 1.2 Nothing checked the subscriptions

`createAmsSubscription` / `listAmsSubscriptions` exist, and
`POST /advertising/ams/subscribe` lists then creates the missing datasets — but only
when an operator presses it. Nothing periodic. The plan's own row says *"not checked
today"*, and that is right.

This failure is silent by nature: a subscription never created, or one Amazon dropped,
produces no error anywhere — just an hour of advertising data that never arrives.

### 1.3 The existing route treats "could not read" as "nothing subscribed"

```ts
try { ...listAmsSubscriptions... } catch { /* list best-effort */ }
```

`have` is left empty and every dataset is then attempted. A list that **could not be
read** and a list that **came back empty** are opposite facts.

### 1.4 SNS confirmation does not apply here

A grep for `SubscriptionConfirmation` / `SubscribeURL` finds nothing, and it should not:
this installation's AMS destination is an **SQS queue** (`NEXUS_AMS_DESTINATION_ARN`,
drained by `ams-sqs-poll`), not an HTTPS SNS endpoint. There is no confirmation handshake
to answer. Stated rather than left looking unbuilt.

## 2. What changed

| File | Change |
|---|---|
| `services/ams-sqs.service.ts` | `AmsRawMessage` carries `messageId` |
| `jobs/ams-sqs-poll.job.ts` | Dedupe through the **P2.1 inbound ledger**, keyed on the SQS message id. Ledger-first: no row, no ingest, no ack |
| `jobs/ams-subscription-check.job.ts` (new) | Nightly at 04:10 UTC. Reports per profile and dataset; creates nothing |
| `services/advertising/ads-marketing-stream.service.ts` | `amsRegionFor` exported — it was a local `const` in a route |
| `routes/advertising-intel.routes.ts` | Uses that one function instead of its own copy |
| `index.ts` | Starts the check |

### 2.1 The decisions worth keeping

- **The dedupe reuses the P2.1 ledger rather than a new table.** AMS is an inbound
  event; `recordInbound` is already idempotent on `(channel, externalId)` and reports
  the existing status. That also gives AMS the retry, dead letters and replay every
  other channel got in P2.1. A second dedupe table beside the first is exactly the
  drift this programme keeps finding.
- **Only a `done` duplicate is skipped.** A redelivery of a message whose first attempt
  FAILED is the retry we want, not a duplicate to drop.
- **Ledger first.** Without a row we cannot tell a redelivery from a new message, and
  with an incrementing write that is the one place a guess is expensive. The message is
  left on the queue.
- **The message is recorded in the platform's workspace.** One message carries records
  for several advertisers, so it belongs to no single business. The per-record routing
  that decides where the DATA goes is untouched.
- **A failed list is `unknown`, never `missing`.** See 1.3.
- **An ARCHIVED subscription counts as missing.** It is present in the list and delivers
  nothing — the most misleading of the three states, because counting subscriptions
  would call that profile healthy.
- **An empty sweep is not reported as healthy.** A green with an empty denominator is
  the most reassuring wrong answer there is.

### 3.2 A wrong default was caught before it shipped

The check's first draft imported `amsRegionFor` from `ads-core/ams-dataset.js` with a
`.catch(() => ({ amsRegionFor: null }))` and fell back to `'NA'`. That export does not
exist — the function was a local `const` inside `advertising-intel.routes.ts` — so
**every profile would have been asked in the wrong region**, every list would have
failed, and every profile would have read as `unreadable`: an Amazon outage rather than
a mapping bug. The function is now exported once and the route uses it too, so the two
cannot drift to different region maps.

## 4. Still open

1. **The done-when is not met, and cannot be checked from here.** *"Hourly data arrives
   for every live profile"* is exactly what the nightly check now measures — its first
   run is the answer, and it has not run yet.
2. **The duplicates already applied are not corrected.** This stops new double-counts;
   it does not find or unwind any that happened before today. Doing that needs a
   reconciliation against Amazon's own reports, which is P3/P4 territory.
3. **The check reports; it does not create.** Creating a subscription is a live channel
   call. `POST /advertising/ams/subscribe` remains the operator's tool.
4. **`VisibilityTimeout: 30` is unchanged.** The dedupe makes a redelivery harmless
   rather than making it rare. Raising it, or shrinking the per-tick batch, is a
   separate tuning decision with its own measurement.
5. **`/advertising/ams/subscribe` still swallows a failed list** and then attempts every
   dataset (1.3). It is an operator-pressed route and was left alone; the nightly check
   is the honest reading of the same facts.
