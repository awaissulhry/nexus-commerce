# P6.4 — a disconnect says what happened at the channel, and where to finish

State: **BUILT 2026-09-21**, committed locally.

Plan row (FINAL-PLAN.md §6, P6.4): *"Revoke at the channel where it can be done; where
not, clear locally and show the channel page link."*
Plan §4.1: *"Disconnect calls the channel only for eBay."*

## 1. Evidence (measured 2026-09-21)

| fact | state |
|---|---|
| channels declaring a `revokeUrl` | **1 of 5** — eBay only |
| `revokedAtChannel`, returned by `POST /accounts/:id/disconnect` | returned, and read by **no web caller** |
| a "where to revoke" link anywhere in the tree | **none** |
| what the screen said when nothing was revoked | *"Disconnected — the stored grant was removed from Nexus."*, tone **success** |

🔴 So for **Amazon SP-API, Amazon Ads, Shopify and Etsy** a disconnect cleared *our
copy* of the credentials while the grant **kept existing at the channel** — and the
operator was shown a green *"Disconnected"* with nothing to click.

The old sentence was not a lie; it says "removed from Nexus". But the tone said
**success** and the screen offered no way to finish, so the half-done state read as
done. A green for a half-done job is the kind that teaches an operator the screen is
not worth reading.

**P4.5e found the same class from the other side** — the Ads client kept calling Amazon
after a disconnect because a legacy row still held a token. This is the half the
operator can see.

## 2. Changes

1. `services/cx/catalog.ts` — `ChannelSpec.auth.revokeHint?: { url; label; detail }`:
   where a **human** removes the grant, for a channel with no revoke endpoint.
2. The four connector specs declare theirs:
   | channel | where |
   |---|---|
   | Amazon SP-API | Seller Central → Apps & Services → Manage Your Apps |
   | Amazon Ads | Amazon account → Login with Amazon → Manage apps |
   | Shopify | Shopify admin → Settings → Apps and sales channels |
   | Etsy | Etsy → Account settings → Security → Apps |

   Each carries a **sentence**, not just a link — Shopify's says that uninstalling is
   what removes the token and that a disconnect here only clears our copy.
3. `routes/accounts.routes.ts` — returns `revokeHint`, and returns **null** when the
   channel genuinely revoked it. A hint beside a completed revoke would tell the
   operator to redo something already done: the same false-instruction trap P6.2
   avoided in its alert wording.
4. `apps/web/.../channelDetail.ts` — `disconnectAccount` carries the hint instead of
   discarding it, and **new** `disconnectNote()` gives three outcomes three sentences:
   - revoked at the channel → **success**, "the grant was revoked at the channel";
   - not revoked, hint known → **warning**, "the grant still exists at the channel" +
     the link;
   - not revoked, no hint → **warning**, and still a sentence. A channel added later
     with neither must not render an empty banner.
5. `ChannelDetailClient.tsx` — uses it and renders the link
   (`target="_blank" rel="noreferrer noopener"`).

## 4. What this does NOT claim

The four hint URLs are the channels' **published settings pages**, written from their
documented navigation paths. They were not opened and clicked in this session. If one
moves, the sentence still tells the operator what to look for — which is why each hint
carries a `label` describing the path, not only a bare link.

**Shopify has a REST "delete current API permissions" call** that uninstalls an app.
It is deliberately not wired here: P1.4 put every Shopify change on the `2026-07`
GraphQL client with a named account, and the gateway **refuses** a Shopify write on any
other path. Adding a REST uninstall would need an exemption to that rule, which is a
bigger decision than this row — recorded rather than taken.

## 5. Production proof — OPEN

Needs one operator action, and it is safe: disconnect any non-eBay account. The banner
should be **amber**, say the grant still exists at the channel, and carry a link to
that channel's app settings. Disconnecting an eBay account should stay **green** and
show no link.
