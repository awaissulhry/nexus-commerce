# P1.7 — validate before send

State: **BUILT (2026-09-20), committed locally (not pushed, not deployed).** One piece is held for the Owner: the Amazon flat-file route (`build/P1.7-flat-file-edit-list.md`).

Plan row (FINAL-PLAN.md section 6, P1): *Validate before send: Amazon `VALIDATION_PREVIEW` for every content write; eBay `Verify…` calls before Add. Push lock also blocks `ENDED` listings. Done when: no Amazon content write without a preview; a closed or ended listing cannot come back.*

## 1. What was measured first (2026-09-20)

A full read-only census, every claim with its command:

- **Amazon.** The preview is `AmazonSpApiClient.validateListing` (`clients/amazon-sp-api.client.ts:984`), `mode=VALIDATION_PREVIEW`, classified as a **read** by the gateway. Three content writers had it (studio, cockpit, and the media publisher in its review stage); **six had none**: the flat-file submit route, the batch feed (and the image feed that delegates to it), the outbound queue except one source, the listing wizard's full PUT, the direct publish route, and the variation-sync processor.
- **eBay.** 18 create paths; **one** (the studio) ran `VerifyAddFixedPriceItem` first. The Trading helper `addFixedPriceItem` — used by the queue path, `createSharedListing` and its bulk loop — did not. The Sell Inventory API has no verify step to add.
- **Push lock.** It refused `syncPaused` and `offerClosedAt`. Its `presenceIntent` arm — the one that carried ENDED — **could never fire**: the column is in a staged migration, absent from `schema.prisma` and from the generated client (`/usr/bin/grep -c "presenceIntent" node_modules/.prisma/client/index.d.ts` → 0). `ChannelListing.listingStatus`, which does exist and does carry `ENDED`, was never read. The only working ENDED refusal in the repo was the eBay label guard's own.

## 2. Change

### 2.1 The push lock refuses an ENDED listing (`04166df5d`)

`assertPushAllowed` now refuses when `listingStatus` is `ENDED` (trimmed, case-insensitive) or when `endedAt` is set — the second starts working the day the Presence migration lands, with no further change. New code `PUSH_LISTING_ENDED`. Precedence unchanged: paused, then closed, then a deliberate intent, then the channel's own status. The eBay label guard keeps both codes its tests pin.

Every caller that passes a full row gets the rule for free (the 24 sites that go through `readPushControls`, which selects no columns, and the direct full-row reads). Five synthetic `{ offerClosedAt }` literals stay as they are: each sits beside a real-row call.

### 2.2 eBay verifies before it adds (`ee9fe18ea`)

`addFixedPriceItem` calls `VerifyAddFixedPriceItem` with the **same** item XML first (new exported `verifyAddFixedPriceItem`). Success or Warning proceeds; anything else refuses with `notSent`, so a listing eBay would reject is never created. One place covers the three Add call sites. A local rehearsal is recognised by its `DRYRUN-` answer and sends nothing; a real but empty answer is still a refusal.

### 2.3 Amazon dry-runs every content write (`986b2862e`)

New `services/amazon/validate-before-send.ts`:

- `isAmazonContentPatchSet` — `purchasable_offer`, `list_price` and `fulfillment_availability` are price and stock; anything else is content. Read from what is actually sent, not from the row's label, so a mixed payload counts as content.
- `amazonContentRefusal` — runs the preview and returns the sentence to report, or null. **Fail-closed**: a preview that cannot run at all stops the write. A warning is not a refusal.

Wired into: the outbound queue (every content patch set, not only `FM_CATALOG_CASCADE`), the listing wizard's full PUT, the direct publish route, and the batch feed's image messages.

## 4. Traps met

1. **`@nexus/shared` runs from `packages/shared/dist`, which is not in git.** The first full suite after the push-lock change measured the **old** rule; the new failure (the label guard) only appeared after `npm run build` in that package. Rebuild it before trusting a local run; production builds from source.
2. A JSON listings feed is **not** all-or-nothing at Amazon: each message is reported on its own. The batch feed here still refuses the whole submission when one image message is refused — image batches are small and a loud refusal is the safer default — but the wording in commit `986b2862e` overstates Amazon's behaviour. The flat-file proposal (section 5) deliberately skips refused rows instead of refusing the sheet.
