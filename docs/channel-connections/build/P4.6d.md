# P4.6d — listing content and images on Etsy

**Package:** P4.6. **Slice:** d. **State:** BUILT, local, green.

## 1. 🔴 One channel, three body formats

The single most surprising thing about writing to Etsy, and the reason callers do not build these
requests themselves. All four rows are from Etsy's OpenAPI document (read 2026-09-21):

| what | endpoint | body | partial? |
|---|---|---|---|
| stock / price (P4.6c) | `PUT /listings/{id}/inventory` | **JSON** | no — **full replace** |
| content | `PATCH /shops/{shop}/listings/{id}` | **form-encoded** | **yes** |
| add an image | `POST /shops/{shop}/listings/{id}/images` | **multipart** | — |
| remove an image | `DELETE …/images/{image}` | none | — |

`application/json` and `application/x-www-form-urlencoded` **one path apart**, and sending the
wrong one is a 400 that does not say which. The write client now carries `form`, and a test pins
the header on both paths.

A content write being **partial** is the good news: unlike the inventory PUT, a field left out is
left alone, so it carries no regional-pricing risk and needs no read-back to be safe.

## 2. 🔴🔴 `state` is not a content field, and that is the finding

Etsy's own words on `updateListing`'s `state`:

> *"Setting a `sold_out` listing to active will **update the quantity to 1** and **renew** the
> listing on etsy.com."*

So a field that reads like *"show this listing again"* is, on a sold-out listing, **three** things:

1. a state change — what the caller wanted;
2. a **stock write Nexus never made**, straight past `resolveIntendedQuantity`, the shared-stock
   pool and the audit — the exact class of defect P4.3a found in `syncInventoryFromEtsy`, arriving
   this time through a *content* field;
3. a **renewal, which Etsy charges the shop for**.

Had `state` sat beside `title` in one object, an operator editing a title could have done all
three by adding a field. It is a separate function with a separate name, and setting `active`
requires `acceptRenewalAndQuantityReset: true` — no default, so a caller that has not thought
about it cannot agree to it by omission. Setting `inactive` needs no such yes: it costs nothing
and resets nothing. **`should_auto_renew` is left out entirely** for the same reason — it commits
the shop to a recurring charge.

A test proves the runtime refuses `state` through the content path too, so a caller casting
through `any` cannot publish and renew a listing while believing it edited a title.

## 3. Etsy's text rules, checked before the call

Etsy publishes an exact regex per field. They are **copied into the code with Etsy's sentence
quoted beside each**, and checked locally — not from distrust, but because a rejected write costs
a live call and a ledger row, and *"the character «$» is not allowed in a title"* is a far better
answer than a 400.

| field | Etsy's set |
|---|---|
| title | `\p{L} \p{Nd} \p{P} \p{Sm} \p{Zs} ™ © ®`, and `%`, `:`, `&`, `+` **once each** |
| tag | `\p{L} \p{Nd} \p{Zs} - ' ™ © ®` |
| material | `\p{L} \p{Nd} \p{Zs}` only |
| description | **no rule published, so none invented** |

### ⚠️ Three predictions written into the test were wrong, and the regex settled it

The first version of this test asserted `$`, `€` and `<` were all refused in a title. Running it
showed `<` is **allowed**, so the test was wrong and the code was right. Derived from Etsy's
regex rather than from intuition:

- **Allowed** in a title: `< > = + ~ |` (mathematical symbols, `\p{Sm}`) and `# @ ! ? / *`
  (punctuation, `\p{P}`).
- **Refused** in a title: `$ € £ ¥` (**currency** symbols, `\p{Sc}`) and `` ` `` `^` (modifier
  symbols, `\p{Sk}`).

🔴 **A currency symbol cannot appear in an Etsy title.** `"$19.99 Ceramic Mug"` is refused while
`"50% off Mug"` is fine — which reads backwards from what a seller expects, since a price in a
title is an ordinary thing to want. It has its own test and its own sentence. The allowed set has
its own test too, so a later "tidy-up" that tightens the regex breaks a test rather than real
titles.

Nothing is ever **trimmed to fit**: an over-long alt text and an over-size image order are
refused. A title silently cut is a change the operator did not make and cannot see.

## 4. `undefined` and `null` are different instructions

On a PATCH they have to be: `undefined` is *"do not touch this field"* and `null` is *"clear this
field"*. `encodeEtsyForm` leaves the first out and sends the second empty. An **empty array** is
also sent, because *"this listing now has no tags"* is a real instruction and sending nothing
would mean *"leave the tags alone"*. Collapsing any of these is how a partial update quietly
blanks something nobody asked it to.

Arrays become **repeated keys** (`tags=a&tags=b`), which is what OpenAPI's default for a form
body declares when no `encoding` is given — and Etsy's document declares none. See §6.

## 5. Proof — 49 + 25 tests, all green

`listing-write.p46.vitest.test.ts` (49) and the extended `write-client.p46.vitest.test.ts` (25).

**Mutations: 16 applied, 16 killed**, with a 🟢 null-mutation control that correctly SURVIVED.

⚠️ **One survived the first run and was a real gap.** *"send the form body as JSON"* broke no
test — nothing checked the `Content-Type`, so the one defect that would fail **every** content
write was invisible. Three cases now pin it: form → `x-www-form-urlencoded` with the exact encoded
string, 🟢 a positive control that the same client sends JSON for the inventory PUT, and a form
body winning if a caller somehow sends both. Re-run: **KILLED**, plus a new M15 (*form body
ignored*) also killed.

## 6. The one thing a live call should settle

**Array encoding in a form body.** Etsy's document declares no `encoding`, so OpenAPI's default —
`style: form, explode: true`, i.e. repeated keys — is what it formally specifies, and that is what
is built. But the `tags` and `materials` **descriptions** still say *"a comma-separated list"*,
which is v2's phrasing.

**Prediction, written before any live call:** repeated keys are accepted, because the schema types
them as arrays and the description is legacy prose. If a live `updateListing` with two tags comes
back 400, the fix is one line in `encodeEtsyForm` — join with `,` instead of appending — and the
test at `P4.6d — encodeEtsyForm › an array becomes repeated keys` is where to change it.

This is written down rather than guessed at, and it needs a **live channel call**, which needs the
Owner's yes.

## 7. Open

  lane, which is where `resolveIntendedQuantity` binds to P4.6c's writer.
- Etsy's `createListingTranslation` / `updateListingTranslation` exist and are **not** built here.

  authority; joining them is its own decision, not a line in this slice.
