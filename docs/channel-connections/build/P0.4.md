## 2. Changes

1. `services/refunds/refund-publisher.service.ts` — `issue_refund` goes through `ebayFetch(connection.id, url, { method: 'POST', marketplaceId, headers: { 'Accept-Language': 'en-US' }, body })`. The client takes the token from the token service (the same source `getValidToken` uses when the token service is on) and signs. Unchanged: the account lookup, the "eBay auth failed" pre-check, the call-ledger row (`recordApiCall`), the body, the error parsing and the result.
2. **Fix to P0.3** (`lib/outbound-webhook.ts`): `node:http` / `node:https` are imported when a webhook is sent, not at module load. The P0.3 version broke `services/pim/theme-change.vitest.test.ts` (it failed to load). Details and proof: `build/P0.3.md` section 4, CORRECTION.

## 5. Found, but NOT in this package

- When a Return has no order id, the refund falls back to the **primary** eBay account (`tryResolveConnection({ channel: 'EBAY', primary: true })`). The wrong-account guard is P0.7.
- `services/refunds/retry.service.ts` re-runs refunds. eBay `issue_refund` sends no idempotency key, so a retry after an unknown outcome (a timeout after eBay applied it) relies on eBay refusing a second full refund. Worth a look under P1 (idempotency, plan section 7.1 item 8).
- `Accept-Language: en-US` is hard-coded for every marketplace (P1.5 is the header builder).
