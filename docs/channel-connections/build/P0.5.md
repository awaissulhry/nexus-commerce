## 2. Changes

API:
1. **New** `services/cx/app-secret-expiry.ts` — the one module for app-secret dates: `listAppSecrets` (selects no credential column), `setAppSecretExpiry` (writes the date and a ledger event `app_secret_expiry_set` with who, from and to), `appSecretAlertLevel` (most urgent level reached: 90, 30, 7, or 0 = expired), `runAppSecretExpiryAlerts` (each level once per recorded date, deduped on a ledger event `app_secret_expiry_warn` keyed by environment + date + level; a new date starts the levels again).
2. `routes/cx-connections.routes.ts` — `GET /api/cx/apps` and `PUT /api/cx/apps/:channelKey/secret-expiry` (`{ expiresAt: 'yyyy-mm-dd' | null, environment? }`). A real calendar date only, not before 2020, at most 400 days ahead; stored as midnight UTC (a conservative day: the alert comes a little early, never late). 404 when the app row does not exist.
3. `lib/auth/permissions-manifest.ts` — `/api/cx/apps` needs `settingsIntegrationsManage` (the same as `/api/cx/connections`).
4. `services/cx/events.service.ts` — two new ledger event types.
5. `jobs/cx-heartbeat.job.ts` — the old exact-day block is replaced by `runAppSecretExpiryAlerts()`; a failure there is logged and does not stop the sweep.

Web (`apps/web/src/app/settings/channels/`):
6. **New** `app-secrets.ts` (pure: status tone and words, date format, sort) and **new** `AppSecretsCard.tsx` — an "App secrets" card at the top of the Diagnostics tab: one row per app, Amazon SP-API first, a status pill, one plain sentence, a `DateField` and "Save date". Design-system parts only (`Card`, `Banner`, `EmptyState`, `Field`, `DateField`, `Button`, `Pill`, `Skeleton`); `channels.css` holds geometry only (`--nds-*` tokens).
7. `DiagnosticsTab.tsx` — renders the card (also when no account is connected), and its grid gets `gridTemplateColumns: 'minmax(0, 1fr)'`. Without that, the account picker's fixed 360 px `Listbox` set the track width and **every** card on the tab overflowed a phone-width panel (measured: a 360 px track in a 298 px panel). This was true before P0.5; it is fixed here because the new card sits in the same grid.

Status wording: Amazon with no date = warning "No expiry date recorded" with where to find it; other channels with no date = neutral; > 90 days = success; ≤ 90 info; ≤ 30 warning; ≤ 7 and expired = danger.
