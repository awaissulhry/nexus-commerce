# P5.3 — one Shopify API version, and a quarterly bump that is one line

State: **BUILT 2026-09-21**, committed locally. (Previously: MEASURED, not built.)

Plan row (FINAL-PLAN.md §6, P5.3): *"Shopify: remove or move the 6 `2024-01` clients to
`2026-07`. Then a routine: move to the newest version every quarter."*
Deadline: **already out of support**.

## 1. Evidence (measured 2026-09-21)

P1.4 did most of it: `SHOPIFY_API_VERSION` became the single accessor
(`services/shopify/api-version.ts`), and the six `2024-01` clients came down to **two**,
both READS.

| site | what it was |
|---|---|
| `utils/config.ts:45` | `process.env.SHOPIFY_API_VERSION \|\| "2024-01"` — a stale default |
| `services/images/shopify-live-images.service.ts:97` | a hard-coded `'2024-01'` on a REST `GET /products/{id}.json` |

(The two other `2024-01` strings in the tree are historical comments in
`listing-write.service.ts` and `outbound-sync.service.ts`, recording a path that was
deleted.)

🟢 **Both were dead — and this time it is measured, not inferred.**

`/admin/api/2024-01/` has **0 rows** in `OutboundApiCallLog`. Every Shopify call there
is on **`2026-07`**: 43 × `graphql.node`, plus `metafieldDefinitions`,
`metaobjectDefinitions`, `publications` and `shopLocales`, all 200, last 2026-09-20.

The previous session *suspected* the REST read had never run, reasoning from P2.4's
"production has no `SHOPIFY_*` variable". The call ledger says so **directly** — a
better class of evidence, and worth the two minutes it took.

And `config.ts`'s value is dead twice over: a census of `.apiVersion` finds only the
channel spec and the call-ledger row — **nothing reads it** — and `loadShopifyConfig`
only runs when all three `SHOPIFY_*` variables are set.

### Why `2024-01` was not the cautious choice it looked like

It has been out of Shopify support for **over a year**, so the REST path was broken on
*both* versions. Moving it cannot regress anything observable (it has never run), and
the supported version at least fails clearly if it ever does.

## 2. Changes

1. `utils/config.ts` — the fallback is `SHOPIFY_API_VERSION`, not a second literal.
2. `services/images/shopify-live-images.service.ts` — `const apiVersion = SHOPIFY_API_VERSION`,
   with the measurement and a ⚠️ recorded in place: **if this ever gets credentials it
   should move to the GraphQL admin client**, not have its REST version bumped again.
   A REST products read is not like-for-like on a modern version, and every other
   Shopify path already goes through `services/shopify/admin-client.ts`.
   **This slice does not claim that reader is now correct — only that it has one
   version source.**
3. **New** `services/shopify/api-version.p53.vitest.test.ts` — the routine the plan
   asked for, as a gate rather than a note: the version is defined **once**, no other
   code line names a Shopify version literal, and a quarterly bump is therefore a
   one-line diff.

## 3. Proof

- **New** `services/shopify/api-version.p53.vitest.test.ts` (6): defined exactly once
  and in the right file; no code line elsewhere names a `YYYY-QQ` Shopify literal; the
  value is a supported version and specifically not `2024-01`; both former sites read
  the accessor; and the gateway still refuses a Shopify **change** on any other version.
- 🟢 **A positive control on the census** — that the definition file itself *does*
  contain exactly one literal of the matched shape. Without it the census passes just
  as well if the pattern stopped matching anything.
- The census reads **code lines only**, so the historical comments in
  `listing-write.service.ts` and `outbound-sync.service.ts` stay as the record they are.
- **Mutation check** (made, run, restored, compared):
  | Mutation | Tests that failed |
  |---|---|
  | the stale `2024-01` default returns | **2** |
  | the REST read hard-codes `'2025-04'` | **2** |
  | a second definition of the accessor appears | **2** |
  | the version goes back to `2024-01` | **1** |
- `tsc --noEmit` (apps/api): 0 errors. `services/shopify` + `services/images` +
  `utils`: **443 passed, 1 skipped, 43 files**.

## 4. The quarterly routine, as the plan asked

Bumping Shopify is now: change the one line in `services/shopify/api-version.ts`, run
the API suite. The gate above is what keeps it to one line — a second literal fails it
with the file and line that added it.

## 5. Production proof — OPEN

Nothing changes: the two moved sites have never run (0 calls on `2024-01`), and every
live Shopify call was already on `2026-07`. The proof is that the Shopify reads keep
returning 200 on `2026-07`, as they already do.
