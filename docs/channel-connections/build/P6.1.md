# P6.1 — Automatic Amazon app-secret rotation

State: **BUILT (2026-09-19), committed locally (not pushed, not deployed). OFF until the Owner does the one-time setup in section 4.** Run under the Owner's "Start to implement the whole plan" (FINAL-PLAN 14.3).

Plan (FINAL-PLAN.md section 6.1): Amazon requires a new SP-API app secret every 180 days; if it is missed, every Amazon call stops. Nexus rotates it by itself: ask Amazon for a new secret 30 days before expiry, read it from the registered queue, test it, store it encrypted, set the next date. Done when: a rotation runs end to end, the new secret is used by every Amazon call, and the old one is never read again.

## 1. How Amazon's rotation works (read 2026-09-19 on Amazon's own pages)

Sources: developer-docs.amazon "Rotate your application's client secret", "Set up credential rotation notifications", "LWA Credentials FAQ"; the model `application-management-api-model/application_2023-11-30.json`; Amazon's sample `use-cases/lwa-rotation` (github.com/amzn/selling-partner-api-samples).

- `rotateApplicationClientSecret` = `POST /applications/2023-11-30/clientSecret` on `sellingpartnerapi-{na|eu|fe}.amazon.com`, with a grantless LWA token for scope `sellingpartnerapi::client_credential:rotation`. Answer: 204. Rate: 1 per minute. Not available for sandbox apps.
- The new secret is sent ONLY to the SQS queue registered for "Application Client New Secret": `APPLICATION_OAUTH_CLIENT_NEW_SECRET`, payload `applicationOAuthClientNewSecret { clientId, newClientSecret, newClientSecretExpiryTime, oldClientSecretExpiryTime }`.
- Expiry warnings go to the queue registered for "Application Client Secret Expiry": `APPLICATION_OAUTH_CLIENT_SECRET_EXPIRY`, payload `applicationOAuthClientSecretExpiry { clientId, clientSecretExpiryTime, clientSecretExpiryReason }`.
- The queue policy must allow principal `437568002678` `SendMessage` + `GetQueueAttributes`.
- The old secret keeps working 7 days after rotation (in some cases less). Refresh tokens do not change.

## 3. Changes

1. **New** `services/cx/amazon-secret-rotation.service.ts`:
   - `handleAmazonCredentialMessage` — an expiry notice for our app records the date (the P0.5 date, no typing needed); a new secret for our app is **tested with a real token exchange**, then stored sealed in `ChannelApp` with its expiry and `rotatedAt`, and recorded (`secret_rotated`, without the secret). A secret that fails the test or cannot be stored is **left on the queue** and alerted. Messages for another app are ignored.
   - `requestAmazonSecretRotation` — refuses (0 calls to Amazon) unless the credential queue is configured, readable by Nexus, and its policy lets Amazon's principal send to it: a rotation without that would lose the only copy of the new secret. Then: rotation-scope token from the current secret → `POST …/clientSecret` → 204 → `secret_rotation_requested`; anything else → `secret_rotation_failed` + alert.
   - `runAmazonSecretRotation` — one pass: read the queue; if the secret expires within 30 days, no rotation in the last 24 hours and none stored in the last 7 days → request one and wait up to 60 s for the new secret.
   - A secret never reaches a log line, the ledger, an alert or an API answer.
2. **New** `jobs/amazon-secret-rotation.job.ts` — every 10 minutes, platform-wide (one app for all of Nexus; it runs in the legacy profile like the other platform jobs), only when `AMAZON_APP_CREDENTIAL_QUEUE_URL` is set. Registered at boot (`index.ts`) and in the manual-trigger registry (`amazon-secret-rotation`).
3. `services/cx/apps.service.ts` — `storeClientSecret` (sealed, with expiry and `rotatedAt`; drops the 60-second cache so the next exchange uses it).
4. Env readers moved to `ChannelApp`: the grantless token (`clients/amazon-sp-api.client.ts`), the readiness check, the diagnostics route.
5. **Safety net for a shared queue** (`services/amazon-sqs.service.ts`, `jobs/amazon-sqs-poll.job.ts`): if the Owner registers the SAME queue as the notifications queue, a credential message there is recorded in the ledger with a **redacted** payload, handed to the rotation handler, and deleted only when the handler is done (before this, the P0.6 poller would have stored the body — with the secret — as an unknown type).
6. Channels → Diagnostics → App secrets: the Amazon row says whether automatic rotation is on, and when it last rotated (`GET /api/cx/apps` gains `automaticRotation`).
7. `services/cx/events.service.ts` — two ledger types: `secret_rotation_requested`, `secret_rotation_failed`.

## 4. The Owner's one-time setup (turns it on)

1. **AWS → SQS:** create a Standard queue (for example `nexus-amazon-app-credentials`) in the same AWS account and region as the notifications queue, so Nexus's AWS keys can read it. Use SQS-managed encryption (SSE-SQS). Give Nexus's IAM user `ReceiveMessage`, `DeleteMessage`, `GetQueueAttributes` on it.
2. **Queue access policy:** allow principal `437568002678` the actions `sqs:SendMessage` and `sqs:GetQueueAttributes` on the queue ARN (Amazon's "Set up credential rotation notifications", step 1).
3. **Solution Provider Portal → Developer Console → Notification Preferences → Subscription → our app:** select the queue ARN in BOTH rows, "Application Client Secret Expiry" and "Application Client New Secret".
4. **Railway, `@nexus/api`, production:** set `AMAZON_APP_CREDENTIAL_QUEUE_URL` to the queue URL, then deploy.
5. **Check:** Settings → Channels → Diagnostics → App secrets shows "Automatic rotation is on". The expiry date arrives with Amazon's next expiry notice; to have it at once, record it by hand (P0.5).

Until step 4, nothing in this package calls Amazon, and the rest of Nexus behaves as before.

After the Owner's setup and a push: the App secrets card says rotation is on; `CronRun` rows `amazon-secret-rotation` appear every 10 minutes with "N days left, nothing to do" until 30 days before expiry; then one `secret_rotation_requested` and one `secret_rotated` in the ledger, the card's date moves ~180 days ahead, and `OutboundApiCallLog` shows Amazon calls continuing with no `invalid_client`.

## 7. Not in this package

- A "rotate now" button for an early, deliberate rotation (for example after a leak). The code rotates only inside the 30-day window; an early rotation is a manual step in the Solution Provider Portal (then record the new date, or let the expiry notice record it). Ask if a button is wanted.
- Rotation for the Amazon Ads app, eBay and the eBay signing key is P6.2.
