**"push allowed"**, and the comment states the fail-open as a *principle*.

The ruling is right, for a reason worth keeping: **Amazon holds ONE merchant

🔴 **"We could not check" is not "there is no conflict."** A retry is cheap: the
row stays queued and the next attempt runs the guard again. Sending blind is not
reversible.

**This is the fourth fail-open found in one day** — after P4.1d (policy
reconciliation warned instead of refusing), P4.1e (the lane marker guessed) and
P4.2a (unmatched SKUs going unreported). **A rule's `catch` is where it goes to

## 3. What was built

The catch now **holds** the push: it returns the same `SKIPPED` shape the
conflict branch uses, with `error: "eu-shared-qty-guard-unavailable"`.

🔴 **It alerts under its OWN conflict type**, `EU_SHARED_QTY_GUARD_UNAVAILABLE`,
added to the `ConflictType` union beside `EU_SHARED_QTY_CONFLICT`. Reusing the
conflict type would tell the operator **their listings disagree** when the truth
is that **our guard broke** — one is theirs to fix, the other is ours, and a
screen that blends them sends the operator to the wrong place.

The operator's sentence says it was held, why (one EU quantity per SKU), and that
it will be retried, plus the existing `EU_GUARD_REMEDY`.

**The alert never decides the push.** `logConflict` is wrapped and best-effort,
and the `return` sits *outside* that try — an alert failure must not re-open the
gate. A mutation moves the return inside and the test convicts it.

The **conflict** path is untouched; only the failure path changed.

## 5. What this changes in production

A push whose guard check throws is now **held and retried** instead of sent. If
the guard's query is broken for a sustained period, Amazon quantity pushes will
back up in the queue rather than going out unchecked — which is exactly what D9
asks for, and it is visible: the queue backlog age is one of P3.6's four Health
metrics, and each held row raises a conflict the Diagnostics tab shows.

**Watch for it after this deploy.** A sudden rise in
`EU_SHARED_QTY_GUARD_UNAVAILABLE` means the guard's own query is failing, not
that listings disagree.
