# P4.5f — nothing creates a deprecated Sponsored Brands entity by accident

State: **BUILT 2026-09-21**, committed locally. Part of P4.5 (advertising).

Plan row (FINAL-PLAN.md §6 deadline table, 2026-07-06): *"Sponsored Brands 'Product
collection' ad entity deprecated in favour of Manual / Auto Collection (**CONFIRMED**).
A full shut-off in January 2027 is reported by a third party only (**NOT CONFIRMED** on
Amazon's pages). **CODE:** Sponsored Brands creation defaults to
`creativeType: 'productCollection'` (`services/advertising/ads-create.service.ts:940`).
→ P4.5: default to Manual Collection."*

## 1. Evidence

**The defect is real and is a silent default.**
`createSbAdLocal` read `const creativeType = input.creativeType ?? 'productCollection'`.
Its **one** caller, `POST /advertising/sb-creatives/create`
(`routes/advertising.routes.ts:8347`), passes the request body straight through as
`never`. So an operator who simply did not mention a creative type got the deprecated
entity, with nothing said.

**The path has never run.** Measured on the development database 2026-09-21:

| | |
|---|---|
| `POST /sb/v4/ads` in `OutboundApiCallLog` | **0** |
| `POST /sb/v4/ads/list` (the read) | 285 |
| `AdProductAd` rows with `adType: 'BRAND_AD'` | **0** |

So the default has never actually produced a deprecated ad — which is what makes this
cheap to fix and impossible to verify against a real Amazon answer.

### 🔴 The line this slice would not cross: renaming the wire value

The plan row says *"default to Manual Collection"*. **The wire value for Manual / Auto
Collection could not be established.**

- Amazon's `POST /sb/v4/ads` API reference renders only with JavaScript — P0.8 hit the
  same wall on the deprecations page — so `WebFetch` returned only the page title.
- Two web checks (2026-09-21) produced third-party write-ups and no enum.
- With 0 stored calls there is no Amazon answer in `OutboundApiCallLog` to derive it
  from either.

Swapping a value Amazon **still accepts** — it deprecated the entity, it did not remove
it, and Amazon's own note carries **no shutdown date** — for a guessed one, on a path
that has never run, is the worse trade. *Predict before you write* cuts both ways: a
change whose correct value cannot be stated in advance is not a fix.

**The same restraint applies to the casing.** Every other enum this client sends on SB
v4 is upper-cased (`state: (…).toUpperCase()`), and `adType: 'productCollection'` is
not. That is a smell recorded in the vocabulary file, **not a finding** — nothing
available can tell "wrong case" from "this endpoint's convention".

**One thing the web check did add, and it is recorded with its status:** two
third-party sources report that since **September 2026** Amazon auto-converts newly
created Product Collection campaigns to Manual Collection. Reported, not confirmed on
Amazon's pages — the same standing as the January 2027 date P0.8 recorded.

## 2. Changes

1. **New** `services/ads-core/sb-ad-types.ts` — the three SB creative types, each with
   its wire value, its label, and its deprecation (date, replacement, shutdown date,
   **source**). `sbAdTypeWire()` refuses a type the file does not name;
   `sbAdTypeNotice()` returns the sentence for a deprecated one.
   - `shutdownDate` is **null**, not January 2027. Storing a third-party date as if it
     were Amazon's is how a rumour becomes a deadline.
2. `ads-create.service.ts` — **no default**. An omitted `creativeType` is refused with a
   sentence that names the deprecation and lists the choices. An explicitly chosen
   deprecated type is still **sent** (refusing would break an operator deliberately
   matching an existing campaign's format) and **logged** as deprecated.
3. `ads-api-client.ts` — `adType: sbAdTypeWire(input.creativeType)`: one vocabulary.

## 4. Open — what would close this properly

**This row is NOT finished, and saying otherwise would be the false green.** To move
Sponsored Brands onto Manual Collection, one of:

1. A captured **200 from a real `POST /sb/v4/ads`** (which is a live channel call and
   needs the Owner's yes), or
2. the `adType` enum read off Amazon's **rendered** API reference — the page needs a
   JavaScript-capable browser, which this session did not use.

Until then the behaviour is: nothing chooses the deprecated entity for you, and
choosing it deliberately says so in the log.

**Production proof:** nothing to observe. The path has never run, so the only visible
change would be a 500 from `/advertising/sb-creatives/create` with the new sentence if
an operator posts without a `creativeType`.
