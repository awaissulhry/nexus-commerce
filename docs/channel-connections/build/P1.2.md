## 1. The ratchet

`apps/api/scripts/channel-gateway-ratchet.mts` (TypeScript AST, read-only), run by `.githooks/pre-push` after the MAP.3 check.

- Counts every `fetch(`, `https.request(`, `axios…(` and `new SellingPartner(` that talks to eBay, Amazon SP-API, Amazon Ads, Shopify or Etsy, outside `services/gateway/`. Channel: a host in the call, else the hosts in its file, else the channel in its file path, else an eBay `apiBase` argument.
- A send that is not a channel API call carries `// gateway-exempt: <reason>` (an OAuth token exchange the gateway depends on, a pre-signed storage URL, our own CDN, a connector heartbeat). It is listed, not counted. No reason = counted.
- `--check` fails when a channel's count is above its baseline (in the script). `--list` prints every site.

## 2. P1.2a — Amazon SP-API on the gateway

| Path | Change |
|---|---|
| The SDK (`amazon-sp-api`, 69 `callAPI` sites in 21 files) | Every instance is made in `lib/amazon-sp-client.ts`. Its one sender (`_request.api`) is replaced by `services/gateway/amazon-sdk.ts` `routeSdkThroughGateway`: the SDK still builds the request and shapes the answer (payload, pagination, `CustomError`, its own QuotaExceeded retry). An SDK version without that sender is **refused** (`SdkShapeChanged`), never bypassed. Replaces the old per-call ledger wrapper (no double rows). |
| The listings client (`AmazonSpApiClient.fetchWithRetry`, 8 methods + `request()`) | Body now `gatewayFetch`. The fixed 200 ms gap is replaced by the rate bucket. |
| 18 direct sends | notifications setup (5) + admin route (2), 2 diagnostic probes, FBA inbound v0 (4) + v2 client, finances, participations, A+ pull, app-secret rotation request, image media client, legacy catalog read. New helpers: `amazonSellerFetch` (account + region + token resolved in one place) and `amazonGrantlessFetch` (app-level). |
| 22 exempt | 8 OAuth token exchanges, 10 pre-signed document downloads / uploads, the SDK factory (routed), the connector heartbeat, our CDN image download, an operator-configured third-party review feed. |

Gateway additions in this step: `gatewayFetch` (answer as a `Response`, so a `fetch` site moves without changing how it reads the answer; no answer → `GatewayNoAnswer`); `kind: 'setup'`; the safe-to-repeat retry rule; tracing span per call; `operationOfPath` (ledger names without ids); the account check and ledger write in their own modules (`gateway/account.ts`, `gateway/ledger.ts`) with one-line test stand-ins (`test-support/gateway-stubs.ts`); the connectors' rate parsers moved to `services/cx/rate-readings.ts` (the gateway read nothing before, because the specs register only when loaded); the rate bucket gets the app's Redis from `lib/queue.ts` (importing the queue module connected every script and test that loaded the gateway).

## 3. What changes for the Owner

1. **Every Amazon call now writes one ledger row** (before: only SDK calls; the listings client and the direct sends wrote none). The 90-day retention job already prunes the table.
2. **An Amazon write can no longer skip the publish mode.** Production is `live`, so nothing changes there. In a dry-run or gated environment every Amazon write is refused with a sentence, including paths that never checked the mode. A listings `VALIDATION_PREVIEW` is a read and is still sent.
3. **Connection setup is not publishing.** Notification subscriptions, destinations and the app-secret rotation (`kind: 'setup'`) are sent in every publish mode — otherwise a switched-off channel could never connect or receive events.
4. **A write that could apply twice is no longer retried.** The old listings client retried every POST on a 5xx (a label purchase could be bought twice). Now only reads and writes that are safe to repeat (PUT, DELETE, the listings PATCH) retry after a network error or 5xx.
5. **P1.6 candidate found:** `amazon-catalog.service.ts` `fetchFromAmazonAPI` calls a path that is not an SP-API endpoint with a static env token. Moved unchanged; it goes on the P1.6 delete list you approve.
