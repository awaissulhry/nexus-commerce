# P3.1 — One error vocabulary

**Built 2026-09-20.** Plan row: *one error vocabulary (class, channel code, the
channel's own message, attribute, severity, retryable). Every gateway maps into it.*
Done when: *every connector has a mapping table with tests.*

---

## 1. What was measured first

`services/gateway/vocabulary.ts` already had four of the six fields — `errorClass`,
`retryable`, `channelCode`, `channelMessage` — and a mapping function for all five
connectors. Missing: **`attribute`** (0 occurrences) and **`severity`** (0).

And **there was no test for the file at all.** Two suites reference
`classifyChannelAnswer` in passing; nothing asserted what any channel's error body
becomes. So the done-when — *"every connector has a mapping table with tests"* — was
not met for any of the five.

### 1.1 Then the real bodies were run through it

`OutboundApiCallLog` holds **469,455 stored calls**, 201 of them failures with a
response body. Running those verbatim through `classifyChannelAnswer` found four
defects, none of which a hand-written fixture would have shown:

| Real body | What the classifier produced |
|---|---|
| eBay 62005, double-encoded | `channelCode = null`, message = an escaped JSON blob. **The error id was lost.** |
| eBay OAuth `{error, error_description}` | class right, message = the raw JSON blob |
| Amazon Ads `{"code":"400","detail":"…"}` | message = the whole raw body |
| Amazon SP `{"message":"Too Many Requests"}` | message = `"{\n  \"message\": …}\n"` |

**The double-encoding is the big one.** A body stored as a JSON *string* containing
JSON needs two parses; one yields a string, every field read off it is `undefined`, and
the classifier fell through to the raw text:

```
failed bodies that are DOUBLE-ENCODED:
  AMAZON:  81 of 81
  EBAY:    80 of 120
```

**161 of 201.** Every one of them lost its error code and showed the operator escaped
JSON instead of the channel's own sentence.

Two of the others are plain drift: eBay's OAuth endpoints answer in a shape with no
`errors[]` array at all, and Amazon Ads sends both `detail` and `details` while only the
plural was read — the singular being the one four of six sampled bodies use.

---

## 2. What changed

| Change | Why |
|---|---|
| `parseJson` unwraps a double-encoded body, bounded at two passes | 161 of 201 real failures; a loop would turn a malformed answer into a hang |
| `ChannelVerdict` gains `attribute` and `severity` | The plan's six fields; P3.2 cannot put an error on a field without the first |
| eBay: reads `{error, error_description}`, and `parameters[0].name` as the attribute | The OAuth shape is every real `invalid_grant`; the **first** parameter is the seller's field — the second is `queryParam`, eBay describing its own envelope |
| Amazon SP: falls back to a bare `message`, reads `attributeNames[0]` | A throttle has no `errors[]` envelope |
| Amazon Ads: reads `detail` as well as `details` | Both spellings are real |
| Shopify: reads the **last** segment of `field` / `path` | `input` is the mutation wrapper, not the seller's field |
| `vocabulary.p31.vitest.test.ts` (new) | A mapping table per connector — the done-when |

### 2.1 Fixtures: what is real and what is not

Every fixture is labelled in the test file. **REAL** ones are verbatim from
`OutboundApiCallLog`. **SHAPE** ones come from the vendor's documented envelope, because
this installation has recorded no failure for that channel — Shopify, Etsy and Amazon
Ads have **zero** stored failed bodies. Said plainly rather than presented as observed,
because a fixture that looks measured and is not is how P2.2's green-but-wrong test
survived.

## 4. Still open

1. **`severity` is carried but never anything but `error`.** Nothing yet produces a
   warning: Amazon's listings previews and eBay's `Ack: Warning` are the two sources,
   and both are read elsewhere. The field exists so P3.2 has somewhere to put them; a
   verdict that invented a severity would be worse than one that admits it only sees
   failures.
2. **Three connectors have no observed failures**, so their mapping tables rest on the
   documented shape. The first real Shopify, Etsy or Ads failure should be added as a
   REAL fixture — the four defects above are what happens when nobody does that.
3. **Nothing consumes `attribute` yet.** That is P3.2, which puts each error on its
   listing and its field.
4. **The Trading XML path is untouched** beyond its existing code table.
