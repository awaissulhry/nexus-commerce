## 1. P1.3a — every row is created with its account

| Piece | What it does |
|---|---|
| Migration `20260919b_p13_queue_destination` | `ALTER TABLE "OutboundSyncQueue" ADD COLUMN "channelConnectionId" TEXT`. Additive, nullable, no default, no backfill, no index (rows are read by id at send time). Applied to the LOCAL database only. |
| `services/outbound-destination.ts` `resolveDestinations` | The account of each row, batched (a few reads for any number of rows): 1. the account the row names; 2. the account of the listing it names; 3. for a product-only row, the ONE account holding that product in the row's market (UK = GB); 4. else the channel's ONLY account. Two or more candidates → **no account** (`AMBIGUOUS`), never "the primary" (D7). An unreadable account list leaves the row unresolved instead of failing the save. |
| `services/outbound-rows.ts` | The one way to create a queue row: `createOutboundRow` / `createOutboundRows` / `createOutboundRowsAndReturn` — the same arguments and answers as Prisma's `create` / `createMany` / `createManyAndReturn` (typed with Prisma's own create-input types), plus the **listing-claim check** (BP.S3) and the destination account. A light module (no queue import). The claim check's grant read now uses the caller's client, so inside a transaction it takes no second connection. |
| 35 creation sites in 26 files | Each call changed from `x.outboundSyncQueue.create(…)` to `createOutboundRow(x, …)` (and the two batch forms). Sites that already hold the listing pass its account (follow-master, matrix write, master content): no extra read in their transaction loops. |
| Ratchet | `channel-gateway-ratchet.mts` also counts `….outboundSyncQueue.create / createMany / createManyAndReturn / upsert(` outside `outbound-rows.ts` / `outbound-enqueue.ts`. Baseline **0**. |

What changes now: nothing is sent differently yet — the sender still resolves its account as before (P1.3b switches it). The claim check now runs for every row; it only does work with business profiles ON and a **shared** account (one indexed read otherwise), so accounts nobody shares see no change.
