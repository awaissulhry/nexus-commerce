# R7 — Merchant-owned storefront platforms: connector research

Scope: what a third-party PIM must know to let a merchant connect THEIR OWN store on BigCommerce, Magento Open Source / Adobe Commerce, Wix, Squarespace, PrestaShop and Shopware 6. Every fact carries the official URL it was read from. "unverified" = not confirmable from the official pages fetched in this session (2026-08-29). Licensing/pricing deliberately out of scope.

Method note: official developer docs only (docs.bigcommerce.com, developer.adobe.com / experienceleague.adobe.com, dev.wix.com, developers.squarespace.com, devdocs.prestashop-project.org / build.prestashop-project.org, developer.shopware.com / docs.shopware.com), plus the shopware/shopware and PrestaShop GitHub sources where the docs were silent.

## 1. BigCommerce

### 1.1 Auth
- Three OAuth-based API account types: **store-level** (merchant creates in control panel at "Settings > Store-level API accounts", static token), **app-level** (Developer Portal; each store install yields its own token via the grant-code flow), **account-level** ("Settings > Account-level API accounts"; "direct access to all the account's stores"). https://docs.bigcommerce.com/docs/start/authentication and https://docs.bigcommerce.com/docs/start/authentication/api-accounts
- Token header: `X-Auth-Token`. "access tokens do not expire based on time and cannot be manually invalidated." https://docs.bigcommerce.com/docs/start/authentication
- Store-level token is "shown once" at creation; the account exposes `client_id`, `client_secret`, `access_token`, API path. https://docs.bigcommerce.com/docs/start/authentication/api-accounts (whether a .txt download happens, the max number of accounts per store, and which user permission is required: unverified — the Help Center page did not render)
- **Single-click app OAuth (true OAuth, authorization-code grant):** BigCommerce calls the app's Auth Callback with `code`, `scope`, `context` (= `stores/{STORE_HASH}`), `account_uuid`; app POSTs `https://login.bigcommerce.com/oauth2/token` with `client_id`, `client_secret`, `code`, `scope`, `context`, `grant_type=authorization_code`, `redirect_uri`; response carries `access_token`, `scope`, `user`, `owner`, `context`, `account_uuid`; token is "semi-permanent". https://docs.bigcommerce.com/docs/integrations/apps/guide/auth
- Who may install: "Typically, only store owners and authorized users can create API accounts and access_tokens for a store. However, when an app is approved to be publicly available for additional stores to install, it can generate access_tokens on behalf of store owners." https://docs.bigcommerce.com/docs/integrations/apps/guide/auth — regular users "Cannot install or uninstall apps". https://docs.bigcommerce.com/docs/integrations/apps/guide/users
- **App visibility gates the "Connect → sign in → Allow" flow:** Draft apps only install "on stores owned by the same email address as the Developer Portal account email"; Unlisted apps install on other stores but "Only approved partners can create unlisted apps" (contact appstore@bigcommerce.com); Public = App Marketplace. https://docs.bigcommerce.com/docs/integrations/apps/guide/types — restated: "Apps that aren't approved for distribution through the App Marketplace can only be installed on stores owned by the same email address as the developer portal account's email address." https://docs.bigcommerce.com/docs/integrations/apps/guide/developer-portal
- App creation: sign in at build.bigcommerce.com → Create app → Generate Credentials (Client ID/Secret); Technical tab holds Auth/Load/Uninstall/Remove-User callback URLs, OAuth scopes, App Features. https://docs.bigcommerce.com/docs/integrations/apps/guide/developer-portal
- Load/Uninstall/Remove-user callbacks receive `signed_payload_jwt` (HS256 signed with the client secret; claims `aud`=client id, `iss`="bc", `sub`="stores/{STORE_HASH}", `user`, `owner`, `url`, `channel_id`). https://docs.bigcommerce.com/docs/integrations/apps/guide/callbacks
- "Connector apps" = merchant "manually generate store-level API credentials and enter them into the app's configuration". https://docs.bigcommerce.com/docs/integrations/apps/guide/types
- Marketplace review: partner must respond within 30 days; submission via "Publish app…" plus review fee. https://docs.bigcommerce.com/docs/integrations/apps/guide/publishing
- **Verdict:** true OAuth = YES, but a PIM that is not an approved BigCommerce partner cannot offer it to arbitrary merchants (draft app = same-email stores only). Least-friction key-paste: Settings > Store-level API accounts → V2/V3 token → paste `access_token` + store hash; test with a read on the Store Information family (`GET /stores/{hash}/v2/store` — exact path unverified here; family listed at https://docs.bigcommerce.com/docs/start/about).

### 1.2 Multi-store model
- Channels: "a place where a merchant's store sells products"; types `storefront`, `marketing`, `pos`, `marketplace`, `custom`; default channel id `1` "cannot be deleted". Sites: "tied to exactly one channel"; default site id `1000`. Settings API reads/writes config "globally and on a per-channel basis". https://docs.bigcommerce.com/docs/storefront/multi-storefront
- Channels API: channels, channel listings, channel sites, sites & routes; deleted channels restorable within 90 days, then `terminated`. https://docs.bigcommerce.com/docs/rest-management/channels
- Account-level API accounts span all stores of the account. https://docs.bigcommerce.com/docs/start/authentication
- Product channel assignments / `channel_id` on orders: not on the pages fetched — unverified.

### 1.3 API surface
- Base `https://api.bigcommerce.com/stores/{{store_hash}}/v3/`. V3 families: Catalog, Carts, Channels, Inventory, Locations, Pickup, Price Lists, Promotions, Settings, Sites & Routes, Stored Instruments, Themes, Widgets, Subscribers, Wishlists. V2 (legacy) families: Blog Posts, Coupons, Customer Groups, Gift Certificates, Orders, Order Status, Pages, Redirects, Store Content, Store Information, Time, Banners. B2B API at `https://api-b2b.bigcommerce.com`. GraphQL Admin, GraphQL Storefront, GraphQL Account APIs. https://docs.bigcommerce.com/docs/start/about
- Catalog v3: products, variants, variant options, modifiers, brands, categories, category trees, metafields. https://docs.bigcommerce.com/docs/rest-catalog — images `/v3/catalog/products/{{product_id}}/images`, videos (YouTube only), `PUT .../bulk-pricing-rules`, `POST .../modifiers`, `GET /v3/catalog/summary`, custom fields ≤250 chars, prices to 4 decimals, `POST /v3/catalog/products` creates product with variants. https://docs.bigcommerce.com/docs/store-operations/catalog
- Inventory v3: inventory items (by `variant_id`/`sku`/`product_id`), settings, quantities per location; absolute adjustments ("batched", recommended) vs relative. https://docs.bigcommerce.com/docs/rest-management/inventory
- Price Lists v3: lists, records "bulk upsert" ("only one bulk upsert at a time" per store, else 429), assignments to channels. https://docs.bigcommerce.com/docs/rest-management/price-lists
- Orders: v2 `POST/GET/PUT/DELETE /v2/orders`, `/v2/orders/{id}/shipments`, shipping addresses + quotes, `/taxes`, `/v2/order_statuses`; v3 adds `/v3/orders/{id}/transactions` and `payment_actions/refunds`. https://docs.bigcommerce.com/docs/store-operations/orders
- Customers v3: customers, addresses, attributes, attribute values, form field values, consent, metafields; customer groups v2. https://docs.bigcommerce.com/docs/rest-management/customers
- Promotions v3: condition + action model. https://docs.bigcommerce.com/docs/rest-management/promotions
- Returns API, Reports API: not present in the family list (absent). Tax / Shipping v2 / Payments families: not fetched — unverified beyond the family names above.

### 1.4 Webhooks
- Create `POST /stores/{{STORE_HASH}}/v3/hooks` with `scope`, `destination`, `is_active`, optional `headers`. Payload: `store_id`, `producer`, `scope`, `data{type,id}`, `hash` ("minimal information"). **No payload signature** — authenticate via the custom `headers` object. Destination must be HTTPS on port 443; respond `200` immediately. Retries at escalating intervals (60 s … 86,400 s); after ~48 h the hook "will be deactivated, and an email will be sent"; re-enable with `is_active=true`. https://docs.bigcommerce.com/docs/integrations/webhooks
- Event scopes (full list): `store/product/*` (created/updated/deleted, `inventory/updated`, `inventory/order/updated`, metafields, variant metafields), `store/sku/*`, `store/category/*`, `store/brand/metafield/*`, `store/order/*` (created, updated, archived, statusUpdated, message/created, refund/created, transaction/*, metafield/*), `store/shipment/*`, `store/customer/*` (+ address, payment instrument), `store/cart/*` (+ lineItem, abandoned, converted, couponApplied), `store/priceList/*` (+ record(s), assignment), `store/inventory/location/metafield/*`, `store/metafield/*`, `store/modifier/updated`, `store/option/updated`, `store/subscriber/*`, `store/app/uninstalled`, `store/information/updated`, `store/hook/deliveryException`. https://docs.bigcommerce.com/docs/integrations/webhooks/events
- GraphQL: Admin API (store- and app-level creds), Storefront API, Account API exist. https://docs.bigcommerce.com/docs/start/about — Admin GraphQL endpoint/coverage pages 404'd: unverified.

### 1.5 Rate limits / bulk
- Per 30-second window: Pro "450 / 30sec"; Plus & Standard "150 / 30sec"; Enterprise "by plan and resource"; sandboxes "by resource"; Unlimited plan no request limit. Headers `X-Rate-Limit-Time-Window-Ms`, `X-Rate-Limit-Requests-Quota`, `X-Rate-Limit-Requests-Left`, `X-Rate-Limit-Time-Reset-Ms`; 429 → wait `X-Rate-Limit-Time-Reset-Ms`. https://docs.bigcommerce.com/docs/start/best-practices/api-rate-limits
- Sandbox plans: 500,000/hr. https://docs.bigcommerce.com/docs/start/about/sandboxes
- Pagination default 50, `limit` up to 250. https://docs.bigcommerce.com/docs/start/best-practices
- Bulk: price-list record bulk upsert; inventory absolute adjustments batched (see 1.3). Catalog batch sizes per request: unverified.

### 1.6 Sandbox
- Partner Portal (https://partners.bigcommerce.com/): "Create New > Deal Registration" sandbox or "Create New > Partner Use Sandbox"; region fixed at creation; "cannot process any live transactions". https://docs.bigcommerce.com/docs/start/about/sandboxes

### 1.7 Versioning
- V2 vs V3 split as in 1.3; "V3 APIs are accessible exclusively with OAuth"; "BigCommerce no longer issues legacy API Accounts to new stores." https://docs.bigcommerce.com/docs/start/about
- Changelog lives at https://docs.bigcommerce.com/developer/changelog.md (pointer surfaced by the site; entries not fetched). Formal deprecation cadence: unverified.

## 2. Magento Open Source / Adobe Commerce (2.4.x)

### 2.1 Auth
- Three methods: token-based (Bearer), OAuth 1.0a integrations, session-based; "Third-party applications use OAuth-based authentication to access the web APIs." https://developer.adobe.com/commerce/webapi/get-started/authentication/
- Tokens: `POST /V1/integration/admin/token` and `POST /V1/integration/customer/token` with `{"username","password"}`; "By default, an admin token is valid for 4 hours, while a customer token is valid for 1 hour" (Stores > Settings > Configuration > Services > OAuth > Access Token Expiration); integration activation "generates a consumer key, consumer secret, access token, and access token secret"; using that access token as a plain Bearer requires "Allow OAuth Access Tokens to be used as standalone Bearer tokens" (disabled by default as of 2.4.4); header `Authorization: Bearer <token>`. https://developer.adobe.com/commerce/webapi/get-started/authentication/gs-authentication-token — config defaults Customer 1 h / Admin 4 h. https://experienceleague.adobe.com/en/docs/commerce-admin/config/services/oauth
- **OAuth 1.0a integration flow:** merchant creates integration at System > Extensions > Integrations (Name, Callback URL, Identity link URL, API resources tab); on "Save and Activate" Commerce POSTs `store_base_url`, `oauth_verifier`, `oauth_consumer_key`, `oauth_consumer_secret` to the callback; identity link opens a login popup; app then `POST /oauth/token/request` and `POST /oauth/token/access` with HMAC-SHA256-signed Authorization headers; "Access tokens are long-lived and will not expire unless the merchant revokes access". https://developer.adobe.com/commerce/webapi/get-started/authentication/gs-authentication-oauth
- Pre-configured integrations via a module's `config.xml` (`endpoint_url`, `identity_link_url`); "If you pre-configure the integration, the values cannot be edited from the admin panel." https://developer.adobe.com/commerce/webapi/get-started/create-integration
- **Verdict:** true OAuth = YES (1.0a) but it is **merchant-initiated from the Magento admin** ("Activate"), not from the PIM; there is no PIM-side "Connect → redirect to store → Allow". No module install is needed if the merchant creates the integration by hand. Least-friction key-paste: System > Extensions > Integrations > Add New Integration → Activate → copy Access Token (after enabling the standalone-Bearer setting on 2.4.4+), header `Authorization: Bearer`; test with `GET /rest/default/V1/store/websites` (structure per https://developer.adobe.com/commerce/webapi/get-started/gs-web-api-request; exact path not individually verified on that page).

### 2.2 Multi-store model
- Endpoint structure `<HOST>/rest/<store_code>/<service_name>/<version>/<endpoint>`; `store_code` = a store's code, `default`, or `all` ("only applies to endpoints defined in the CMS and Product modules… affects all of the merchant's stores"). https://developer.adobe.com/commerce/webapi/get-started/gs-web-api-request
- MSI: sources (physical locations), stocks "map a sales channel (currently limited to websites) to source locations", salable quantity, reservations, SourceItem. https://developer.adobe.com/commerce/webapi/rest/inventory/ — `POST/GET/PUT /V1/inventory/sources[/:sourceCode]` https://developer.adobe.com/commerce/webapi/rest/inventory/manage-sources/ ; `POST /V1/inventory/source-items`, `POST /V1/inventory/source-items-delete`, `GET /V1/inventory/source-items` (sku, source_code, quantity, status) https://developer.adobe.com/commerce/webapi/rest/inventory/manage-source-items/ ; `POST/PUT/GET/DELETE /V1/inventory/stocks[/:stockId]` with `extension_attributes.sales_channels[{type:"website",code}]` https://developer.adobe.com/commerce/webapi/rest/inventory/manage-stocks/

### 2.3 API surface
- REST `V1` families (products, categories, attributes, configurable/bundle, stockItems + MSI, orders/invoices/shipments/creditmemos, customers/groups, salesRules/coupons, cmsPage/cmsBlock, taxRates/taxRules/taxClasses, carts, store websites/storeGroups/storeViews/storeConfigs, bulk status, modules): the quick reference delegates to the generated reference at https://adobe-commerce.redoc.ly (index page https://developer.adobe.com/commerce/webapi/rest/quick-reference/). Individual paths not verified in this session beyond MSI (2.2) and search/bulk below. RMA (`/V1/returns`) is Adobe Commerce-only — unverified.
- Search: `searchCriteria[filter_groups][i][filters][j][field|value|condition_type]`, `sortOrders`, `pageSize`, `currentPage`; condition types eq, finset, from, gt, gteq, in, like, lt, lteq, moreq, neq, nfinset, nin, nlike, notnull, null, to; "You can only search top-level attributes"; no OR across filter_groups. https://developer.adobe.com/commerce/webapi/rest/use-rest/performing-searches
- Bulk: prefix `/async/bulk` before `/V1` (e.g. `POST /rest/<store>/async/bulk/V1/products`), payload = array of request bodies, response `bulk_uuid` + `request_items[]` + `errors`; needs RabbitMQ and the `async.operations.all` consumer; GET not supported. https://developer.adobe.com/commerce/webapi/rest/use-rest/bulk-endpoints/ (status endpoint page 404'd — unverified)
- GraphQL: `https://<commerce-server>/graphql` (PaaS) / `https://<region>-<environment>.api.commerce.adobe.com/<tenantId>/graphql` (SaaS); positioned for "headless storefronts and sophisticated mobile applications". https://developer.adobe.com/commerce/webapi/graphql/ — admin/catalog write mutations: not documented (treat as absent).

### 2.4 Webhooks
- **Open Source has no native outbound webhooks.** Adobe I/O Events for Commerce requires "Adobe Commerce 2.4.4 or higher"; "Magento Open Source is not supported"; package `magento/commerce-eventing`; `bin/magento events:generate:module`. https://developer.adobe.com/commerce/extensibility/events/installation/
- Adobe Commerce Webhooks = synchronous calls on events; configured in a module's `etc/webhooks.xml` or `app/etc/webhooks.xml`; SaaS: Admin System > Webhooks; package `magento/commerce-webhooks`, `bin/magento webhooks:generate:module`. https://developer.adobe.com/commerce/extensibility/webhooks/ and https://developer.adobe.com/commerce/extensibility/webhooks/installation/ — edition gating for webhooks and I/O Events signature scheme/retries: unverified.
- Hooks in-process: PHP plugins/observers (general; not fetched).
- GraphQL: see 2.3 (storefront-only).

### 2.5 Rate limits / bulk
- No request-rate limiter documented. Web API Input Limits (Stores > Configuration > Services > Web API Input Limits): complex arrays "up to 20 items", default page size 20, "maximum value is 300"; separate GraphQL Input Limits section. https://developer.adobe.com/commerce/webapi/get-started/api-security
- Bulk: see 2.3.

### 2.6 Sandbox
- No hosted sandbox: install via Composer (recommended) or GitHub clone. https://experienceleague.adobe.com/en/docs/commerce-operations/installation-guide/overview — sample data `magento sampledata:deploy` ("You cannot uninstall sample data"). https://experienceleague.adobe.com/en/docs/commerce-operations/installation-guide/next-steps/sample-data/overview — Cloud integration environments: unverified.

### 2.7 Versioning
- REST version segment `V1` only. Lifecycle: "three-year standard support window from the General Availability (GA) date" + 1 year extended: 2.4.4 GA 2022-04-12 → 2025-04-12 (ext 2026-04-14); 2.4.5 2022-08-09 → 2025-08-12; 2.4.6 2023-03-14 → 2026-08-11 (ext 2027-08-31); 2.4.7 2024-04-09 → 2027-05-31 (ext 2028-05-31); 2.4.8 2025-04-08 → 2028-05-31; 2.4.9 2026-05-12 → 2029-05-31. https://experienceleague.adobe.com/en/docs/commerce-operations/release/planning/lifecycle-policy and https://experienceleague.adobe.com/en/docs/commerce-operations/release/versions
- Cadence: "A full patch for the Adobe Commerce 2.4.x LTS release line… is released annually (May)"; security patches "at minimum… annually". https://experienceleague.adobe.com/en/docs/commerce-operations/release/planning/schedule
- GraphQL schema: additive (no version segment) — inferred from 2.3; unverified as policy.

## 3. Wix (Wix Stores / Wix eCommerce)

### 3.1 Auth
- "third-party apps integrating with Wix APIs must authenticate using the OAuth protocol"; "API keys… aren't available for use in third-party Wix apps." https://dev.wix.com/docs/build-apps/develop-your-app/access/authentication/about-authentication.md
- **OAuth = client credentials per app instance:** `POST https://www.wixapis.com/oauth2/token` `{grant_type:"client_credentials", client_id:<APP_ID>, client_secret:<APP_SECRET>, instance_id}`; "The token is valid for 4 hours"; header `Authorization: <ACCESS_TOKEN>`. App ID/secret from the app dashboard OAuth page; `instanceId` from the App Instance Installed webhook, any webhook payload, service-plugin metadata or the app-instance query param. https://dev.wix.com/docs/build-apps/develop-your-app/access/authentication/authenticate-using-oauth.md — "Custom authentication" (authorization-code + refresh tokens, `https://www.wixapis.com/oauth/access`) is "no longer available for new apps". https://dev.wix.com/docs/build-apps/develop-your-app/access/authentication/about-oauth.md
- **Install = the consent step:** standard install flow (App Market / dashboard / editor / shared link) — "Wix prompts the Wix user to select the intended site and grant permissions"; external install flow lets you start from your own site and get redirected back. https://dev.wix.com/docs/build-apps/launch-your-app/app-distribution/install-your-app/about-app-installation.md — installation URL `https://www.wix.com/app-installer?appId=…&postInstallationUrl=…&shareUrlId=…` (shareUrlId required for unlisted apps); redirect returns `appId`, `tenantId`, `instanceId`, `signedInstance` ("Verify signedInstance before you trust instanceId"). https://dev.wix.com/docs/build-apps/launch-your-app/app-distribution/install-your-app/about-the-external-install-flow.md
- **Unlisted apps need no review:** "the app is considered unlisted, and there's no need to go through the submission process"; create a Share Install Link from the app dashboard. https://dev.wix.com/docs/build-apps/launch-your-app/app-distribution/install-your-app/share-an-app-install-link.md — App Market review is "an automated AI process… from submission to published in minutes". https://dev.wix.com/docs/build-apps/launch-your-app/app-distribution/about-app-distribution.md
- App Instance Installed webhook payload: `appId`, `originInstanceId`; metadata `instanceId`, `accountInfo.siteId`. https://dev.wix.com/docs/rest/app-management/app-instance/app-instance-installed.md
- **API keys (own-account path):** "Only account owners and co-owners can create API keys" at https://manage.wix.com/account/api-keys; key scoped to all sites or specific sites; site ID via Query Sites or the dashboard URL after `/dashboard/`. https://dev.wix.com/docs/api-reference/articles/authentication/api-keys/about-api-keys.md — headers `Authorization: <API_KEY>` plus exactly one of `wix-site-id` / `wix-account-id`; example test call `POST https://www.wixapis.com/stores/v3/products/query`. https://dev.wix.com/docs/api-reference/articles/authentication/api-keys/make-api-calls-with-an-api-key.md — key string format/prefix: unverified.
- **Verdict:** true OAuth "Connect → sign in → Allow" = YES for any third party (unlisted app + share install link / app-installer URL, no review). Key-paste fallback = API key + site ID.

### 3.2 Multi-store model
- One Wix site hosts one Wix Stores instance; an account holds many sites/projects — Sites APIs (Projects, Sites/Query Sites, Site Actions, Site Folders). https://dev.wix.com/docs/api-reference/account-level/sites/introduction.md
- Multi-location inventory (Catalog V3): "Each inventory item is uniquely identified by its variantId and locationId"; default location auto-created; Stores Locations V3 read-only; create locations via Locations API with `"INVENTORY"` in `locationTypes`. https://dev.wix.com/docs/api-reference/business-solutions/stores/catalog-v3/about-inventory-management.md — Locations API. https://dev.wix.com/docs/api-reference/business-management/locations/introduction.md
- Multilingual API exists. https://dev.wix.com/docs/api-reference/business-management/multilingual.md

### 3.3 API surface
- **Stores Catalog V3:** Products V3 (CRUD, Query/Search/Count, Bulk Create/Update/Delete, Create/Update Product With Inventory, events Product Created/Updated/Deleted), Inventory Items V3 (CRUD, bulk create/update/delete, bulk increment/decrement incl. by variant+location, events), Stores Locations V3, Brands V3, Ribbons V3, Info Sections V3, Customizations V3 (options/modifiers), Read-Only Variants V3 ("up to 1,000 variants per request"), Categories (tree, bulk add/remove items), Promotions V3. Menu: https://dev.wix.com/docs/api-reference/business-solutions/stores.md ; overview https://dev.wix.com/docs/api-reference/business-solutions/stores/catalog-v3/introduction.md ; pricing fields `actualPrice`, `compareAtPrice`, `cost`, `handle` for re-import. https://dev.wix.com/docs/api-reference/business-solutions/stores/catalog-v3/products-v3/introduction.md
- **Catalog V1:** Catalog (Create/Update/Query Products, collections, media, variants, bulk property updates) + Inventory ("up to 300 variants… in a single call"). https://dev.wix.com/docs/api-reference/business-solutions/stores/catalog-v1/inventory/introduction.md
- **eCommerce platform:** Cart, Checkout, Abandoned Checkout, Discount Rules, Recommendations, Orders, Order Transactions, Order Fulfillments; service plugins for additional fees, shipping rates, validations, payments, catalog. https://dev.wix.com/docs/api-reference/business-solutions/e-commerce/introduction.md — Orders section: Orders, Draft Orders, Order Billing, Order Transactions, Order Payment Requests, Order Invoices, Order Fulfillments, Orders Settings. https://dev.wix.com/docs/api-reference/business-solutions/e-commerce/orders/introduction.md — Orders API: get/search/update/cancel/archive/create (`channelInfo.type`, `OTHER_PLATFORM`); events approved/updated/canceled. https://dev.wix.com/docs/api-reference/business-solutions/e-commerce/orders/orders/introduction.md — Fulfillments: up to 300 line items per fulfillment, bulk ≤100 orders, statuses Pending/Accepted/Ready/In_Delivery/Fulfilled. https://dev.wix.com/docs/api-reference/business-solutions/e-commerce/orders/order-fulfillments/introduction.md
- CRM: Contacts (+ V5), Labels, Extended Fields, Members, Loyalty (incl. Coupons under Rewards), Marketing consent. https://dev.wix.com/docs/api-reference/crm.md — Business Management: Analytics, Locations, Marketing, Multilingual, Payments, Site Properties, etc. https://dev.wix.com/docs/api-reference/business-management.md
- Not located in the fetched menus: stand-alone Coupons API, Media Manager, Tax, Shipping-rate reads, Returns — unverified.

### 3.4 Webhooks
- Configured per app in the app dashboard; payload is a signed JWT — verify with the app public key from the Webhooks page; every event carries `instanceId`, `eventType`; must return 200 within 1250 ms; up to 12 retries (1 min, 10 min, 1 h, 2 h ×3, 4 h ×3, 8 h ×2, 12 h); at-least-once, possibly out of order; Logs tab; webhooks are versioned with the app. https://dev.wix.com/docs/build-apps/develop-your-app/api-integrations/events-and-webhooks/about-webhooks.md
- Each catalog version has its own events; subscribe to both V1 and V3. https://dev.wix.com/docs/api-reference/business-solutions/stores/catalog-versioning/introduction.md
- GraphQL: "Developer Preview"; `POST https://www.wixapis.com/graphql`, `Authorization: <API_KEY or Bearer <ACCESS_TOKEN>>`, "query and mutate Wix data". https://dev.wix.com/docs/api-reference/articles/work-with-wix-apis/platform/about-the-wix-graph-ql-api.md

### 3.5 Rate limits / bulk
- 429: "wait a minute and then retry"; 409 revision conflicts on updates. https://dev.wix.com/docs/api-reference/articles/work-with-wix-apis/troubleshooting/troubleshooting.md — numeric quotas: unverified.
- Bulk Create Products: `POST https://www.wixapis.com/stores/v3/bulk/products/create`, "up to 100 products", ≤1000 variants. https://dev.wix.com/docs/api-reference/business-solutions/stores/catalog-v3/products-v3/bulk-create-products.md — other bulk sizes in 3.3.

### 3.6 Sandbox

- Release policy: major "Once a year", minor "Every first Monday of the month", patch on demand; phases maintained → extended support → security-only → EOL; latest 6.7.13.1, 6.6 extended, 6.5 security. https://developer.shopware.com/release-notes/ — 6.6.0.0 2024-03-18 (PHP 8.2 min, Stock API default). https://developer.shopware.com/release-notes/6.6/6.6.0.0.html — 6.7.0.0 2025-06-17. https://developer.shopware.com/release-notes/6.7/6.7.0.0.html — 6.8 "planned for 2027 instead of 2026"; 6.6 extended support "until 6.8 becomes available". https://www.shopware.com/en/news/next-major-version-6-8-planned-for-2027/
