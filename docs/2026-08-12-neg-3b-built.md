## 1 · 🔴 The routing is proven

`kolchoz carrere` in `IT-AIRMESH-SP-Competitor-Phrase`, paused through the **real path** —
`updateAdTargetWithSync` → `OutboundSyncQueue` → the worker's dispatch → `PUT /sp/negativeKeywords`
— and then read back from Amazon's own `/sp/negativeKeywords/list`:

```
before    {"keywordId":"217136428943111","matchType":"NEGATIVE_EXACT","state":"ENABLED"}
after     {"keywordId":"217136428943111","matchType":"NEGATIVE_EXACT","state":"PAUSED"}
restored  {"keywordId":"217136428943111","matchType":"NEGATIVE_EXACT","state":"ENABLED"}
```

A 200 from a correctly-shaped call would not have been proof. **Amazon reflecting the state is.**

This is the first state ever pushed to a negative in this account. Before the NEG.3 fix it would
have gone to `/sp/keywords`, been answered `entityNotFoundError` at `$.keywords[0].keywordId`, and
orphaned the row permanently. `orphanedAt` held at **0** before, during and after, and the subject
is back exactly where it started.

**The operator's subject rule is better than the one I proposed, and I adopted it.** The allowlist
makes "safe because the campaign is inert" impossible — **0 negatives are both allowlisted and in a
non-ENABLED campaign** — so the safety property is a **dead term** instead: 0 impressions and 0
orders in 120 days, in an already-allowlisted campaign, with 15 other negations left blocking it.
No configuration change, nothing to revert, nothing to forget.

I re-derived the eligible set rather than trusting the brief: **241, exactly as stated**. One
correction: **`giacca moto donna`, offered as an alternate, does not qualify** — 11,711 impressions

## 2 · Pause vs archive — unresolved, and therefore unchanged

NEG.3 established that Amazon **accepts** `enabled | paused | archived` for a negative keyword, and
this session proved it accepts a pause in practice. That is state acceptance, not semantics.

**The question is whether a PAUSED negative still excludes the term.** I could not answer it:

- Amazon's own negative-targeting and bulksheet pages are SPA-rendered and return no content to a
  fetch; four searches over Amazon's docs, the Python SDK and the vendor literature turned up
  definitions of `paused` only for **positive** entities ("ads will not serve"), which does not
  transfer — for an exclusion, "not serving" is not a meaning.
- The one empirical test that would settle it is pausing a negative on a term with live traffic and
  watching for impressions. That is a live experiment on a live term, which §4 forbids.

**So, per §5.3: the docs are silent, and I changed nothing.** Archive remains the retirement path,
Pause is not offered in the UI, and the vocabulary is untouched.

🔴 **`NegativeTargetsTab.tsx:90` already offers Pause on a negative**, and has since it was written.
If pause does *not* stop the exclusion, that button is a lie. Recorded in the locks doc §4 rather
than fixed — it is another page's file.

**What would settle it**, for whoever picks this up: Amazon Ads support, or a deliberate experiment
on a term you are willing to have unblocked for a day. The prize is real — if pause stops the
exclusion, the retirement path becomes reversible, which is the property `ads-graduation.ts`'s
ceiling actually cares about.

## 3 · The removal path

`NegRemoval` fills the write seam `slot-contract.ts` declared on day one. The client change is
**four lines** and no restructuring.

**Entry points**: the grid row (`onRowAction`) and the drawer, one button per negation. **Bulk is
issued from the drawer** against N explicit negation ids — never from a selection bar over a term
row, because a term is not an Amazon object. `selectionActions` stays deliberately null.

**Three copy variants, three different facts**, and the labels differ on the button itself — for
`giacca moto`, 70 rows read **Archive** and 1 read **Remove**:

| | copy |
|---|---|
| at Amazon | *"Archiving at Amazon cannot be undone. There is no un-archive — re-negating this term later creates a new negative."* |
| local-only | *"Amazon has never confirmed this negative. Removing it deletes our record; nothing changes at Amazon."* |
| already ARCHIVED | **no action**, plus: we do not know *when* — `updatedAt` is the last ingest tick and all 62 share one |

Every number comes from `term-context`, the single owner. The write count is **`overlapRows`**,
never `overlap.length`. The remainder sentence appears verbatim. Bulk says *"This is 16 separate
writes, each with its own outcome."*

**Delivery is rendered distinctly.** The outcome report counts five classes separately and a
retirement reads *"queued for Amazon"* with the note that **the write gate has not run yet** — it
runs in the worker and refuses 1,014 of 2,058 negatives outright.

## 5 · The defect only clicking found

**The confirm dialog never opened.** The URL gained `?retire=<id>` and nothing appeared.

`NegRemoval` read `window.location.search` at render time. Under the App Router's soft navigation
that is not a reactive source: `router.replace` updates the URL, the component re-renders because
its props changed, and it reads a `window.location` that has not caught up. `useSearchParams` is the
source that tracks it — the hook the client and the drawer already use.

That is now five sections, five defects that a green pre-push and a passing script did not catch:
four in NEG.1, a fifth empty state in NEG.2, delivery honesty in NEG.3, and this.

## 6 · Open

1. **Pause semantics** (§2) — the one question this session could not answer, and the one with the
   largest payoff.
2. **`NegativeTargetsTab.tsx:90`** offers Pause on a negative today; if §2 resolves against pause,
   that control is a lie. Another page's file.
3. **The `campaign_allowlist` shape is a policy nobody has stated.** It permits retirement in all
   82 allowlisted campaigns — which are exactly the ENABLED ones — and refuses it in the 138 that
   are not. Nobody chose that as a *negatives* policy; it is the bid-write allowlist being reused.
   Worth an explicit decision before bulk is used in anger.
4. **Bulk is built but unexercised at scale.** The largest real term is 70 rows; nothing bigger than
   16 has been put through the dialog, and only in preview. The first genuine bulk run should be
   watched.
5. **`updateAdTargetWithSync` writes the local row before the gate runs**, so a refused archive
   leaves `status: ARCHIVED` locally until an ingest heals it. `delivery` makes that legible; it
   does not fix it.
