# Product sheet editing — investigation report and plan (2026-09-30)

Branch `fix/product-sheet-editing` (from `origin/main` `df98af093`). Investigation only; nothing is built.
Detail per perspective: `.local-pse/reports/1-…7-*.md` in the worktree (local, not committed).

## Summary

- **Why dropdowns "often" fail.** Three causes combine:
  1. No editor works until the formula data arrives. On production that is 5 calls one after another, so every cell
     is blocked for the first ~6–10 s after the page opens.
  2. In every dropdown, Enter and Tab close the list with the old value: the grid takes the key.
     Only a mouse click on a choice works.
  3. Dropdowns that the channel marks "open" (Brand, Material, Style, 13 eBay IT fields, 25 Amazon fields per market)
     are closed lists in the editor, so your own value cannot be typed.
- **Other things you cannot edit.** Amazon variations with no product type have almost every cell locked
  (production: REGAL, 16 rows, 2,816 cells). Motovento on eBay DE has no item-specific columns at all (no field list).
  Formulas cannot be saved by a user in two businesses. Typing into a selected dropdown cell loses the first letter.
- **Danger today.** In the Amazon product-type cell, Enter right after opening replaces the type with
  "3D_PRINTABLE_DESIGNS" and saves it (production's first page of 1,875 types has no OUTERWEAR). Until P0 ships,
  choose the type with the mouse or press Escape.
- **Values that save but never reach eBay.** A listing-level item specific edited on a variation row, and every
  list-valued item specific, is stored but not sent. Colour/gender that differ per variation are sent as the first
  variation's value.
- **Full-control gaps.** The source of a value is hidden on eBay, Amazon and Shopify. Reset takes 3 steps (none on the
  Master sheet). There is no bulk reset. One off-list value gets 8 different answers on 8 paths, and some block when
  the channel would accept the value.
- **Slow.** 6 calls wait on each other before the first row. Each API call costs 45–135 database statements (~6 ms each
  on production). Each edit reloads the whole sheet (6 calls, ~6,000 React renders). Payloads are 10–20× their data.
- **Why tests missed it.** Every sheet test calls handlers directly or stops at "the editor opened". CI never opens
  the sheet.

## 2. Plan — one PR per phase, each with its own tests and before/after numbers

### P0 — everything you cannot edit or select
1. Editors never wait for formulas. Plain cells open at once; only a cell that holds a formula (or starts with `=`) shows
   its formula state. Formula batches run in parallel (one call where possible). A paste made while formulas load is
   kept and retried, never dropped.
2. Every popup list editor owns Enter, Tab, arrows and Escape. Enter/Tab commit the highlighted choice. Inside
   option-list and measure pop-ups the inner controls are reachable by keyboard. The search box stays on top.
3. One click on the chevron opens the list.
4. Typing into a selected cell keeps the first character in every editor.
5. Open lists take a typed value ("Use 'Xavia Racing'"), and every list has "Clear". A stored value that is not in the
   list is shown, highlighted as current, and can be kept.
6. A category/product-type editor opens on the current value; Enter without a choice keeps it.
7. An Amazon variation without its own product type uses the parent's.
8. A missing channel field list is fetched once (read-only, through the gateway) when the sheet opens; if that fails,
   the sheet says so and offers "Load eBay fields".
9. The formula writer forwards the business header, so formulas save for a user in two businesses.

Tests: the unit key-ownership test over every popup editor; Playwright commits by keyboard, mouse and paste for each
editor kind on eBay IT, Amazon DE, Master; an API test for the product-type fallback and the schema fetch on miss.
Measure before/after: time until a select lists its options on production; commits by Enter that write.

### P1 — the full-control rule
1. One verdict function for every path (editor, paste, formula, bulk-save, import, publish): store and warn while
   editing; block only at publish, only when the channel itself would reject, with the exact reason. Only the bad
   cell is refused, never the whole product.
2. Source visible at rest on every channel (same mark as Master/Etsy), and correct: a legacy listing title is shown
   as "Listing value", with "Follow Master" offered.
3. Reset: one click in the cell menu on every sheet (Master too), "Reset selection", "Set column…"/"Reset column";
   Delete asks "clear or reset"; a pasted column asks once.
4. eBay: a listing-level item specific edited on any row is saved where eBay reads it, and the row shows that it
   applies to all variations; list values are sent; per-variant non-axis values are warned about at publish
   (eBay takes one value); stored values are never hidden; the 65-character value limit warns while editing;
   single/multi comes from the full schema row.
5. Hidden or missing fields become reachable: stored specifics with no column, family attributes placed on a
   channel the business has no account for (#14), "All attributes" names its scope (#15), eBay item-location city and
   postal code (#30), the family row on per-variant columns.
6. Formulas accept open-list values and list results (today `="Xavia Racing"` on Brand is refused).

### P2 — speed
1. Load: csrf/me no longer serial and not blocking the page; product, destination and sheet start together;
   other studio tabs load only when opened.
2. Database: one transaction per request instead of BEGIN/SET ROLE/COMMIT per query; session and permissions read
   once per request. *(Touches every API call — highest risk item; own commit, full API + real-PG suite.)*
3. Edit: patch the edited rows from the save answer — no full sheet, readiness and reference reload.
4. Payload: `contentAddress` and provenance per column, not per cell; readiness for the open coordinate only.
5. Bulk save: batch the rows (target ≤ 15 statements per row); 105 rows ≤ 3 s.

Budgets (production, warm): editable = first row ≤ 2.5 s; ≤ 15 API calls on load; sheet ≤ 200 B per cell;
readiness ≤ 50 KB on a channel scope; ≤ 10 statements for a trivial GET; edit → saved ≤ 0.8 s p95 with ≤ 2 calls and
≤ 60 renders; 105-row paste ≤ 3 s.

### P3 — guardrails
1. Unit key-ownership test for every popup editor (runs in the existing web job, < 1 s).
2. Playwright commit sweep in a new CI job (3 shards, production build, seeded fixture — never production): every
   column of every scope, committed by keyboard, mouse and paste; asserts the exact `bulk-save` body and the stored value.
3. Speed budgets in CI: request counts and waterfall depth exact; bytes ±3%; statement counts per route; renders per
   edit; timings report-only for 2 weeks, then enforced.
4. Static ratchet `scripts/check-sheet-editor-coverage.mjs`: a new column kind or editor without an editor test fails.

## 4a. Channel verify / dry-run and account limits
- **Not run yet.** The app has no verify-only call for an existing listing. eBay `VerifyAddFixedPriceItem` runs only
  inside submit and only for a new item; Amazon `VALIDATION_PREVIEW` runs inside submit or through
  `GET /preflight?live=1`, which checks a different payload and writes Nexus issue rows. Shopify and Etsy have none.
- **Closest safe check:** the publish review (`POST …/studio-publication/preview`, then `…/selection`). Code proof
  (report 5 §4): it only reads from eBay/Amazon (GetItem, inventory GETs, getListingsItem) and writes one Nexus
  `BulkOperation` row with status PREVIEW. It never calls `/submit`. Not for Shopify (its preview saves content).
- **Account limits:** the app cannot read eBay selling limits, Amazon account health/restrictions, the Shopify plan
  or Etsy shop state. They must be checked by hand in Seller Hub and Account Health.
- Read-only production facts already gathered: eBay IT field list for category 177104 fetched 2026-09-29 20:22 UTC;
  season list is `Estate / Inverno / Tutte le stagione` (strict); Xavia's live GALE eBay IT listing group holds only
  `Marca = Xavia`.
