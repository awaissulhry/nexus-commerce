### 1.3 Root causes in the code

**B1 — Languages snaps back (S1).**
- Picking a non-language view while languages are on calls `languageView.set(null)` and parks the view in a ref
  (`useSheetColumns.ts:233-243`).
- The URL change remounts the sheet, so the parked view is lost.
- Landing runs again. The saved working layout holds `@lang` columns. `matchesSelection` passes when no language is
  selected (`:324`), and `:337-338` turns languages back on.
- Result: you cannot leave Languages mode.

**B2 — No "select all" in Customise (the Owner's shared-scope report).**
- The dialog's All/None only render when `quickPicks` exist (`PreferencesModal.tsx:564`). The sheet passes none
  (`useSheetPreferences.ts:78-91`).
- "Select columns for bulk actions" works only on columns already in view (`PreferencesModal.tsx:756-771`). In
  Languages mode those are the language columns only, so "Show" is disabled.
- Languages mode also makes one group per text field, so there are many more groups to tick one by one.

**B3 — The last view is never remembered.**
- Picking a view or a built-in view writes nothing. `activate()` only calls `markDirty()`, which saves widths, pins
  and sort to the browser (`useSheetColumns.ts:27, 229`).
- The server "Current layout" is written only by Customise Save / Save as view / Update (`:421-456`).
- Landing order: product-type default > working layout > my default > All (`:325-350`). A type default beats your
  last layout on every reload.
- Named views are stored per channel (`product-edit:views:<CH>`), but the working layout per market
  (`product-edit:layout:<CH>:<MKT>`). So a layout used on IT does not open on DE.
- Customise **Save** on a named view turns its name into "Custom (N)" (`:451`).
- The dialog forgets its search text and open/closed groups on every open (`PreferencesModal.tsx:996-999, 440-442`).

**B4 — Progress bars do not refresh.**
- The Shared-product bar comes with the sheet rows and refreshes after a save.
- The channel·market bars come from `GET /api/products/:id/readiness` (`contracts.tsx:366-491`). They refetch only
  on a live event (`useLiveRefresh`, `:508-543`).
- ⋯ → Reload reloads the rows only, not the bars (`useMasterSheetAdapter.tsx:221-232`,
  `useChannelSheetAdapter.tsx:315-322`).
- An edit on a variant row is ignored: the event carries the child's id (`contracts.tsx:535`).
- On error there is no Retry.
- The server side is fine: a save rebuilds the index at once for 1–2 families, and bigger edits within a minute
  (`readiness-index.service.ts:78-103`, `readiness-pending.job.ts`). The page just never asks again.
- Also: progress columns cannot really be hidden. Customise lists them as tickable, but `activate()` always adds them
  back, and their pins are dropped (`views.ts:133-137`, `columnLayout.ts:31-43`, `useSheetColumns.ts:226`).

**B5 — The side menu keeps old languages.**
The channel items in the left drawer switch scope without clearing `locales` (`navigationHref.ts:7-9`), unlike the
Editing menu (`contracts.tsx:838-849`). This can land on the "Choose supported content languages" error.

**B6 — Dead code.** `sheet/channel/viewChips.ts` `buildChannelChips` / `rowsForChip` are used only by tests.

## 2. The design

One rule: **each question has ONE control, in ONE place.**

| Question | Control | Where |
|---|---|---|
| What do I edit? | Scope (+ market, account on a channel) | Editing bar |
| In which languages? | Languages | Editing bar |
| Which columns? | Columns (the views menu) | Sheet toolbar |
| Which rows? | Rows (the filter menu) | Sheet toolbar |

### 2.1 New layout

```
EDITING [● Shared product ▾]  [Languages: Italian +8 ▾]
21 rows · 20 variants  [Find a SKU…]  [Columns: All attributes · 215 ▾]  [Rows: All rows ▾]
                                         [Compact|Cozy|Spacious]  [Customise]  [Export]  [Import]  [⋯]

With a row filter on:
21 rows · 20 variants  [Find a SKU…]  [Columns: All attributes · 215 ▾]  [Rows: Missing required · 21 ✕]
```

On a channel scope the Editing bar keeps its Market (and Account) menus, as today.

### 2.2 Languages — one control

- The `Languages` menu is the only language control. The **Languages chip goes away.**
- One language ticked → normal columns in that language.
- Two or more ticked → text fields show side by side, one column per language.
- Choosing a view never changes the languages. Choosing languages never changes the view.
- The languages are remembered per scope, like the view (§2.5). A link that names languages still wins.
- Views store plain column keys. Old views and layouts that stored `name@de` keys are read as `name` (no database
  change).

### 2.3 Columns — one menu

- The trigger says the view name and its attribute count: `Columns: All attributes · 215`.
- The count is attributes only. Progress and identity columns are not counted, here or in Customise.
- Menu:
  - **Built-in:** All attributes · Required · Has gaps · Essentials · Family facts · Text fields (was "Localized
    content").
  - **My views**, **Team views** (as today).
  - Save as view… · Customise columns…
- The **Required chip goes away**; Required is a normal menu item.

### 2.4 Rows — one menu

- The trigger says what is on: `Rows: All rows`, or `Rows: Missing required · 21 ✕`. No more "Filters 5".
- Items: All rows · Missing required · Invalid values · Warnings · Mapping errors (channel only) · Needs translation ·
  Out of date · AI drafts. Each with its count and its one-line explanation (as today).
- A row filter also narrows the columns to the ones with matches (as today), but now a visible switch at the bottom
  of the menu says so: **"Only columns with matches"** (see decision D1).
- A row filter is temporary. It is not saved in a view. It clears when you change scope (as today).

### 2.5 Views remember — always

- One memory per user per scope (Shared, Amazon, eBay, Shopify), on the server. **Not per market.**
- The last view you pick (built-in or your own) is saved at once. Reload, reopen, or change market → it opens.
- A product-type default is used only when you have never picked a view for that scope (see decision D2).
- Customise **Save** on your own view keeps its name. On a built-in view it saves "My layout".
- Widths and sort stay in the browser, as today.

### 2.6 Customise columns

- It shows which view you change: "Customise columns · <view>".
- **Select all** and **Clear all** at the top of the list. With search text they act on the matches only
  ("Select all 12 matches").
- Attributes are listed once, not once per language. Languages come from the Languages menu.
- It opens as you left it: search text, open and closed groups.
- Progress columns can really be hidden, shown and pinned, and stay that way.

### 2.7 Progress bars

- ⋯ → **Reload** reloads the rows AND the bars.
- After every saved edit (also on variant rows) the bars refresh by themselves, about one second later.
- If the bars cannot load, the column says so and offers **Retry**.
- The Progress column menu has **Refresh progress** and shows when it was last read.

### 2.8 Smaller fixes

- Changing view or languages keeps the old grid on screen while the new columns load. No blank grid.
- The left-drawer channel links clear languages like the Editing menu (B5).
- Status pills (Setup incomplete / Cached requirements / Requirements) stay, one slot, shown only when something needs
  attention.
- Remove the dead chip code (B6).
- Market on Shared: I check what it changes there. If it changes what you see, the bar shows it. If not, it stays
  hidden and no longer changes the layout (§2.5 already removes the per-market layout).

## 3. Decisions for the Owner

**D1 — A row filter and the columns.**
- A (recommended): a filter also hides columns with no matches, as today, with the visible switch "Only columns with
  matches" (on by default). You see why columns went away, and you can turn it off.
- B: a filter hides rows only. Columns stay as the view shows them. The problem cells are coloured.

**D2 — Last pick vs product-type default.**
- A (recommended): the last view you picked always opens. A product-type default is used only the first time. This is
  what "it should remember always" says. It changes the order approved on 2026-09-26 (type default first).
- B: keep the type default first. Your last pick opens only for types with no default.
