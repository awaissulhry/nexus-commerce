## What was measured before the change

Measured on master · IT, XAVIA AIREON (41 rows), 1512 px wide:
- **195 of 336 rendered cells (58%)** drew the em dash.
- Every one of them came from `EmptyValue`.
- The one glyph had three different meanings:

| meaning | cells | example |
|---|---:|---|
| empty, and you can type here | 83 | Manufacturer, Material, Colour |
| follows the parent, and the parent is empty | 84 | Description, Bullet points, Search keywords (🔗 —) |
| does not apply to this row | 28 | Variation theme on a child, Colour on the parent |

Views before the change:

- The sheet menu hid New view…, Rename… and Duplicate… (`manage="minimal"`, CH.1).

## Phase 1 — built on this branch

### 1. Empty cells (option A)

The sheet is an editing surface. Its empty cell means "no value", not "not measured". So:

| state | before | after |
|---|---|---|
| empty, editable | `—` | blank; a screen reader hears "No value" |
| does not apply to this row | `—` on a locked cell | blank, with a light diagonal hatch; the tooltip still says why |
| follows an empty parent | 🔗 `—` | 🔗 only, in the muted text tone instead of the link blue |
| required and empty | `⚠ required` | unchanged |

- **Opt-in, per grid.** A new `NexusGrid` prop, `emptyCells="blank"`. It works through a context (`GridEmptyCellsContext`) that `EmptyValue` and the variation-theme child cell read, and through `data-empty-cells` on the engine's own wrapper.
- Every other grid keeps the dash. That includes the import diff, the variants grid and every number grid, because there "no data" and a measured 0 must stay different.
- A measured zero keeps its dash and its title in every mode.
- **The hatch is the DS class `nds-cell-na`.**
  - Master adds it where `columnApplies` says no.
  - The variation-theme column adds it on child rows ("Set on the parent").
  - The channel scope has no such concept (its locks are about write access), so it gets blanks only.

### 2. Views — the full menu (step 1)

- `SheetToolbar` uses `GridViewsMenu manage="full"`. This reverses CH.1's `minimal`.
- It is the same on master and on every channel scope.
- It adds New view…, Rename… and Duplicate…, next to Save as view…, Update, Make default and Delete.
- **New view…** opens the one Customise dialog with the view-name field already open.
  - The DS `PreferencesModal` gains `viewSave.startNaming`. It is opt-in, and no other caller changes.

### 3. Views — a view keeps everything (step 2)

- A saved view (schema 3) gains three optional fields:
  - `columnWidths` (column key → px)
  - `sort` (ordered `{ colId, sort }`)
  - `density` (`compact | cozy | spacious`)
- Older views read unchanged. A view without a field leaves that part of the screen alone.
- **Row height is new on the sheet.**
  - The toolbar gets the same `GridDensityToggle` the products page uses, on every scope.
  - Your last choice is remembered in this browser.
  - A view that carries a density applies it.
- **Saving and updating a named view** stores the widths, sort and row height on screen.
- **Applying a view** from the menu, or landing on the default view, restores them.
- The personal working layout is unchanged. Widths and sort still follow the browser there.
- **The API** (`validateSavedViewPayload`) checks the three fields.
  - Widths: 20–2000 px, at most 5000 keys.
  - Sort: at most 50 entries, `asc` or `desc` only.
  - Density: one of the three names.

### 4. Fixes the Owner asked for during the session

- **Filters opened under the table.** The panel sat inside the toolbar, which clips anything that sticks out of it, so the panel was invisible.
  - The DS `GridToolbarFold` panel is now portaled and placed by `usePopoverPosition`.
- **Filters are a dropdown, not chips** (Owner: "better to actually keep a dropdown").
  - It is one DS `Menu`: "All rows" first, then one row per filter.
  - Each row shows its count and its detail line. The active filter is ticked.
  - The trigger still reads `Filters N`, or `Filters · <label>` when a filter is on.
- **Footer `?` misaligned.** The strip kept 128 px free for the Ask AI button, which the studio does not show.
  - The space is now kept only while that button is on screen.
  - The strip now has the toolbar's 6 px gutter: `?` right edge = `⋯` right edge (1721), and the first items start at 73 = 73.
- **Row-height control folds first.** At 1440 wide, Export and Import stay on the bar and the row height moves into `⋯`. This uses the new `useToolbarOverflowTier`.

### 5. The selection bar — Option A, BUILT (Owner: "I'll go with your recommendation")

- While rows are selected, the sheet toolbar reads "Selected N rows". The verbs and Clear take the search field's place, and the row height steps aside, as on the products grid (`GridSelectionActions`).
- The bottom bar is gone from the sheet. The footer no longer repeats the count.
- **Shared verbs.** `FamilySelectionVerbs` is the one definition of the verbs, so the Variants tab's `BulkActionBar` shows the same buttons.
- **Delete style.** A destructive verb is red only when it can run.
- **Row look.** A selected row gets a 12% primary wash on every cell and a 3px rail on the checkbox cell.
- **Focus.** A mouse tick leaves no focus box or halo. Keyboard focus keeps both.
- This is engine-wide, and the products grid now looks the same.
- The Variants and Matrix tabs still use their bottom bars (not asked).

The measurements that led here:

Measured on master · IT with 2 rows selected:
- A selected row takes `--nds-wash-primary`, which is very light. Tinted cells (inherited Brand, the content columns) paint over it, so only some cells look selected.
- Clicking a checkbox leaves the focus box on that one cell.
- "2 selected" is printed three times: toolbar, bar and footer.
- Disabled verbs look washed out, and the disabled `Delete child…` is pale pink.

Proposal given to the Owner: A (like the products page — actions move into the toolbar while rows are selected, a clear whole-row highlight, no focus box, calm disabled buttons) or B (keep the bottom bar, restyle only).

## Phase 2 — built on `feature/product-sheet-views-p2` (Owner: "I approved all your recommendations")

Decisions taken: team views with owner-only edits; product type only (families later); rule views through fully ticked groups plus savable Required and Has gaps presets.

### 3. Team views
- `SavedView` gains `shared` (Boolean) and `defaultProductTypes` (String[]). Additive migration `20260926a_saved_view_sharing`.
- The API lists a teammate's view only when it is shared, and only on a sheet's named views. It names the owner by `UserProfile.displayName` only, never an email.
- Only the owner can change or delete a view. A teammate's PATCH or DELETE gets 404.
- The views menu: my views, then a rule, then team views. A team view reads "Shared by <name>" and offers only Duplicate….
- My own view adds Share with team / Stop sharing. Deleting a shared view warns that the team loses it too.

### 4. Views by product type
- My view can be "default for Outerwear products". One default per owner, surface and type: taking a type moves it off my other views.
- **Landing order:** my default for this product type > the team's default for it (newest) > the working layout > my global default > All attributes.
- The product type is the family parent's (`family.productType`), on master and on every channel scope.
- **Measured and fixed:** master landed before the family arrived, so the type was still empty and a type default never won. The sheet now waits for the product type (an empty type is allowed).

### 5. Rule views
- A columns view may carry `rules`: `group`, `required` or `gaps`. They are resolved when the view is applied, so a new column there joins by itself. A rule only adds columns.
- Saving a named view stores every fully ticked group as a group rule, and the Required / Has gaps rule when that preset (or the view) offers it and all its columns stay ticked.
- New preset **Has gaps**: the columns with a readiness gap on a row in view.
- The menu note says what a view follows ("Follows required fields"), and the count includes what the rules add.
- The API checks `rules`: up to 200, each known and distinct.

### Found on the way
- **The views menu ran off screen.** It grew to 756 px under a 906 px window, and Delete… sat 33 px below the fold. `usePopoverPosition` now publishes the free room as `--nds-popover-room`; `.nds-menu` caps to it and scrolls.
