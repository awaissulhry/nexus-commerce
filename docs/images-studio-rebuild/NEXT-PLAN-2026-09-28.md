## W4 — Library duplicates Fix 2
Calibrated rule already in the code (`image-hash.service.ts`, IE.13): aHash ≤ 6 AND dHash-256 ≤ 16 means the same
picture. 17–26 means "same template, other text" (for example a size chart per language).

**W4a — Same picture at two addresses (PR).**
- Data (an additive migration): `ProductImage.sameAsImageId` (self link, SetNull when the kept photo is deleted) and
  `distinctFromIds String[]` ("Not the same" answers). Model ownership does not change.
- The library identity (`pictureKeys`) also joins `sameAsImageId`: one card, with the other rows as copies.
- The Media read gives each card its look-alikes (the rule above). A pair that is joined, a version or "Not the same"
  is not shown.
- Action "Same photo — keep this one" (a DS Modal: both pictures side by side, size and address, what changes):
  one transaction marks the copy and replaces it with the kept photo in EVERY plan layer — Shared, Channel and each
  Listing, alias layers included (it is removed where the set already holds the kept one). One event. Undo is refused
  when the set changed after it. Nothing is deleted.
- "Not the same" stores the pair. Library filter: "Look-alikes".

**W4b — Language versions (PR).**
- The photo window gets "Language" (none / several / a language) and "Version of …" through the existing
  `PATCH /media/library`.
- Gap found: when two photos that sit in one set become versions of one photo, the set repeats one photo, and the
  destination shows the chosen version twice. The same write keeps the main-language photo where both are placed, in
  every layer including aliases, and says so before saving. Undo works the same way.
- The 17–26 band suggests "Language versions?" for text photos (size charts).

**W4c — Fingerprints in production (the Owner's word).**
- Use `apps/api/src/scripts/backfill-image-facts.ts` (safe fetcher, dry run by default, fills only empty fields, also
  width and height). Do NOT use the older `scripts/ie2-backfill-image-hashes.mjs` that LIBRARY-DUPLICATES.md names.
- `--product <id>` (one family) — added with W4b; checked on the local stack (TEST-JACKET: 10 products, 20 photos to complete). Run it on nexus-worker (`railway ssh`): first the dry run (counts), then
  `--apply` for GALE-JACKET with the Owner's word. Measure: rows filled, look-alike pairs found.
- The Owner decides each "Same photo" on the page. Nothing merges automatically.
