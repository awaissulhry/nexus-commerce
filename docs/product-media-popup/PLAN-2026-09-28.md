## 0. In short (for the Owner)

- **Your "zoning" idea is right, and it already exists.** It is the **photo plan**. A family keeps its photos in SETS:
  one **Common** set, one set **per colour** (the "picture axis"), and — only when you ask — one set for a single SKU.
  Every size of a colour uses the colour's ONE set. Nothing is copied per SKU. Each channel is then built from the
  sets: eBay gets one picture set per colour, Shopify gets each photo once and points each variant at its colour's
  first photo, Amazon gets each child its colour's photos then Common, Etsy links one photo per colour (§1).
- **But most products do not use the photo plan yet.** They use the **older gallery**: every SKU keeps its own list.
  On REGAL-JACKET (40 SKUs) that is **184 photo rows for only 25 different pictures** (measured on the private copy).
  The photo plan for the same family is **Common 4 + 4 colour sets of 3** — 16 places, and every size follows its colour.
- **Today's cell opens two big dialogs** (§2): the gallery dialog is **660 × 789 px** (82 % of a 962 px screen), with a
  1,453 px scroll, a 33-item menu per photo, and up to 4 dialogs stacked; the photo-plan dialog is **920 × 789 px**, with
  a 5,771 px scroll and **377 Tab stops**. You said: *"too big … it doesn't even look like a pop-up editor."*
- **The new pop-up** (§3) is ONE small panel under the cell (480 px wide, at most 520 px tall; a full-width sheet on a
  phone), like the variation-theme and Shopify pop-ups: the cell's photos in order, drag or keys to reorder, "+ Add"
  opens the family's photos in the same panel, a click on a photo shows it bigger in the same panel. **Enter or a click
  outside saves. Esc cancels. No Save / Cancel buttons. No dialog on top of a dialog.**
- **One cell = one set.** A colour row edits its colour's set (and says "used by 10 SKUs"), the parent row edits Common.
  The same data, the same routes and the same "saves in Nexus, publish sends it" as today (§4).
- **Real time:** after Enter every cell that shows the set changes at once (all 10 sizes of the colour), the save runs
  in the background, and other open sheets refresh through the live event the photo plan already sends (§4.4).

| Fact | Evidence |

## 3. The new pop-up

### 3.1 Rules (the same as every new sheet pop-up — Lane B spec §4, copied as a pattern)

1. **Open:** the cell's usual gestures (double-click, Enter, F2, Delete, Backspace — unchanged, `M/productMediaColumn.tsx:88-89`).
   The pop-up opens UNDER the cell (desktop) or as a sheet across the screen below 640 px (`CellPanel`,
   `_studio/shopify/ShopifyDraftCell.tsx:44-133`, box kind `media` = 480 × max 520 px, `DS/grid/editors/editorBox.ts:94`).
   Focus goes to the first photo (the pop-up moves it there). Screen readers hear "Product media: <SKU>".
2. **It shows the cell's photos AT ONCE** from the row (no spinner for the strip); the family's library and the
   channel checks load behind it.
3. **Save:** Enter, or a click outside. **Cancel:** Esc. Open and close with no change writes nothing.
   Enter on a photo saves too (it does not open the photo; a click or the photo's ⋯ → "Open" shows it).
4. **Refused:** the pop-up stays open. One red line: `Not saved: <one sentence from §5>`. A click outside is held back
   while a save is refused.
5. **Read-only:** the photos show, nothing moves, and the reason is on screen.
6. **Footer:** one key line + one line on where it saves (§4.1).
7. **One cell = one set.** The pop-up never edits two sets at once. Common is edited on the parent row.
8. **No dialog on a dialog.** The library, the bigger photo and the upload all live INSIDE the one panel.

CHANGELOG in both.

## 4. Saving — today's contract, unchanged

### 4.1 Where each save goes (no new route, no data change)

| Row | Enter sends | It changes | It sends to a channel? | Footer line |
|---|---|---|---|---|
| Plan, Shared sheet | `POST /products/:id/media/ops` `{ address: SHARED, ops }` | the family's Shared plan | no — "Publish" does | "Saves in Nexus · every channel follows it unless a listing has its own" |
| Plan, channel sheet | the same route, `address: LISTING (channel, market, account, alias)` | that listing's own layer | no | "Saves in Nexus · Publish sends it to <channel>" |
| Older gallery, Shared sheet | `PUT /products/:id/product-media?scope=MASTER…` `{ expectedRevision, collection }` | the product's list for this language | no | "Saves in Nexus · channels without their own list follow it" |
| Older gallery, channel sheet | the same route with the listing | the listing's Nexus draft | no — "Synchronize" does (as today, `M/ProductMediaDialog.tsx:122`) | "Saves a Nexus draft · Synchronize sends it to <channel>" |
| Upload (both) | `POST /products/:id/images` (or `/videos`), one file at a time | the family library, at once | no | "Uploaded files stay in the library" |

### 4.2 The photo plan: one save on Enter (see **D1**)

Today every drag in the plan dialog saves at once (`IP/useMediaPlan.ts:83-126`). The pop-up rule is "Esc cancels", so
the pop-up keeps a draft and Enter sends ONE request with the ops the edit needs — kinds the route already takes:

| The edit | Ops sent on Enter |
|---|---|
| reorder, add, remove in the row's set | `{ op: 'replace', set, assetIds: <draft>, expect: <what this layer owned when the pop-up opened, or null> }` |
| "Only this SKU" ticked | `{ op: 'replace', set: 'sku:<id>', assetIds: <draft>, expect: null }` |
| "Only this SKU" unticked | `{ op: 'follow', set: 'sku:<id>', expect: <the SKU set> }` |
| "Follow Shared again" (channel sheet) | `{ op: 'follow', set, expect: <the listing's copy> }` |
| no change | nothing (no request) |

`expect` makes the server refuse the save when someone changed the set after the pop-up opened (`SH/media-plan.ts:137-139,
176-180`); the server never overwrites another person's change. Before sending, the pop-up runs the same rules locally
(`IP/model.ts:333-337` `applyLocal`), so a refused edit is refused without a request.

### 4.3 The older gallery: exactly today's save

`PUT /product-media` with the revision read when the pop-up opened; `collection: null` for "Use the all-languages
list" (`M/ProductMediaDialog.tsx:51-61`). Alt text, transcript and captions stay per language, per item.

### 4.4 Real time

1. **Enter → every cell of the set changes at once.** The pop-up closes, the row's thumbnails AND the thumbnails of
   every row that shows the same set (all 10 sizes of the colour; every variant when Common changed) take the new
   photos at once, with the cell's "saving" look (`M/productMediaColumn.tsx:81`, `M/useMediaCellActions.ts:34-50`).
   The sheet then re-reads the family and confirms. A refusal puts the old photos back and says why on the cell.
2. **Other screens.** A photo-plan save already sends `product.media.changed` to every open screen
   (`API/services/images/media-plan.service.ts:388` → `apps/web/src/lib/sync/use-listing-events.ts:134-136` →
   `M/productMediaColumn.tsx:53-57`). An older-gallery save sends nothing today — **see D2**.
3. **While the pop-up is open** and another screen changes the same set, one line appears: `Someone changed these
   photos. Enter will not overwrite them — Esc, then open the cell again.` (the save would be refused by `expect` or
   the revision anyway).
4. **The checks follow every drag** (pure functions, no request).

Speed (private copy, 3 reads each): `GET /product-media` 7–10 ms, 13 KB; `GET /media` (REGAL-JACKET) 26–48 ms, 86 KB.
The strip never waits for them (rule 3.1-2).
