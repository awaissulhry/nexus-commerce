## 2. What exists today (measured on 51742b8d9)

- **Grant** (`StockPoolGrant`): business A lends some of its warehouses to business B; B accepts. Settings › Shared
  products › "Stock you lend" / "Stock you borrow". No tie to assortments. **Stays as it is.**
- **Link** (`StockPoolLink`): one B product sells from A's lent warehouses. It needs an active `CatalogLink`, and a
  CatalogLink comes only from an assortment copy:
  - DB guard `nexus_stock_pool_link_guard` (`packages/database/workspaces/stock-pool.sql:330-334`);
  - `nexus_pool_effective_link` (`:550-563`, joins CatalogLink) — every new sale goes through it;
  - `nexus_pool_preview` (`:610-634`, finds A's product only through CatalogLink);
  - service `switchProducts` / `listPoolProducts` (`apps/api/src/services/stock-pool/pool-links.service.ts:113-305`).
- Everything after the link (holds, sales, put-back, restock, the listing quantity cascade) reads only
  `StockPoolLink.sourceProductId`. It does not need to change.
- **Matrix tab** (`apps/web/src/app/products/[id]/edit/_studio/matrix/`, API `apps/api/src/services/pim/matrix.service.ts`):
  - Stock column (read-only) already shows the pool's numbers for a pooled SKU (`loadSyncLedgers`), but **not
    which business** the stock comes from. The source is dropped at `matrix.service.ts:165-168` and `source.ts:126-135`.
  - Per coordinate (each market × account; each eBay alias; Amazon EU as one region): Qty (what is pushed; typing pins
    it), Mode (Follow / Pinned), Buffer, Sync, Fulfilment. FBA shows `—`.
  - There is no connect / disconnect on the Matrix.
  - Known wrong display: a SKU that left a pool and has no own warehouse rows pushes **0**, but the Matrix shows
    "⚠ Uncounted" and the tooltip says "nothing is pushed" (`matrix-cells.ts:223`, `sync-control-core.ts:237-240`).

## 3. What changes

### 3.1 Database (one additive migration, `20261001a_stock_pool_sku_links`)

- `StockPoolLink.catalogLinkId` becomes optional. A new link from this feature has none. The 21 links that exist
  today keep theirs and keep working exactly as now.
- New column `StockPoolLink.sku` (text, null for old links): the SKU both products had when the link was made (audit).
- Link guard, on a new link **without** a catalog link: A's product must be a product of the grant's lender, not
  deleted, with **exactly the same SKU** as B's product. All other checks stay (owner only, grant on, no chains, no
  lots or serial numbers, one active link per product).
- `nexus_pool_effective_link`: the CatalogLink join applies only to links that have one. For an SKU link it checks
  instead that both products still exist and still have the same SKU.
- `nexus_pool_preview`: finds A's product by the same SKU (old CatalogLink path kept for old links). Same return type.
- New read door `nexus_pool_sku_matches(grant_id, product_ids[])`: per B product, A's product with the same SKU, or
  why there is none (no such SKU, deleted, lot-tracked, would form a chain). Runs as B; reveals only SKUs B already has.
- SKU change or delete while connected: see decision D1.
- The whole new `stock-pool.sql` is appended to the migration; `policy-migrations.json` points at it;
  `prisma/baseline.sql` regenerated; `check:drift` and the policy parity check pass.

### 3.2 API

- `switchProducts` / `previewSwitch`: a SKU connects when A has the same SKU (through the new door). New links are
  SKU links. "Back to own stock" ends any link, old or new.
- Per-SKU switching: the Matrix sends only the selected SKUs (`withVariations: false`). Selecting the parent row means
  the whole family.
- `listPoolProducts` (the Settings page list) shows SKU matches too, so both places agree.
- Matrix read: each row carries its stock source — `own`, or `pool` with the lender's name and the lent warehouses.

### 3.3 Matrix tab (web)

- **Stock › "Stock source…"** in the Matrix toolbar's Stock menu. It is active when rows are ticked. Only an owner of
  the business can apply; others see why.
- **Pop-up** (design-system Modal, the pattern the Owner liked on 09-26: a default for every choice, one summary, one
  table, a counted main button, Done with Undo):
  - Choice: "Own stock" or "Stock of <business> — <warehouses>" (one entry per pool lent to this business).
  - Summary: "18 SKUs will use Xavia Racing's stock. 2 cannot: Xavia Racing has no product with that SKU."
  - Table: SKU · stock now (source, available) · stock after · what each listing gets now → after · status.
  - Main button: "Connect 18 SKUs" / "Disconnect 20 SKUs". After: a toast with Undo, and the Matrix re-reads.
- **Stock column:** a connected SKU shows its number with the lender's name ("12 · Xavia Racing"); the tooltip names
  the warehouses. Own-stock rows look as today.
- Fix the "⚠ Uncounted" / "nothing is pushed" display: show 0 and say 0 is sent.

### 3.4 Any profile, any channel (Owner, 2026-10-01: "very dynamic")

- Nothing names a business or a channel. The pop-up lists every pool lent to this business, from any profile, now or
  later. A profile may lend to several profiles; each SKU follows its own stock or ONE pool.
- The Matrix already builds its columns from each market × account, so a new channel or account appears by itself.
  A new channel gets the pool number through the same quantity cascade as soon as its own quantity sync exists.
- Proof: a test with three profiles (A lends to B and C at the same time) and a new account added after connecting.

### 3.5 Real time when an item sells (Owner, 2026-10-01)

- Today (measured in code): a sale written by the worker reaches the other profile in about 1 second
  (`afterStockMovementCommit` → `kickStockPoolWork`). A sale written by the API process (webhooks, manual order
  actions) does not kick (`afterPoolChange` skips the `api` role, `pool-tasks.ts:287-290`); it waits for the poller:
  up to **10 seconds** when quiet (`pool-tasks.ts:299-313`).
- Change: the database triggers that queue pool work also send a wake-up signal (`pg_notify`). The worker listens
  and runs at once, whoever wrote the sale. Same pattern as `services/assortment/sync-worker.ts` (direct database URL,
  not the pooler). The poller stays as a backstop.
- Target: under 2 seconds from the sale to the other profile's listing update being queued, in both directions
  (lender sells → borrower's listings; borrower sells → lender's and borrower's other listings). Measured locally.
- Not in Nexus's hands: how fast each channel shows the new number (eBay and Shopify: seconds; Amazon: can take
  minutes).

## 5. Safety rules (unchanged)

Only an owner of the borrowing business connects or disconnects. Only warehouses the lender lent are used; FBA never.
A product either lends or borrows, never both. Old links are not touched. No stock moves when a link starts or ends;
listings are recalculated in the background (`recascade`).

## 6. Decision for the Owner

**D1 — A connected SKU is renamed, or its product is deleted, in either business.** — **DECIDED 2026-10-01: A.**
- **A (chosen): refuse the change** with "This SKU shares stock with <business>. Disconnect it first." Nothing
  changes stock without the Owner's action.
- B: disconnect it automatically and tell the Owner. The SKU then sells from its own stock (maybe 0).
