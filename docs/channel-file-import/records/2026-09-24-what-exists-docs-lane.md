## A. §0 What exists (20 lines, for PLAN.md)

1. THREE import engines, not two. (a) catalog-transfer `services/pim/catalog-*` (Sept): the product-sheet drawer (`routes/catalog-transfer.routes.ts:45` inspect, `:56` preview) and `/products/catalog-transfer` (`:125` preview) both use it; drawer mounted in web `sheet/master/useMasterSheetAdapter.tsx:717` and `sheet/channel/useChannelSheetAdapter.tsx:55`. (b) FX flat-file wizard (July) on `/products/amazon-flat-file` → `routes/amazon-flat-file.routes.ts:1011` `/parse`, saves via `flat-file.service.ts:3218` `syncRowsToPlatform`; eBay twin web `EbayImportWizard.tsx:359` → `/api/ebay/flat-file/parse`. (c) FF2 `services/flat-file/import/*` (`routes/flat-file-import.routes.ts:64`) reads only its own Nexus workbook with ExcelJS (`import/parse.ts:1-13`); no web caller ("Dormant", `docs/superpowers/plans/2026-07-16-xlsm-amazon-template-hybrid.md:45`).
2. The legacy import-wizard no longer writes on its own: it stages Products-entity `SET` rows into the catalog-transfer job (`services/import-wizard.service.ts:1,21-30`); product target only, never reads Amazon/eBay templates.
3. Catalog-transfer contract: long rows `entity, sku, channel, accountId, marketplace, aliasKey, locale, field, action, format, value, version`; `SET/CLEAR/INHERIT`; empty action+value = unchanged (`docs/2026-09-05-catalog-transfer.md:19,29`; `packages/shared/catalog-transfer.ts`).
4. Previews persist in `BulkOperation` for 24 h; apply rechecks schema + snapshot per record transaction; never publishes; limits 10 MB / 50,000 outcomes (`docs/2026-09-05-catalog-transfer.md:37-39`; `services/pim/catalog-amazon-workbook.ts:96,102`).
5. Native Amazon reader `detectAmazonTemplate` (jszip + XML, `services/amazon/template-workbook.ts:444`) knows two grammars: `v2` (keys with `#N.` / `::`) and `legacy` (row holding `item_sku`) (`:329-339`). Strict mode refuses two product sheets, duplicate key paths, formula/error cells (`:474-488`). Record action is read from `::record_action` only (`:297`, `:524`).
6. The catalog-transfer Amazon adapter runs ONLY on `/products/catalog-transfer`, file type "Amazon template" (web `products/catalog-transfer/page.tsx:82`, accepts `.xlsx,.xlsm` `:89`) → `catalog-transfer.routes.ts:135` → `catalog-amazon-workbook.ts:101`. The product-sheet drawer has NO Amazon branch (worker order: editing → wide → eBay → transfer, `services/pim/workbook-parse.worker.ts:63-83`) and accepts `.xlsx,.csv,.zip` only (web `_studio/import/ProductTransferDrawer.tsx:203`; worker `:51`).
7. ## B. Open gaps the docs and code themselves name

- **Old flat file** (`legacy` grammar): refused by catalog-transfer (`catalog-amazon-workbook.ts:21`). FX reads it, but `update_delete` is never classified (`template-workbook.ts:524` reads `::record_action` only) → an old-file Delete row reads as replace (inferred from code).
- **Two-language file**: any key qualified with another marketplace/language is an issue (`catalog-amazon-workbook.ts:46-49`). R-18: one-language publish paths refuse on a multi-language market (`docs/product-cheat/PLAN.md:4871`).
- **Full replace vs partial update**: treated the same (`catalog-amazon-workbook.ts:43`). Amazon's "create or replace" clears attributes the row omits; Nexus keeps them → after a replace upload Nexus ≠ channel (inferred).
- **Delete rows**: refused by catalog-transfer (`:33`); FX excludes them unless typed-DELETE (`docs/xlsm-hybrid-runbook.md:26`).
- **Parent/child + variation theme** on existing products: not imported (`:50`); only set for new products (`:123-130`). FX's axis extraction is a separate implementation (`2026-07-16-…-hybrid.md:99`).
- **EAN/GTIN/exemption**: not imported — only a declared ASIN survives (`:51-56`). The July files had no identity columns (`2026-07-16-…-hybrid.md:32`); the corpus may differ.
- **Price and quantity**: excluded by both adapters (`catalog-amazon-workbook.ts:45,74`; `catalog-ebay-workbook.ts:28,109`; GALE `README.md:43`). No import path reaches the price door.
- **Images**: Amazon `image_locator_*` handling is not described anywhere read; GALE kept the existing gallery during partial updates (`2026-09-14-gale-import/README.md:13`); media has its own workspace (`docs/product-sheet/PLAN.md` MD-3/MD-4).
- **Entry points split**: Amazon templates only on the catalog page; eBay workbooks only in the drawer (product-scoped `resolveEbayWorkbook(table, productId)`, one product group per upload); `.xlsm` refused by the drawer.
- **Catalog page parse is uncontained** (`catalog-transfer.routes.ts:125-137`) — the 09-16 rule is "every new parser must obey" the worker (session prompt §4).
- **eBay create path absent**: existing listings only (`catalog-ebay-workbook.ts:95-97`); shells must be migrated first (`2026-09-15-ebay-workbook-import.md:43-48`; `docs/product-sheet/PLAN.md:1486`); markets limited to IT/DE/FR/ES/UK (`:34`); custom specifics outside the schema are issues (`2026-09-15…:36-39`); the root `XAVIA-eBay-IT-*` shape is not described anywhere.
- **Schema dependency**: an uncached category schema blocks every row of that product type (`catalog-amazon-workbook.ts:35`; `catalog-ebay-workbook.ts:103`).
- **"File vs Nexus vs channel"** comparison: not in any preview; no doc names it.
- **Validator/writer convergence** is follow-up work (`2026-09-05-catalog-transfer.md:41`); formula-controlled cells are refused on import (`2026-09-08-…-implementation.md:17`).
- **Two Amazon template importers** (FX and catalog-transfer) with different rules on the same files — the session prompt asks to pick one on purpose (§4 traps).

## C. Rulings already made that bind this work

- Owner gate 2026-07-16: "qty import default OFF, price ON, deletes excluded-by-default **with explicit owner override**, vault auto-capture ON" (`2026-07-16-…-hybrid.md:3`, options `:173-176`).
- FBA quantity is never written on import and never exported; export `::record_action` blank; Desktop originals never modified (`docs/xlsm-hybrid-runbook.md:25-29`).
- EU merchant quantity is ONE number for all EU markets; never touch FBA quantity (`SESSION-PROMPT-2026-09-24.md:79-80`).
- D15.1 "One file both ways. An export re-imported unmodified must give ZERO changes" (`docs/product-sheet/PLAN.md:682`); D15.5 "Blank cells: ignore (default) or clear. An omitted column is always ignored" (`:686`).
- TR-5 blank = unchanged; removed rows ≠ delete (`docs/product-sheet/PLAN.md:1474`); TR-12 stock/price/publication stay with their owners (`:1481`); TR-13 refuse account-less channel imports (`:1482`); TR-16/TR-17 eBay identity + shells first (`:1485-1486`).
- Import never publishes (`2026-09-05-catalog-transfer.md:39`; `SESSION-PROMPT-2026-09-24.md:17`).
- One price door: `writeChannelPrices`, `expectedVersion` required (`docs/product-cheat/PLAN.md:109,193,233`; `services/pim/channel-price-write.service.ts:132`).
- R-17 (a) send every language a market carries; R-18 (b) one-language paths refuse on a multi-language market (`docs/product-cheat/PLAN.md:4863,4871`).
- Flat-file and import-wizard no-touch rules LIFTED 2026-09-24; name any import-wizard change in the plan first (`SESSION-PROMPT-2026-09-24.md:80-82`). This supersedes D15.14 "`ImportJob`/`ImportJobRow` are UNTOUCHABLE" (`docs/product-sheet/PLAN.md:704`).
- Code rule, not an Owner quote: a native template never replaces existing shared content and never promotes across channels (`catalog-amazon-workbook.ts:18,114-115`).
