## 0. Executive summary (the ten facts that shape the proposal)

1. **Only eBay has a real "sign in → Allow" connect flow.** Amazon SP-API is a single env-var refresh token materialised as a synthetic `ChannelConnection{managedBy:'env'}` row at boot (`api/index.ts:331-409`); Amazon Ads has an OAuth route that **no UI calls** — the settings page is a paste-your-client-secret-and-refresh-token form (`[prod]` screenshot 10); Shopify / WooCommerce / Etsy have no connect flow at all and render "Coming soon" regardless of env (`api/routes/connections.routes.ts:81-96`, `web/app/settings/channels/ChannelsClient.tsx:424-426`).
2. **eBay tokens are plaintext at rest, twice.** `accessToken/refreshToken` and the deprecated `ebay*` twins are written verbatim (`api/services/ebay-auth.service.ts:282-287,343-356`); `[prod]` rows show `v^1.1#…` prefixes, 2,504-char access tokens, 96-char refresh tokens in both column sets. `api/lib/crypto.ts:5` has said "ChannelConnection tokens later" since CR.1. Only `AmazonAdsConnection.credentialsEncrypted` and carrier credentials are encrypted.
3. **Scopes are neither maximal nor recorded.** Prod's eBay authorize URL requests **six** scopes (`[prod]` popup URL: `api_scope, sell.account, sell.inventory, sell.fulfillment, sell.marketing, commerce.identity.readonly`); `sell.finances` is missing, and `ebay-financial-sync` fails **daily** on prod with `403 errorId 215001 domain ACCESS` (`[prod]` CronRun). `connectionMetadata.scopes` is read by the detail page (`api/routes/connections.routes.ts:171`) but **no writer exists** — `connectionMetadata` is NULL on all 14 prod rows, so scope drift cannot be detected and the detail page's own copy ("the OAuth callback writes them…") is false (`web/app/settings/channels/[type]/ChannelDetailClient.tsx:395`).
4. **"Connected" is not a fact about the channel.** The card is `!!connection.isActive` (`ChannelsClient.tsx:396`): for Amazon that is a boot-time env-presence boolean that even requires an unused `AWS_ROLE_ARN` (`api/index.ts:333-340`), with `lastSyncStatus:'SUCCESS'` hard-stamped (`:380`) — prod shows Amazon "Last sync: never" beside 50 processed ORDER_CHANGE notifications (`[prod]` screenshot 07); for eBay the green dot means "the last **token refresh** succeeded" (`ebay-auth.service.ts:288-290`), not that any data call did. No channel has a periodic heartbeat. The "Test" button on prod still returns the literal `"eBay seller (verified)"` (`[prod]` screenshot 03; `ebay-auth.service.ts:452-497`).
5. **Webhook ingress is per channel, mostly unverified, and never raw-body.** No raw-body parser is registered anywhere (`api/index.ts`, `apps/api/package.json`), so every HMAC receiver signs `JSON.stringify(request.body)`; eBay's receiver implements the wrong scheme (HMAC instead of ECDSA+public key) and skips verification when the token env is unset (`api/routes/ebay-notification.routes.ts:86-101,345-358`); WooCommerce's check tests an object for truthiness and never rejects (`woocommerce-webhooks.ts:297-306`); Etsy's six receivers have no verification at all (`etsy-webhooks.ts:317-625`); and two generic stock-mutating routes are PUBLIC with no auth (`webhooks.routes.ts:59,137`). On prod, `WebhookEvent` holds **only Amazon** rows (5,158, all processed, `signature` NULL); eBay/Shopify/Etsy have never received one.
6. **Idempotency is keyed on the entity, not the delivery.** Shopify/Woo receivers use `payload.id` (`shopify-webhooks.ts:953…1358`), so the second `orders/updated` for an order is skipped forever and every `inventory_levels/update` after the first is dropped (`externalId = "undefined"`); eBay's fallback key contains `Date.now()` (`ebay-notification.routes.ts:379`). No receiver reads `X-Shopify-Webhook-Id`.
7. **Refresh is unlocked and failure is mis-filed.** eBay refresh has no lock (30-min cron + 5-min-window reactive path + manual route can race, `ebay-auth.service.ts:259-292`); failure is written as `lastSyncStatus:'FAILED'` — the same field a data sync uses (`:305-311`) — with no notification and no write pause; refresh-token expiry (18 months) is untracked (`EbayTokenResponse` has no such field, `:8-13`). Amazon Ads' 365-day expiry has no alert (`lastError/lastErrorAt/lastVerifiedAt` have **zero writers**; `[prod]` `lastVerifiedAt` frozen at 2026-05-18).
8. **Two disconnect paths, one of which keeps live credentials.** Card "Disconnect" revokes at eBay and nulls the columns (`ebay-auth.service.ts:380-437`); AccountsPanel "Disconnect" only flips `isActive:false` and leaves the plaintext refresh token in the row (`api/routes/accounts.routes.ts:384-387`). Ads delete removes the DB row and never revokes at Amazon. No connect/refresh/revoke writes an audit row (§5.9).
9. **Auth is duplicated ~19 ways for Amazon** (14 `new SellingPartner(...)` constructions + 5 hand-rolled LWA exchanges; `api/lib/amazon-sp-client.ts:1-8` admits it), 7 independent Shopify HTTP clients pin `2024-01` in 9 places, and two credential naming conventions coexist for eBay (`EBAY_CLIENT_ID/SECRET` vs `EBAY_APP_ID/CERT_ID`). No typed env schema exists (`api/env.ts` is 19 lines of dotenv).
10. **The sync layer has one real engine and four ghosts.** `OutboundSyncService` + BullMQ is live (`api/services/outbound-sync.service.ts:522`); `UnifiedSyncOrchestrator`, `ProductSyncService`, the Phase-27 `channel-sync` lane (builds a payload, never sends, then writes `IN_SYNC` — `api/workers/channel-sync.worker.ts:202-216`), `inbound-sync.service.ts` (invalid unique key, throws) and `variation-sync-processor` (no producer; hard-coded USD) are dead, broken or harmful. Operator field mappings (`/settings/mappings`, 536 `ChannelSchema` rows on prod, **0 rules**) never reach a real push (`sync-mapping-merge.ts` consumers are all the no-send lane).

Security: **3 Critical, 5 High** findings (§5). Two are verified on prod: `GET /api/amazon-ads/auth/connect` is reachable unauthenticated (302 to Amazon consent, `[prod]` curl), and `POST /api/ebay/auth/initiate` is behind session auth (401). The public write probe (`/api/admin/amazon-auth-probe`) returned 404 on prod — it is registered in code (`api/index.ts:786`) but 404s there; **why is unverified** (route-prefix or deploy drift) — treat as latent until confirmed removed.
