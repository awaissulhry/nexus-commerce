Related route findings require checking reachability while implementing:

- `DELETE /products/:id/overrides/:fieldKey` selects the first product/channel/market/alias listing without account. Expected version is optional and checked before an unconditional ID update. Use the canonical override writer and its ownership/CAS contract rather than retaining this competing mutation path.
- Snapshot routes do not validate the URL product/listing pairing. Restore accepts only snapshot ID; its coordinate comparison excludes account/product and its write does not CAS an observed version. Do not expose this as a scoped restore until URL ownership, source/target identity and atomic conflict checks are complete. Retain existing stock/pricing ownership; do not broaden restoration behavior as part of this task.
- `resolveConnection({ listingId })` falls back through declared-primary resolution for an unattributed listing, despite its explanatory comment describing a stricter single-account rule. The new workspace boundary must preserve exact null or refuse unattributed destinations; it must not use this fallback to turn a listing deep link into primary-account work. Avoid an unrelated platform-wide resolver rewrite.
- Channel sheet locale is intentionally the channel market's configured language. Shared content locale is separate. Preserve that existing ownership instead of forwarding the Shared locale indiscriminately into channel writes.
