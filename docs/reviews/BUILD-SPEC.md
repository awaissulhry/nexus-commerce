## 0. Ground rules for every lane
- One lane = one worktree `git worktree add -b reviews/<lane> /private/tmp/reviews-<lane> <base>`; stage files by name; never touch
  the main checkout. Low CPU: `nice -n 15`, `vitest --maxWorkers=2`, one typecheck at a time, `uptime` + `ps -Ao pcpu,command | sort -rn | head` before a start.
- DS only (barrels `@/design-system/primitives|components|patterns|grid`), no new Tailwind, new files 0 raw controls, `--nds-*` tokens only,
  plain English (no `t()`; if a lane uses `t()`, keys go in `lib/i18n/messages/en.json` + `it.json`). Fetch = ``fetch(`${getBackendUrl()}/api/…`)``
  (the legacy relative `fetch('/api/reviews…')` 404s when deployed — never copy it). Links `@/lib/workspaces/Link`, router/pathname `@/lib/workspaces/navigation`.
- API: a new route file holds 0 Prisma calls (logic in `services/`), an existing route file may not gain one (`check-route-prisma-ratchet`).
  Every `/api/reviews*` and `/api/review-*` route is already gated: GET = `reviews.view`, write = `reviews.manage`
  (`lib/auth/permissions-manifest.ts:506-508`) — new paths MUST stay under those prefixes. Actor = `requestUserId(request)` (`lib/auth/request-permission.ts`), never a body field.
- Marketplace calls only through `services/gateway/*`; crons only `lib/cron/clustered.ts`; new server events in `packages/events/catalog.ts`
  (Phase 1 adds none: live updates use the existing SSE `GET /api/reviews/events` + BroadcastChannel invalidations); migrations additive + hand-written;
  never hand-edit `styles/tokens*.css` or `packages/database/*.js`.
- **Integrator-owned files** (the coordinating session edits them while folding lanes into a PR branch; lanes never touch them):
  `apps/web/next.config.js` (redirects), `R/_shell/reviews-nav.ts` and `R/_lib/reviewsLinks.ts` after PR A (href swaps), `api/lib/command-idempotency.ts` (COMMAND_SCOPES),
  `scripts/*-baseline.json` (lowering only), `.claude/DS-GAPS.md` and `design-system/CHANGELOG.md` after PR A (lanes hand the line to add).
- Fixture rows: every Review read in new code goes through `visibleReviewWhere()` (excludes `ingestSource = 'FIXTURE'`). No env-var name is ever shown in the UI.
- Header pattern = Settings shell: the sub-header's `DetailHeader dense` is the page title; pages render NO `PageHeader` (Settings measured
  "the same two lines twice", `settings/channels/ChannelsClient.tsx:142`). Page subtitle + actions go to the shell via `useReviewsHeader()`.
  Requests/Insights link tabs are dropped (sub-sidebar holds them). Boards still drawing those tabs or a PageHeader: follow this rule, not the board.

## 3. Pages
Every page: route `page.tsx` is a server component exporting `metadata` (`title: 'Reviews · Inbox'` …) + `<Suspense fallback={<…Skeleton/>}><XClient/></Suspense>`;
`loading.tsx` = DS `Skeleton` rows. States on every page: loading = shell meta "Loading…" + per-section Skeleton; a failed read = that section's
`Banner tone="danger"` with "Try again" (never zeros, never an empty grid); empty = `EmptyState`/`GridNoRowsOverlay` with the board's words;
no `reviews.manage` = actions held with "You need 'Manage reviews' to …" (`Button heldReason`, never disabled+title); page access = global `PageGuard` (`pages.reviews`).
Grids: `NexusGrid` + `grid/columns/presets.ts`, `domLayout="autoHeight"`, `GridPager`, `useGridState({ surface, baseUrl: getBackendUrl(), … })`,
Customise = `PreferencesModal`, every grid prop memoised. URL state: pure `*Query.ts` (parse once, `replaceState({}, '', …)`), tested.
Mutations: no optimistic rows — call → `emitInvalidation(type)` → `refreshServerSide({ purge: false })` → `useToast()` with the server's count.
