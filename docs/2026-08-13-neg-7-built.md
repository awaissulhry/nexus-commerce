## 1 · 🔴 The blast radius is two numbers, and the second one is the story

**Capability** — what one execution *could* touch. **Observed** — what it actually does, read from
the rule's own execution rows. They disagree completely:

| rule | capability | observed |
|---|---|---|
| Account-wide negative sync | **74** campaign-level negatives per run (IT), cap 20/day → up to **1,480/day** | **0 of 388** attempts reached the write |
| Wasted keyword instant negate | 1 per run, cap 200/day | **0 of 690** |
| Auto match-type migration | 1 per run, cap 100/day | **0 of 51** |
| Auto harvest & negate | not determinable from the rule | last dry run: **14** |

**Three of the five enabled rules never reach their write**, and the widest-radius rule in the
section is one of them. `Account-wide negative sync` fails `"keyword + marketplace required"` on
every single execution: its action config carries neither, and the `KEYWORD_WASTED_SPEND` trigger
supplies neither. **It has never once run its own selection query.**

Showing only the capability overstates the risk. Showing only the observation understates it — that
rule is one context fix away from its full radius. Both are on the row, and the row says which is
which in a sentence.

## 4 · 🔴 Three corrections to §2, all measured

**(a) The blast radius was 86 in my first pass, and 86 is an execution that cannot occur.** I summed
IT+DE+FR+ES. The handler's own WHERE is `{ marketplace, status: 'ENABLED', externalCampaignId: { not: null } }`
— **one execution happens in one marketplace**. The headline is now the largest single marketplace
(74) with the breakdown beside it and the sentence *"one execution never spans two marketplaces, so
these counts are not additive"*. Asserted both ways: it must equal 74 and must not equal the sum.

**(b) The rule denominator is 51, not 62.** The table holds 62 rules across three domains —
advertising 51, replenishment 8, reviews 3. "7 of 62" would have disagreed with every other surface.
§2's 51 is correct; my first counter was not.

**(c) `createNegative` has 7 call sites, not 6.** §2 says 6. Counted again as §2 asks: routes ·
`negatives-ngrams` (NEG.6's) · two in `automation-action-handlers` · two in `ads-harvest` ·
`ads-keyword-funnel`. All 7 pass `marketplace`, so the safety claim is unaffected — only the count.

## 5 · The cap counter is still broken, measured rather than assumed

`automation-rule.service.ts:573` counts with `NOT: { errorMessage: 'DAILY_CAP_EXCEEDED' }`. In SQL
that is `NOT (errorMessage = 'X')`, which is NULL — and therefore false — for every row where
`errorMessage IS NULL`. A successful execution carries a null `errorMessage`.

**Measured: 229,419 executions in 60 days carry no `errorMessage`, and the NOT-clause matches 0 of
them.** The counter that is supposed to stop a rule at its cap cannot see a single success.

Not fixed here — `automation-rule.service.ts` is shared and another session owns it. This page
counts from `AutomationRuleExecution` directly and says so on screen.

## 6 · `add_negative_phrase` — reported, not implemented

On the tab, categorised, ceilinged, and **absent from `ACTION_HANDLERS`**. A rule using it fails
every execution with "Unknown action type". No rule uses it today. Asserted by parsing the 29
registered handler assignments rather than grepping for the string, which also appears in comments.

## 7 · 🔴 A probe that manufactured its own failures

My first condition-2 check reported **three** call sites as missing `marketplace`. All three were
false: two pass it as ES6 **shorthand** (`{ scope, marketplace }`) and the regex demanded a colon,
and the third was a `vi.fn()` mock definition matched by a careless grep.

A verification script that invents failures is worse than none — it would have sent someone to
"fix" working code. Every structural claim in `_neg7-rules.mts` is now asserted against **parsed
structure or an explicit allow-list**, and test files are excluded by name rather than by luck. The
action list is checked by parsing `_shared/tabs.tsx` and asserting it is identical to the API's, so
a drift fails a test instead of quietly disagreeing with the tab badge.
