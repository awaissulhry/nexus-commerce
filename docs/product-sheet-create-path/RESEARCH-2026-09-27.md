# Product sheet as a listing tool in a new market — research (2026-09-27)

Branch `study/sheet-create-path` from `origin/main` 2fd0e2f68. Code reading only: no database, no API call, no browser.
Line numbers are at 2fd0e2f68, under `apps/api/src/` unless a path says otherwise. "No listing" means: the product
has no `ChannelListing` row for the coordinate channel + market + account (`channelConnectionId`) + alias (`aliasKey`).
Anything marked UNVERIFIED was not proven from the code.

## Summary

- **The sheet offers every cell on an unlisted market, and whether a save works depends on where the value is
  stored.** On Amazon · SE with no listing:
  - attributes kept in the listing's override bag (color, material…), listing columns and the sheet's media cell
    **quietly create a DRAFT listing**;
  - these are **refused**: platform fields (brand, condition, product type, eBay item specifics), price, fulfilment,
    all content (title, description, bullets — even "Edit the shared English"), the variation theme, the projection
    mapping, and the Amazon and eBay galleries.

  The order of your edits decides what saves: type Color first, reload, and the rest start working (§1).
- **Bug:** a refused platform field (Amazon brand, eBay item specifics…) is **painted as saved**. The server reports
  the error under the JSON path (`brand`) instead of the cell's field (`attr_brand`), so the web never matches it
  (§1 #3).
- **Publish deadlocks:**
  - Publish refuses a family with no theme ("Set the Amazon variation theme in Information before publishing"), and
    the sheet (Information) refuses the theme without a listing.
  - The same happens with the fulfilment method.
  - The SE price cannot be set before a listing exists, so Publish falls back to the master price and sends it with
    the market's currency (§4).
- **No shared creator.** 29 code paths create `ChannelListing` rows:
  - they use three different ways to pick the account, and about 17 write no account at all;
  - about half leave `isPublished` at its schema default of TRUE;
  - only the Variants tick sets `syncPaused` (§2).
- **Drafts are not inert today.** A draft born from a sheet edit has `syncPaused: false`, and that exposes it to:
  - the stock cascade, which queues a quantity for it;
  - the Amazon dispatcher, which PATCHes it by SKU with no draft check;
  - the EU shared-quantity guard, which cannot see it;
  - master price and content changes, which push to it;
  - a product status change, which flips it from DRAFT to ACTIVE.

  `syncPaused: true` + `isPublished: false` makes a draft nearly inert (§3).
- **Publish does not promote Amazon or Shopify rows.** After Amazon accepts a feed, the local row stays DRAFT /
  unpublished / no external id; only eBay Trading promotes it. So a paused draft would stay paused after it is
  published (§3.3).
- **Recommendation: one rule, one function** (`ensureDraftListings`).
  - The first channel-scope save on a coordinate with no listing creates an inert draft for exactly that coordinate
    (plus the family's parent and variants), in the same transaction.
  - Version 0 means "I saw no listing".
  - The account is always explicit, never null.
  - The variation theme writes to the new parent draft.
  - Publish promotes the draft and lifts its pause.
- **Possible live risk now:** drafts already created by typing on unlisted markets may be getting stock pushes. This
  needs a read-only count in production, which needs the Owner's word (§3.4).

**What makes this painful**
- One Amazon · SE row: Color saves (draft created), Brand is refused but looks saved, Title refused, Price refused with
  the wrong reason, Fulfilment fails the whole batch, Variation theme will not open.
- Creators differ: #9 sets `syncPaused: true`; #1, #2, #11 do not (§3 shows why that matters).
- #1/#2/#11 create only the edited product's row. A child edit makes a child draft with no parent draft, so the
  theme cell (a parent-row fact) still says "no listing".
- The bulk route picks the primary account when the scope names none (`bulk-edit.service.ts:419`), and
  `primaryConnectionIds` returns `null` with no active account (`services/connection-resolver.service.ts:311-318`), so
  a draft can be born with no account. Later tools refuse such rows (`services/pim/workspace-destination.ts:51`), and
  `readFamilyAccountId` counts any row's account (`services/pim/family-account.ts:16-17`), so a wrongly attributed
  draft steers future account choice.
- The client never learns the created row, so `row.listing` stays null until the post-save refresh.
- Header `useChannelSheetAdapter.tsx:796-813` reads "Not listed · 1 listing · 20 variations" when nothing exists (it
  counts alias groups), and "1 listing · 20 variations" for a draft — draft and live look the same.

### 3.2 Dangers (a marketplace write because a draft exists)

1. **Stock movement → Amazon PATCH for SE by SKU.** No layer checks draft, `isPublished` or the external id. SE is an
   EU shared-quantity market, and the guard only reads `isPublished: true` siblings. If the live EU rows are pinned
   (e.g. held at 0), the draft's SE push can overwrite the one EU number — the incident class the guard exists for.
   UNVERIFIED: what Amazon does with a quantity PATCH for a marketplace where the SKU has no offer.
2. **Master price change → price PATCH** for a draft in a euro market (the queue step ignores the pause).
3. **Drift self-heal** re-runs the stock cascade for an unpaused draft.
4. **eBay** quantity is SKU-level (inventory item), so a draft on another eBay site still moves the shared number.
5. **Product status change** rewrites DRAFT → ACTIVE (`master-status.service.ts:165-176`), whatever the pause says;
   a Shopify draft then enters the read-back that heals by default.

### 3.3 Publish does not promote the row (Amazon, Shopify)

After an Amazon feed is ACCEPTED (`studio-publication.service.ts:175-187`) or Shopify VERIFIED (`:286`), nothing
updates the local rows: they stay `DRAFT` / `isPublished false` / no external id. Only eBay Trading promotes them
(`:52-58`). Consequences:

- Today those live Amazon listings stay in sync only because nothing in the push path looks at the draft state.
- A draft born `syncPaused: true` (the Variants tick) stays paused after Publish, and no publisher clears the pause.
  So its stock would not sync until someone resumes it.

### 3.4 What makes a draft inert, and what is still open

- `syncPaused: true` blocks the stock cascade, every dispatcher (push lock), drift detection, both read-backs and the
  EU guard's intent (`sync-control-core.ts:231`, `push-lock.ts:20`).
- `isPublished: false` keeps it out of the EU guard's sibling set, the Amazon read-back, automation, auto-publish and
  the grid's "SYNCED".
- `listingStatus: 'DRAFT'` + no external id keeps it out of delist, content drift and the Shopify read-back.
- `quantity: null`, `price: null` avoid drift alerts.
- `offerActive` is **not** a guard (honoured only with `NEXUS_RESPECT_OFFER_ACTIVE=1`, `outbound-sync.service.ts:853`).
- Still open with every field set: master status flips DRAFT → ACTIVE; master price and content queue rows (skipped
  at dispatch, but they leave `lastSyncStatus 'PENDING'` and currency alerts); Publish does not lift the pause (§3.3).
- **Live risk now (UNVERIFIED size):** rows created by #1, #2 and #11 carry `syncPaused: false`. Worth a read-only
  production count, on the Owner's word: rows with `listingStatus 'DRAFT'`, `isPublished false`, no external id and
  `syncPaused false`, and any `OutboundSyncQueue` rows for them.

## 4. Publish already expects drafts — and deadlocks without them

- Publish creates missing rows itself (`ensureDrafts`, `studio-publication.service.ts:254-258`, called at `:280` and
  `:290`): "These drafts never establish channel presence … Only provider results can establish publication."
- Amazon Publish resolves the variation theme through the same resolver as the cell, with or without a listing
  (`services/pim/studio-publication-amazon.ts:64-82`, `services/pim/stored-variation-projection.ts:42-60`). When no
  rule or derivation gives a theme: "Set the Amazon variation theme in Information before publishing." (`:81`).
  Information refuses the theme without a listing (§1 #7). **Deadlock.**
- A new child with no fulfilment method: "choose a fulfillment method before publishing" (`:112`). The sheet refuses
  the method without a listing (§1 #5). **Deadlock** unless the product-level flag is set.
- Price: with no listing, Publish sends `product.basePrice` (`studio-publication-amazon.ts:94-95`,
  `services/amazon/cockpit-publish-row.ts:82`) with the **market's** currency (`studio-publication-amazon.ts:101`).
  On SE (SEK) the sheet cannot set a local price first (§1 #4). UNVERIFIED whether a readiness rule catches it.

## 5. Recommendation

### The rule

> **The first channel-scope save on a coordinate where the product has no listing starts a draft listing for
> exactly that coordinate (channel + market + account + alias) — and, for a variation family, the parent's and the
> variants' drafts — inside the same database transaction, through ONE shared function. A draft is inert: nothing is
> sent to the channel, no stock/price/content/status cascade touches it, and it never reads as "listed". Only Publish
> sends, and a successful Publish turns the draft into a live listing.**

Why: three writers already create drafts on a save (#1, #2, #11). Publish creates them anyway (§4). The Variants tick
creates them (#9). The eBay Media page already tells the operator to create the listing by typing in Information
(#13). The rule turns the existing half-behaviour into the only behaviour, and makes it safe. Refusing everywhere
would keep the sheet useless for a new market.

### How it works

- **One function**: `ensureDraftListings(tx, { coordinate, productIds, family: true })` in a new
  `services/pim/draft-listing.service.ts`.
  - It addresses rows with `whereCoordinate` (`lib/listing-coordinate.ts:35`).
  - It inserts only what is missing (`ON CONFLICT DO NOTHING` / `skipDuplicates`) and returns
    `{ id, productId, version, created }`.
  - It is the only place a draft's fields are decided: `listingStatus 'DRAFT'`, `isPublished false`,
    `syncPaused true`, no external id, `quantity`/`price` null, `channelMarket`, `region`, `aliasId`, the account.
- **Family**: create the parent row and one row per live variant together. A variant with no row counts as
  *excluded* (`family-projection.service.ts:1947`, "absence IS exclusion"), so a parent-only draft would show "0 of
  20 variants" and a collision count over nothing. The operator can untick variants afterwards (#9).
- **Account**:
  - use the scope's account (the sheet already sends `marketplaceContexts[].accountId`), else the channel's primary
    active account;
  - **never null** — with no active account, refuse: "Connect an Amazon account before listing on SE.";
  - the market must be an active `Marketplace` row (`workspace-destination.ts:30-31`).
- **Alias**: only the primary listing (`aliasKey ''`) is created on demand. A non-primary alias must already exist
  (`validateAliasWriteTargets`; `POST /products/:id/aliases` makes alias rows).
- **Versions (CAS) for a row that did not exist**: **version 0 means "I saw no listing"** — already the projection's
  convention (`:1561`, `:1956`).
  - The web sends `expectedVersion: 0` when `row.listing` is null (today it sends nothing, `useChannelSheet.ts:296`).

### Where there is a real choice

1. **When the draft is born**
   - **A (recommended): on the first save** of any channel-scope value. No extra click, and it matches what #1, #2
     and #11 already do.
   - B: an explicit **"Start a draft on Amazon · SE"** button, with every cell refused until it is pressed. More
     deliberate, but it keeps the Owner's "why can't I type here" for one more click, and it adds a second verb
     beside Publish.
2. **How a draft is kept inert**
   - **A (recommended): the pause** — `syncPaused: true`, the Variants tick's recipe — plus three fixes:
     - Publish lifts the pause and promotes the row (above);
     - master status skips drafts;
     - master price and master content skip paused rows when queuing, as the stock cascade already does.

     It reuses a lock that already works at both the queue and the dispatch layer.
   - B: a **push-lock rule for never-published drafts** (`isPublished false` + no external id + `DRAFT` → refuse in
     `assertPushAllowed` and filter at every enqueue). There is no pause to lift. But today Amazon and Shopify rows
     published through the studio stay in exactly that state after they go live (§3.3), so B would stop their stock
     sync unless Publish promotes them first *and* existing rows are backfilled. Larger blast radius; better as a
     later hardening once promotion exists.
