## Preserved foundations

The working tree already contained extensive uncommitted work. Starting copies of affected areas and the initial Git status were saved under `/tmp/nexus-redesign-before`. No reset, checkout, or reconstruction from Git history was used.

The canonical mapping candidate is `/channels/mapping`, including MappingClient, its existing rule/formula/category editors, `Marketplace.schemaMapping`, shared-category resolution, and `resolveBatch`. Category-specific field rules overlay marketplace defaults; explicit listing overrides remain authoritative for their supported fields. The product sheet, preview and publishing paths already use this resolver. Shared categories and marketplace category IDs remain distinct.

The product master/channel sheets retain the existing Nexus grid, SheetWriter, editors, paste, selection, expansion, views and column preferences. A byte comparison against the starting snapshot found no changes to design-system/grid source files.

Catalog transfer already supports shared fields and explicit destination fields in one long-format CSV or workbook, stable identities, SET/CLEAR/INHERIT, conservative blank/omitted semantics, version conflicts and durable BulkOperation checkpoints. The existing theme service provides versions, usage and targeted description publication; existing variation order persistence is reused.

## Implemented changes

- Product Studio now uses product-specific secondary navigation, an independent scope row, connected-account discovery and contextual mapping access. Title menus/horizontal tabs no longer duplicate the same destinations. Product links from Products Next and selected Listings entry points open Studio.
- The product toggle occupies only the title strip. The existing navigation overlay remains anchored to the measured global header and primary rail, without moving the grid.
- eBay Presentation composes existing theme assignments, preview and axis/value ordering. Its full shared theme editor can render inside the product workspace. Preview-product selection and families selected for a one-time publication are separate. Saving a theme does not publish it.
- Mapping field changes and auto-mapping can create durable, paginated impact reviews before activating a standing rule. Reviews use the same resolver before/after, report protected overrides and invalid outputs, scan 100 products per chunk, checkpoint results and recover interrupted work. Activation and mapping revision creation share a compare-and-swap transaction. Stale mapping tokens are refused.
- Optional account coordinates reach channel sheet reads and row commits. Unsupported ancillary tools and bulk verbs explicitly restrict alternate-account use. Scope changes clear stale listing/record coordinates, and sheet instances are isolated by product/channel/market/account.
- Bulk listing discovery for selected catalog products uses server-side product filtering and pagination. Queued publication is reported as queued, with the server job ID; it no longer emits completion immediately after enqueue.
- Older settings mapping entry points redirect to the current mapping workspace. Following the owner's clarified direction, secondary navigation appears only in product editing. Products Next uses its existing PageHeader; standalone mapping, impact-review and theme-library pages have no catalog sidebar. The unused catalog-sidebar adapter/configuration added in this session were removed.
- Listing presets reuse the existing WizardTemplate model and routes at `/channels/listing-presets`, with the old AI-settings entry rendered through the same library component. Server-side search, channel/market filters and 50-row pages are shared with the wizard picker. Product navigation links to the scoped library. Saving from the wizard captures reusable SKU and variation-theme settings, excluding product facts, prices, stock, media and selected variants. Application explicitly reviews one wizard and requires matching wizard version/timestamp and preset timestamp. Usage changes preserve the definition timestamp. Metadata edits/deletions use compare-and-swap writes.
- The wizard PATCH endpoint now guards its write against concurrent state/status changes and increments its version. Saving local Step 1 choices before a preset preview additionally checks the timestamp originally read by the client. Ordinary legacy callers can still omit that timestamp, so this is not comprehensive stale-intent protection for every wizard path.
- Shared DS additions: OrderedList with keyboard move controls and announcements; wrapping workspace scope layout; an opt-in generated dark theme boundary; explicit embedded Drawer mode; dark info-wash correction. Components, additions to styles, token changes, specimens and documentation are mirrored to Factory without replacing its unrelated differences.
