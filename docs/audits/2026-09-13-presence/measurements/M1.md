Local container: `nexus-development-postgres-20260908` (`pgvector/pgvector:pg17`, port 55439→5432), witnessed with `docker ps --format` at 2026-09-13T16:53Z.

Bare `current_setting('nexus.workspace_id',true)` is **NULL on both**. Local Product/ChannelListing/Offer/OutboundSyncQueue have ENABLE+FORCE RLS and `nexus_workspace_isolation`. The runtime role sees **0 Product / 0 ChannelListing** without a workspace, then **358 / 1012** with `nexus_legacy_workspace`, in the same read-only transaction. Production has **no RLS on those four tables**, no `Workspace` or `WorkspaceMembership`, no `nexus_workspace_runtime` role, and no Product.workspaceId. Its `neondb_owner` connection has BYPASSRLS; no workspace context is needed for these counts. Local and prod ChannelListingTranslation/ReadinessIndex also have RLS off.

This is a direct catalogue reading, and supersedes any inference that production currently has the workspace substrate. The production presence migration cannot install the standard policy/grants until that substrate exists; PR.5 does not own applying it.

What this decides: Every later count/write must name the measured host; Wave 2 production RLS/grants have an unmet infrastructure prerequisite.
