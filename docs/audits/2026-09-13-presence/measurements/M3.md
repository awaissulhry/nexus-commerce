## PR.3 follow-up — aliasId versus aliasKey and actual index semantics

Both DBs: aliasId is NULL on every measured row, while aliasKey is the empty string on every row. They are different columns. Both legacy `*_conn_key` indexes still exist and use NULLS NOT DISTINCT. **The `*_akey_key` indexes differ between databases:** local indexes include workspaceId and use ordinary UNIQUE (NULLs distinct); production indexes omit workspaceId and use NULLS NOT DISTINCT. The latter corrects the proposed inference that both DBs use ordinary UNIQUE. No index was changed.

Exact command: `node /private/tmp/nexus-pr5-presence/alias-index.mjs`, exit 0. READ ONLY + REPEATABLE READ, same runtime workspace initialization as M3; ROLLBACK on both. Positive controls are the non-empty Product/ChannelListing counts and the named primary index, which has ordinary UNIQUE semantics.
