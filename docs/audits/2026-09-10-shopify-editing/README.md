# Shopify attribute editing — implementation and verification

> Current architecture: [Common channel-sheet consolidation](COMMON-CHANNEL-SHEET.md). The separate Shopify Information grid and port 3175 harness were removed. Historical fixture receipts below are retained and are not evidence of a current live write.

The Shopify Information registry now provides working editors and draft/synchronization routes for **66 of 69 logical fields (67 of 70 physical chooser columns)** in the observed store: 27 editable native fields and all 39 discovered product/variant definitions. The remaining three logical columns have specific computed/API restrictions. The old “editing this channel field lands with the next build” message is removed from the sheet service; supported fields route to actual listing writers.

[Complete field coverage](FIELD-COVERAGE.md) records every native/definition column, owner, type, applicability, read adapter, editor, Nexus storage, Shopify operation and verification level. It also inventories the **118 advertised API types** and nested reusable-entry fields. The table is generated from the production registry and the recorded real-store schema, not a fixed demo-column list. Of those 118 types, 117 have shared value adapters; the remaining internal taxonomy-disclosure type lacks a readable resource in the pinned API and is not used by any observed chooser definition.

**The common-sheet implementation is in place. Current checks and their limits are in COMMON-CHANNEL-SHEET.md. Live Shopify mutation verification has not been performed.** No development product was designated for a write test. The real store was accessed read-only; no production account, product, listing, inventory or publication was modified during verification. This is not a WCAG AAA certification.

## What persists and when Shopify changes

| Path | Nexus save | Shopify update |
| --- | --- | --- |
| Linked cells in the common channel sheet | Versioned `ChannelListing.platformAttributes._nexusLinkedProducts`, containing durable `sheetValues`, pending `nativeEdits`/metafield `edits`, baselines and digests. Inventory remains a live quantity after its pending adjustment is verified. The common SheetWriter autosaves cells into this document, with per-cell concurrency tokens. | Review & synchronize creates a durable operation. Native fields use narrow product/variant mutations; metafields use compare-digest writes; media/publications/inventory/translations use their specific adapters. “Verified” requires readback, including asynchronous-job completion when an ID is known. |
| Unlinked channel sheet | Existing per-cell autosave gateway and listing version checks; native listing overrides and typed metafield paths. Exact account, alias, GLOBAL market and locale accompany each write. Shared Product data is not the write target. | Separately reviewed listing publication consumes the saved overrides. A new Shopify product is created through the existing publication workflow; exact product/variant IDs are then used for native, metafield and translation operations. Existing publication/review boundaries remain in place. |
| Reference selection | Exact Shopify GID or ordered GID list is staged in the product/variant draft. | The field changes on reviewed synchronization. |
| Shared reusable entry | Local entry intent remains visible until its own explicit save succeeds. | A separate usage review and **Save to Shopify** performs `metaobjectUpdate` or `metaobjectCreate` and verifies it. This is intentionally distinct from selecting a reference or saving a product draft. |
| Common product media (all channel rows) | `_productMediaLocales[locale]._productMedia`, with ordered asset identities, alt text, captions and transcripts. | Publication consumes primary/shared gallery membership and order; supported media files are created/attached through the existing publisher. Localized accessibility metadata is retained in Nexus and the storefront content manifest. Captions/transcripts and per-locale alt presentation require the existing theme/manifest integration; they are not claimed as native Shopify attachment translations. |

Native Shopify product/variant fields are global base values. Secondary-language fields are offered only for actual translatable resource keys; translations use the exact resource, key, locale and source digest. ProductVariant is not queried as a translatable resource. For uncreated draft resources, only documented potentially translatable types are offered and the created resource is checked before synchronization. URL and URL-list translations are included. Money uses the selected store currency. This GLOBAL editor does not introduce Shopify Markets money overrides or pretend that shared fields have independent language values.

## Implementation details that affect reliability

- `StudioTabHost → ChannelScopeTab → ChannelSheet` now serves every channel, including linked Shopify. Master remains `MasterSheetTab` on the shared grid foundation. Shopify contributes typed field/capability and writer adapters, without synthesizing another row hierarchy. The media cell uses the common ProductMediaDialog.
- Store definitions, native input fields/enums, scopes, locale lists, publication capabilities, reference constraints and owning app identity drive capabilities. Merchant names, product IDs and metafield labels do not route writes. Store schema caches and UI requests carry the destination locale; late responses cannot populate another keyed scope.
- Typed editors cover scalars, ordered lists, measurements, money, rating, links, references, JSON and rich text. Lossless JSON parsing preserves long numeric metadata. False, zero, empty lists, cleared values and inheritance remain distinct. Invalid/unknown structures stay visible for repair. JSON schema, declared choices, measurement bounds/units, reference kinds and store currency are validated on the server.
- Shopify fields bypass the shared formula writer. Text beginning with `=` is literal Shopify content. Structured clipboard values carry a typed store envelope; media/reference payloads cannot become ordinary text-cell values. Paste/fill uses the same validators and ownership checks as editing. Requests are bounded/batched and rows remain virtualized.
- Nexus compare-and-set/version failures retain local intent. Native workspace conflicts now offer a three-way review of saved and local changes: disjoint changes combine; true conflicts require an explicit cell choice. Recovery does not silently replace Shopify baselines. Scope/unload guards cover open editors, pending transfers and entry editors as well as the parent draft.
- Synchronization checkpoints distinguish submitted, running, uncertain and verified operations. Inventory uses the pinned API’s `changeFromQuantity` and required idempotency directive. Partial application is reconciled against intended values. Publication creation records the **final read-back status** and exact child IDs even for drafts, rather than deriving publication state from the pre-sync product.
- Category writes retain conflicting constrained metafields instead of deleting them. Handle changes check collisions and request redirects. Gallery removal detaches product references without deleting shared files; shared alt changes disclose their impact and variant associations are checked.
- Category-specific definitions now carry all exact subtype constraints. The observed Color definition has 10,896 allowed categories. Full subtype pages are cached for five minutes per profile/store/definition, invalidated by schema events or explicit refresh, and fingerprinted against fresh definition metadata. Before a write, a separate fresh, paginated `constraintSubtype` query verifies the current product category; cached membership never authorizes a Shopify mutation. New products initialize the reviewed category before constrained metafields. Existing products with a pending category change require that change to synchronize first.

## Legitimate restrictions and precise boundaries

| Field or context | Reason |
| --- | --- |
| Online store schedule | Derived from publication schedules. Edit the exact publication under Sales channels. |
| Publish date | Shopify’s recorded `Product.publishedAt` for the Online Store; null when unpublished. It is read separately from future schedules. Manage publication/scheduling through Sales channels. |
| Package | API 2026-07 accepts a package ID in a measurement input but exposes neither a package catalog nor an assigned package on `InventoryItemMeasurement`. Nexus cannot select or read back a package update. The UI directs this operation to Shopify. |
| Internal `product_taxonomy_disclosure_reference` type | Advertised by the type catalog, but `TaxonomyDisclosure` is absent in pinned schema introspection. Existing values are preserved. No observed product/variant definition uses it. This differs from supported `disclosure_reference`, which points to a disclosure metaobject. |
| Inventory on an unlinked draft | There is no Shopify inventory item or stocking-location identity yet. Initial stock belongs to the publication workflow; per-location editing becomes applicable once those resources exist. |
| Wrong owner row | Product attributes apply to the product, variant attributes to the exact sellable variant. Variant titles are computed from option values; the Name product attribute does not rename a variant. |
| Category-specific definition on another category | Shopify definition constraints explicitly enumerate applicable product categories. Nexus compares exact category IDs, including explicitly declared children; it does not infer membership using string prefixes. Change/synchronize the category before editing its constrained fields. Existing values and drafts remain preserved. |
| Secondary language for shared fields | Shopify provides no independent translated value for that field. Edit the primary-language/base field. Absent metafields must first be created/synchronized before their actual translation resource can be read. |
| Missing permissions or protected definitions | Specific Nexus and Shopify scopes/access checks apply. Another app’s protected definition is not writable merely because it is visible. The selected connection’s owning app can edit its own definitions when permitted. |
| Publication scheduling | Only publications reporting future-publishing support allow a schedule; dates are entered in explicit UTC. |
| Taxonomy value references | The pinned API does not provide a general searchable TaxonomyValue connection. The picker accepts an exact standard taxonomy GID and resolves it in the selected store; definition restrictions still apply. |

Unknown future types are explicitly described as **a missing Nexus adapter**, not relabelled as a Shopify restriction. Their data is preserved. The current store’s 39 ordinary definitions all have an editor and persistence/synchronization path.

## Verification

Before consolidation, the focused checks passed **278 API tests in 22 suites**, **48 shared tests in 4 suites**, and **33 Web tests in 7 suites**: **359 passing tests**. These cover narrow native mutations, schema/editor/writer routing, alias/store/locale isolation, permissions, clears, reference validation, media preservation, version conflicts, partial failures, interrupted jobs, inventory compare-and-set, publication changes, literal/typed transfers, category constraints and draft merge choices. Status cases verify new ACTIVE, DRAFT and ARCHIVED products after Information overrides; category creation is verified before constrained-field planning. Eight production bulk-route cases check structured metadata, money zero, false, empty lists, literal formula-like text, invalid empty text, explicit null and Italian storage. [API machine-readable report](api-tests.json).

One existing API browser-fixture test is conditional on `NEXUS_WORKSPACE_SCOPE_BROWSER=1` and was skipped. An additional existing Web live-channel suite skipped 13 cases because its local API was unavailable; those are not counted among the 33 passing Web tests. A test mock initially lacked the new constraint-invalidation export and was corrected. The bulk-route test's background event/cache services were isolated after a sandbox localhost Redis connection error; its rerun passed without background workers. No production error was hidden or assertion relaxed.

Shared build and Shared/API/Web type checks passed. Both token generation checks passed. Token resolution, CSS parsing, strict raw-control/radius/DS-shadow/hex ratchets, AG import boundary and grid-module checks passed. No guard was rebaselined. The **Factory fork guard reports unrelated drift in `components/index.ts`**: the Web/Factory difference is three blank lines, alongside previously recorded fork differences. This task did not edit shared design-system sources. That earlier run could not reach localhost:3000. The consolidation run reached the actual editor and passed the grid chrome guard at 3 densities × 2 themes × 2 viewports. The 3175 harness is now removed.

The [read-only Shopify evidence](live-capabilities-1.json) was collected through the real Admin client pinned to **2026-07**. It records the selected store schema, 39 definitions, native inputs/enums/scopes, store currency, locale capabilities, taxonomy/package introspection, production reader output for one product plus five variants, and the expanded reference resolver. The new `publishedAt` selection and reference fragments successfully ran against that pinned API. This verifies operation input availability and reads, not mutation outcomes.

The later [definition read](live-definition-capabilities-1.json) includes complete category constraints, and the [fresh applicability read](live-applicability-1.json) exercised the production filtered query successfully. A cold full-catalog-plus-product read initially reached the existing local Shopify request limiter after the 43 category-pagination follow-ups. Schema-only discovery succeeded; bounded caching and the narrow write-time query now avoid downloading that catalog on every save/sync. A full live product read after this last cache change was not repeated.

The pinned operation contracts were checked against official Shopify documentation: [ProductUpdateInput](https://shopify.dev/docs/api/admin-graphql/2026-07/input-objects/ProductUpdateInput), [ProductVariantsBulkInput](https://shopify.dev/docs/api/admin-graphql/2026-07/input-objects/ProductVariantsBulkInput), [metafieldsSet](https://shopify.dev/docs/api/admin-graphql/2026-07/mutations/metafieldsSet), [inventorySetQuantities](https://shopify.dev/docs/api/admin-graphql/2026-07/mutations/inventorySetQuantities), [PublicationInput](https://shopify.dev/docs/api/admin-graphql/2026-07/input-objects/PublicationInput), [fileUpdate](https://shopify.dev/docs/api/admin-graphql/2026-07/mutations/fileUpdate), and [translationsRegister](https://shopify.dev/docs/api/admin-graphql/2026-07/mutations/translationsRegister). Type/validation and applicability contracts use the official [type catalog](https://shopify.dev/docs/apps/build/metafields/list-of-data-types), [validation options](https://shopify.dev/docs/apps/build/metafields/list-of-validation-options), and [conditional-definition model](https://shopify.dev/docs/apps/build/metafields/conditional-metafield-definitions). The API version was not upgraded.

Browser checks and limitations are recorded in [BROWSER-VERIFICATION.md](BROWSER-VERIFICATION.md). Receipts distinguish mock Nexus saves, mock Shopify synchronization and real read-only checks. The obsolete `browser-before-restart.json` is historical: it preceded correction of the fixture’s channel-write target and is **not evidence for successful unlinked routing**.

## Nexus UI effects

Metafield dialogs use existing Nexus Modal, Field, Input, Select, Textarea, Listbox/AsyncListboxPanel, OrderedList, Banner and Disclosure. Scalar/measurement dialogs use the small size; rich text/reference and reusable-entry editing use compact layouts. Long entry-usage lists and exact structured transfer details are disclosed on demand; scalar entry fields do not repeat their labels as headings. Product media uses the smaller large dialog. No new shared control, shared CSS rule or grid theme override was introduced, so no Factory/catalog/DS-GAPS addition is required for this task.

The blue selection contour, border thickness/color, range background, row height, padding and density were not changed. Existing pencil/media controls and default grid loading overlays remain. The only changed Shopify feature CSS token replaces an undefined notice z-index with `--nds-z-actionbar`.

## Unverified behavior and remaining limits

- No real Shopify write/readback, storage upload or storefront/theme round trip was performed. Mutation adapters are tested with mocked Shopify/Prisma boundaries and real input-schema reads. A designated development destination is needed for live verification, especially inventory/publication permissions, category constraints, file membership, localized removal and retries across real network interruptions.
- Native product/variant updates, publication changes, metaobject updates and metafield deletion have no atomic compare-and-set facility used by these APIs. Preflight and post-write reads reduce stale-write risk but cannot eliminate a concurrent remote change between read and mutation. `metafieldsSet` and inventory adjustments retain API-supported compare-and-set protection.
- Native Information undo/redo covers up to 50 unsaved commands and ends at Save draft. In the existing unlinked autosave sheet, AG undo history ends when the acknowledged save refreshes row data. There is no compensating undo after Shopify synchronization.
- Rich-text editing changes text leaves and adds paragraphs while preserving existing headings, links, marks and lists. It is not a full visual formatting authoring toolbar. Malformed stored rich text remains repairable as JSON. Shopify remains authoritative for server-only/uniqueness/category rules and regex-engine differences.
- A complete OS clipboard round trip, actual browser zoom, screen-reader output, forced reduced-motion presentation and every contrast/focus case remain unverified. Responsive screenshots, measured contrast samples, keyboard actions and static motion rules are evidence of specific checks, not an accessibility certification.
