## 1 · 🔴 The measurement that changed the design

**`NgramRow.terms` is not what a phrase negation blocks.** The tokenizer strips stop words *before*
building 2-grams, so `giacca moto con protezioni` yields the gram `moto protezioni` even though
those two words are not adjacent in the query:

| | `NgramRow.terms` | queries actually containing the phrase |
|---|---|---|
| `moto protezioni` | **61** | **13** |
| `protezioni` (1-gram) | 195 | 195 |

A **4.7× overstatement**, on the exact number a confirm dialog quotes to justify an irreversible
write. Every row now carries `catches`, counted by contiguous token match — Amazon's own
negative-phrase semantics — and `terms` is not exposed to the UI at all. The 1-gram agreement is
asserted too, so the divergence is pinned as a 2-gram property rather than a general distrust.

The clearest case is on screen: **`uomo stagioni` costs €42.20 across 98 clicks and blocks zero
terms**, because no query contains that pair contiguously. It is correctly refused.

## 2 · §4 resolved as option (a), because the data demanded it

The n-gram service ignored marketplace and campaign entirely, so every number was account-wide while
every other panel answers to the scope bar. That is not merely untidy:

```
homologué   €72.47   100% FR      protezioni  €134.32  100% IT
```

An account-wide `homologué` under an "IT" heading attributes spend to a market that never spent it.
The filter is additive — absent `marketplace` is exactly today's behaviour, so
`GET /advertising/ngrams` is unchanged — and it costs ~290ms. Campaign scoping maps local →
**external** ids, because `AmazonAdsSearchTerm` stores Amazon's; passing local ones returns zero
rows forever and looks exactly like a quiet account.

Asserted in both directions: `homologué` is present account-wide and in FR but **absent in IT**;
`protezioni` is present in IT but **absent in FR**.

## 3 · The four rails, each measured firing and not firing

A rail that blocks everything and a rail that blocks nothing both fail the suite.

| rail | fires on | |
|---|---|---|
| winning-gram collision | `alpinestar` ⊂ `moto alpinestars` (ROAS 15.9) · `aa` ⊂ `aaa` (ROAS 13.1) | 48 clean |
| converting terms | `alpinestar` → *veste moto alpinestars* €87.50 · `aa` → two `…aaa` terms, €182.18 | |
| protected term | `xavia` — the **top winning gram** at ROAS 57.5 **and** protected | |
| the gram floor | ≥3 chars, ≥5 catching terms, not ASIN-shaped | 7 blocked, 43 actionable |

**🔴 A correction to my own reasoning.** I wrote that the converting-term check was structurally
empty — "wasteful" *is* orders = 0, so a token-matched converting term cannot exist. That is true at
token strictness and it is why the check runs on the **loose** set, which is the only reading that
can ever fire. It fires on two grams, and it is the only rail that carries the *money*, which is
what actually persuades. The suite now asserts the two, by name.

**The floor needs both conditions, and they catch different things.** `aa` reaches **30** terms, so
a term-count floor alone misses it — only the character floor does. `b0cy2s7zgy` and `b092qrxwzn`
are ASINs the tokenizer read as words. `uomo stagioni` is thirteen characters and fails on terms.

## 4 · A near-miss that is evidence, not a defect

`moto estive` is wasteful (€27.13) and `estive moto` is winning (ROAS 44.8) — the same two words in
opposite order, on opposite sides of the page. The collision rail does not flag it and should not:
a negative *phrase* matches a contiguous ordered run, so negating one cannot block the other. A
bag-of-words or substring matcher would have conflated them. The order-sensitivity is load-bearing.

(`estivo moto` — wasteful, masculine — and `estive moto` — winning, feminine — sit one letter apart
in the same view. Confirmed zero overlap between the two lists.)

## 5 · Three defects, all found by looking at production

**🔴 One opacity declaration put 78 text nodes below AA.** `.h10-ngw-list li.blocked { opacity: 0.82 }`
composited every colour inside a blocked row. Every value in the stylesheet was individually fine;
`getComputedStyle` reports the declared colour; only compositing the alpha against the real
background reveals it. Removing it fixed 74 — the amber reason text is 6.60:1 undimmed and the
violet chip 5.99:1. The remaining 4 were independent: the ROAS green `#1f8a4c` is **4.22:1** on the
striped row, now `#177a41` at 5.29. Final sweep: **646 nodes, 0 failures, lowest 4.62.**

**🔴 A false refusal sentence.** Every below-floor gram printed *"Below the floor of 3 characters and
5 terms"* regardless of which condition failed — including three multi-word grams. This is the
sentence an operator must trust to accept that the tool will not let them act; a false one is worse
than none. Each now names its actual failure.

**🔴 The headline reason was the least important one.** The row shows `blockedBy[0]`, and the array
was built in the order the checks were written. `aa` fails converting-terms (€182.18), collision and
the floor — and led with *"it is below the floor"*. Now ordered most-serious-first, and asserted.

**And one shipped-then-caught skew:** `sampleTerms` was added to the service *after* the API commit
and *before* the web commit, so prod's API lacked a field prod's web read on expand. Fixed on both
sides — the field ships, and the type is optional with every read guarded, because a commit is two
deploys and they are not atomic.

## 6 · The one write, and why it has not been run

The confirm states, before anything is clickable: 26 ad groups written to, **1 excluded** for not
being on the live-write allowlist, 195 terms blocked, 0 converting among them, €134.32 removed, and
the market split. Then that it **cannot be undone at Amazon**, and that it blocks every *future*
query containing the word, not only the measured ones.

The action is **live, not dark**. It has not been executed: the first live run negates a word in 26
ad groups irreversibly, and no subject has been named by the operator — NEG.3b's precedent. The
server re-runs every rail before writing, so the UI's disabled button is a courtesy and this is the
enforcement; verified by calling `negateGram` for a below-floor gram, an unmeasured gram and a
protected gram, each refused with **zero** outcomes.

## 7 · Verified on production

- Redirect: `/marketing/advertising/ngrams` → **308** → the page, landing on `#wasteful-words`. The
  old `NgramClient.tsx` and its `page.tsx` are deleted; `grep -r` found no importer outside their
  own directory, unlike NEG.5's `ProtectedTermsPanel`.
- `protezioni` €134.32 · 344 clicks · blocks 195 terms · 27 ad groups — matching the study exactly.
- Expanding a row lists the terms behind it, and `giacca moto con protezioni` is among them — the
  study's caution made concrete rather than asserted. Each term opens NEG.2's drawer; **the gram
  does not**, because a gram is not a term and `?focus=protezioni` would open an empty one.
- Both CSVs kept. Section edges **96 → 1698**, flush with the grid. No horizontal overflow. Zero
  console messages.

## 8 · Open

1. **The first live gram negation has never run.** 43 grams are actionable; `protezioni` alone is
   €134.32 across 27 ad groups. Operator's call.
2. **`estivo moto`, `moto estive`, `estivi`, `estive uomo` are all actionable and all adjacent to a
   winning gram in meaning if not in string.** The rails are string-level; nothing here understands
   that `estivo` and `estive` are the same word inflected. A plural/inflection-aware rail is not
   built and is not obviously safe to guess at.
3. **9 size tokens are labelled but still listed.** They sort below real waste and carry a caveat,
   but the catalogue gap they signal has no home on this page — that is a merchandising decision.
4. **The €3 floor and the 60-day window are defaults, not measurements.** Both are on screen and
   both are movable; neither has been justified against data.
